불변식

  • 본인만 읽고 쓸 수 있습니다. 다른 사람의 정보는 항상 publicProfiles로 봅니다(이메일 노출 방지).
  • groupIds는 Circle callable만 바꿉니다. 탈퇴·삭제 후 남은 오래된 ID는 함수가 다음 생성·참여 때 정리합니다.
  • Circle callable이 클라이언트보다 먼저 문서를 만들 수 있습니다(groupIds만 있는 문서). 이 경우 다음 로그인 동기화에서 클라이언트가 createdAt과 알림 설정을 채웁니다.
  • consent가 없거나 termsVersion이 현재 버전(src/content/legal.js의 TERMS_VERSION)과 다르면 클라이언트가 동의 화면을 보여 줍니다. 감사 글·댓글 생성 규칙은 consent가 있는지 확인합니다.
  • 클라이언트는 삭제할 수 없습니다. 계정 삭제는 deleteAccount callable이 하위 컬렉션(blocks, bookmarks)과 함께 지웁니다. → 계정 삭제

users/{uid}/blocks/{blockedUid} — 차단 목록 ​

createdAt(서버 시간)과, 모두의 감사방에서 차단했을 때만 alias(1~20자, 그 방에서 본 상대의 별명)를 가집니다. 문서 ID가 차단한 사용자의 uid입니다.

  • 본인만 읽고, 만들고(자기 자신은 차단 불가), 지웁니다(차단 해제). 다시 차단(setDoc)은 같은 형태의 수정으로 허용됩니다.
  • alias가 있으면 차단한 사용자 화면은 그 별명("햇살가득 · 모두의 감사방 별명")만 보여 주고 상대의 공개 프로필을 읽지 않습니다. → 모두의 감사방
  • 클라이언트는 이 목록으로 차단한 사람의 글·댓글을 화면에서 거르고, 알림 트리거(Admin SDK)는 받는 사람이 보낸 사람을 차단했으면 건너뜁니다. 새 차단은 onBlockCreated가 운영자 대기열에 낮은 우선순위 신고로 남깁니다. → 차단

users/{uid}/bookmarks/{gratitudeId} — 저장한 감사 ​

createdAt(서버 시간)만 가집니다. 문서 ID가 저장한 글의 ID(자동 ID 형식)입니다.

  • 본인만 읽고, 만들고, 지웁니다. 운영자도 읽을 수 없고, 컬렉션 그룹 조회도 막혀 있습니다. 다시 저장(setDoc)은 같은 형태의 수정으로 허용됩니다.
  • 글을 읽을 권한은 따로 확인하지 않습니다(목록은 본인만 보므로). 화면은 각 글을 본인 권한으로 읽어, 지워졌거나 나간 Circle의 글이면 "더 볼 수 없는 글이에요"와 [목록에서 빼기]를 보여 줍니다. 글이 지워져도 다른 사람의 저장 문서는 서버가 지우지 않습니다(남은 문서는 그 사람 화면에서 이렇게 보임).
  • 클라이언트가 세션에 한 번 구독합니다(최대 500개, src/lib/bookmarks.js). → 저장

notices/{id} — 공지 ​

title(1~60자), body(1~3000자, 줄바꿈 유지), banner(홈 배너로 보여 줄지), publishedAt·updatedAt(서버 시간). manageNotice callable만 쓰고 누구나 읽습니다. 올린 운영자는 adminAuditLogs에만 있습니다. → 공지

publicProfiles/{uid} — 공개 프로필 ​

필드설명
displayName1~100자
tag1~10자, 한 번 정해지면 변경 불가
publicName`${displayName} #${tag}` — 전역 유일
photoURL본인 Storage 업로드(profilePhotos/{uid}/…) 또는 본인 ID 토큰의 Google 아바타, 또는 null
  • 정확히 이 4개 필드만 가집니다. 로그인한 사용자는 문서 하나씩 get만 할 수 있고 목록 조회는 불가능합니다(사용자 목록 수집 방지).
  • 글·댓글의 작성자 필드(authorName, authorTag, authorPublicName, authorPhotoURL)는 이 문서와 같아야 생성됩니다.
  • displayName이 바뀌면 onPublicNameWritten이 내용 필터로 검사해, 걸리면 이름은 그대로 두고 운영자 대기열에 신고를 남깁니다. → 자동 숨김: 이름
  • 클라이언트는 삭제할 수 없습니다(deleteAccount가 지움). 차단 목록에 남은 삭제된 계정은 프로필이 없어 "알 수 없는 사용자"로 보입니다.

publicNames/{key} — 공개 이름 선점 ​

key는 publicName의 UTF-8 바이트를 SHA-256으로 해시한 소문자 16진수입니다. 클라이언트(src/lib/publicName.js), 함수(functions/src/utils/publicName.ts), 규칙(hashing.sha256)이 같은 계산을 합니다.

필드설명
uid이름을 가진 사용자
publicName원문 이름
  • 먼저 만든 사람이 임자입니다. 생성만 가능하고 덮어쓸 수 없습니다.
  • 자기 프로필이 같은 배치에서 그 이름을 갖게 될 때만 만들 수 있고, 이름을 바꿀 때 예전 선점은 같은 배치에서 지워야 합니다.
  • 프로필·선점·users는 항상 하나의 배치로 함께 씁니다(src/lib/firestore.js).
  • 선점 제도 이전에 만들어진 이름은 backfillPublicNames 스크립트로 선점 문서를 만들어 둡니다. → Cloud Functions

필드쓰는 주체설명
name서버 생성 / 관리자 수정1~30자
description서버 생성 / 관리자 수정최대 100자

불변식

  • memberIds에는 항상 adminId가 들어 있고, 관리자는 탈퇴·내보내기 대상이 아닙니다.
  • users/{uid}.groupIds와 memberIds는 같은 트랜잭션에서 함께 바뀝니다.
  • 존재하지 않는 Circle 문서에 대한 get은 오류가 아니라 빈 결과를 돌려줍니다. 클라이언트는 이것으로 "삭제된 Circle"과 "권한/네트워크 오류"를 구분합니다.
  • memberIds는 참여 순서입니다(생성자가 처음, 참여는 뒤에 붙음). 계정 삭제 때 관리자를 넘겨받을 "가장 오래 함께한 멤버"를 이 순서로 정합니다.
  • 관리자가 이름·설명을 바꾸면 onCircleNameWritten이 내용 필터로 검사해, 걸리면 운영자 대기열에 신고를 남깁니다(이름은 그대로). 생성 때는 createCircle이 거절합니다.
  • 운영자(users.isAdmin)는 신고된 Circle을 확인하려고 문서 하나를 get할 수 있습니다(목록 조회는 불가).
  • kind·maxMembers는 관리자도 바꿀 수 없습니다(규칙이 프로필 필드만 허용).

모두의 감사방 (별명 Circle) ​

운영자가 여는 Circle 하나입니다. 초대 코드 없이 원하는 사람이 별명을 정해 참여하고, 그 방의 글·댓글에는 별명만 보입니다. 처음에는 꺼져 있고 운영자가 켭니다. → Circle: 모두의 감사방, 결정 기록 #21

  • 단일 필드 인덱스 제외: props(map, 하위 필드 포함), platform, expireAt은 이 필드로 거르거나 정렬하는 쿼리가 없어 fieldOverrides로 색인하지 않습니다(쓰기 비용·저장 용량 감소). event, uid, createdAt은 쿼리(관리자 분석 화면, adminMetrics, 계정 삭제)가 쓰므로 그대로 둡니다. 이 셋 중 하나로 거르는 쿼리를 새로 만들면 fieldOverrides에서 빼야 합니다.

운영 지표가 세는 초대 이벤트: circle_invite_shared({where: "created" | "settings", method, groupId}), invite_opened({code}), invite_joined({groupId}).
