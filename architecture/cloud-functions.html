공통 규약 (callable) ​

  • 오류는 한국어 HttpsError. 메시지는 사용자에게 그대로 보여 줄 수 있게 씁니다. 클라이언트 래퍼(src/lib/callable.js)는 메시지에 한글이 있으면 그대로, 없으면 상황별 기본 문구로 바꿉니다.
  • 입력 검증. requestData()는 객체가 아니면 {}로 바꾸고, 문서 ID 입력은 requireDocId()로 Firestore ID 규칙(비어 있지 않음, / 없음, 128자 이하 등)을 검사합니다. 길이는 charLength()로 코드 포인트 단위(이모지 1자)로 셉니다.
  • 트랜잭션 우선. 멤버십을 바꾸는 함수는 모두 읽기 → 검증 → 쓰기를 한 트랜잭션에서 합니다.
  • 잠긴 계정 거부. 데이터를 만드는 callable(createCircle, joinCircle, joinOpenCircle, submitQuestion, createShortLink)은 requireActiveUser(uid)로 방금 삭제·정지된 계정을 "이용할 수 없는 계정이에요"(permission-denied)로 거부합니다. → 보안 규칙

Circle callable ​

공통 상수(circles/common.ts): 사용자당 Circle 20개, Circle당 멤버 50명, 초대 코드 유효 30일·사용 50회.

함수권한하는 일
createCircle로그인 사용자그룹 문서, 초대 코드, 생성자의 groupIds를 한 트랜잭션에 생성. 이름 1~30자, 설명 100자 이하, 욕설·혐오 표현 거절. 끝나면 배지 평가("함께하기")
joinCircle로그인 사용자코드 확인 → 이미 멤버면 alreadyMember: true(사용 횟수 미차감, groupIds 복구) → 차단·만료·사용 횟수·정원·Circle 수 확인 → memberIds·groupIds·useCount 갱신. 새로 참여했으면 배지 평가("함께하기"). 그 Circle에 처음이면 circleJoins 기록, 링크의 ref가 지금 멤버인 다른 사람이면 그 사람으로 기록하고 그 사람의 배지도 평가(invites_joined) → 초대 배지. 모두의 감사방을 가리키는 코드는 "초대 코드를 찾을 수 없어요"
getInviterRef로그인 사용자requireActiveUser → inviterRefs에서 내 참조를 찾고, 없으면 8자리를 뽑아 create()(겹치면 최대 5번 다시)
joinOpenCircle로그인 사용자모두의 감사방에 별명으로 참여 → 아래
renameOpenCircleAlias모두의 감사방 멤버별명 바꾸기(7일에 한 번) → 아래
leaveCircle멤버memberIds와 groupIds에서 제거. 관리자는 불가. 그룹이 없거나 멤버가 아니면 groupIds 정리만 (오래된 ID 정리용). 모두의 감사방이면 같은 트랜잭션에서 별명 문서와 선점(aliasNames)도 삭제
removeCircleMember관리자멤버 제거 + removedIds에 추가 + 그 사람의 groupIds에서 제거. 모두의 감사방이면 별명·선점도 삭제
unbanCircleMember관리자removedIds에서 제거 (자동 재참여는 아님)
deleteCircle관리자별명·선점 하위 컬렉션·첫 나눔 표시(circleFirstShares) 삭제 → 멤버들의 groupIds 정리 → 초대 코드 전부 삭제 → 그룹 문서 삭제(마지막) → Circle 사진(circlePhotos/{groupId}/) 삭제. 500개 단위 배치. 감사 글은 보존. 운영자의 Circle 삭제(moderate)와 setupOpenCircle --delete도 같은 deleteCircleData를 씀. 모두의 감사방은 거부(moderate도)
regenerateInviteCode관리자기존 코드 전부 삭제 + 새 코드 발급 + groups.inviteCode 갱신 (원자적). 모두의 감사방은 거부

users.groupIds는 삭제된 Circle이나 내보내진 Circle의 ID가 남아 있을 수 있습니다. createCircle·joinCircle은 트랜잭션 안에서 각 그룹 문서를 읽어 실제로 멤버인 것만 Circle 수에 세고(readUserCircles), groupIds를 그 목록으로 다시 씁니다.

utils/contentFilter.ts는 Firebase에 의존하지 않는 모듈이라 다른 곳에서도 씁니다. 질문 제출은 욕설과 연락처를 모두 거절하고, 자동 숨김과 Circle·공개 이름 검사는 욕설·혐오 표현만 봅니다(moderation/policy.ts의 moderationViolation).

shareRenderer ​

/share/gratitude/{id}, /share/calendar/{uid}/{YYYY-MM}, /share/badge/{badgeId}/{uid}, /invite/{code} 요청과 짧은 링크 /g/{code}, /c/{code}, /b/{code}, /i/{초대 코드}를 받아 SPA 템플릿에 페이지별 메타 태그와 본문을 넣어 돌려줍니다. 경로 해석은 순수 함수 parseSharePath(share/shortLinks.ts, 단위 테스트에 긴 링크 회귀 포함)가 합니다.

  • 짧은 링크 (/g /c /b): 코드 형식(8자, 초대 코드 글자)이 맞을 때만 shortLinks/{code}를 한 번 읽고, 종류가 접두어와 같으면 긴 링크와 같은 처리(handleGratitude·handleCalendar·handleBadge)를 부릅니다. 그래서 공개 판단·캐시(no-store)가 긴 링크와 같습니다. canonical·og:url은 짧은 링크이고, 이 페이지의 __SHARE_DATA__에는 주인의 uid를 넣지 않고 code를 넣습니다. 코드가 없거나 틀리거나 종류가 다르면 "찾을 수 없어요" + noindex(데이터 없음).

  • /i/{code}: /invite/{code}와 같은 처리, canonical과 본문의 참여 링크만 /i/. 코드 뒤에 붙은 경로 조각과 쿼리는 무시합니다(초대한 사람을 링크에 담을 여지, GRATO-15).

  • /go/{name} (캠페인, GRATO-91): 이름 형식([a-z0-9-] 3–32자, 소문자로 맞춤)이 맞을 때만 campaignLinks/{name}을 읽어 302. 사이트 안 대상이면 utm_*를 붙인 상대 경로(열린 호스트 그대로 — stg·미리보기 채널), App Store 링크면 그대로, 없거나 틀린 문서면 /. 찾은 캠페인만 analyticsEvents에 campaign_link_open {name}(uid·IP·기기 정보 없음, 기록이 실패해도 302는 나감). 캐시는 private, max-age=300 — CDN에 두면 함수가 불리지 않아 셈이 빠지므로 브라우저에만 5분. 판단은 순수 함수 campaignLinks.ts.
