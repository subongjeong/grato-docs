Cloud Functions ​

functions/src/index.ts가 내보내는 함수 목록과 동작을 정리합니다. 모두 Cloud Functions v2, Node 22, 리전 asia-northeast3입니다. utils/firebase.ts가 Admin SDK를 한 번만 초기화하고, 각 모듈은 여기서 db와 REGION을 가져옵니다.

공통 규약 (callable) ​

  • 오류는 한국어 HttpsError. 메시지는 사용자에게 그대로 보여 줄 수 있게 씁니다. 클라이언트 래퍼(src/lib/callable.js)는 메시지에 한글이 있으면 그대로, 없으면 상황별 기본 문구로 바꿉니다.
  • 입력 검증. requestData()는 객체가 아니면 {}로 바꾸고, 문서 ID 입력은 requireDocId()로 Firestore ID 규칙(비어 있지 않음, / 없음, 128자 이하 등)을 검사합니다. 길이는 charLength()로 코드 포인트 단위(이모지 1자)로 셉니다.
  • 트랜잭션 우선. 멤버십을 바꾸는 함수는 모두 읽기 → 검증 → 쓰기를 한 트랜잭션에서 합니다.
  • 잠긴 계정 거부. 데이터를 만드는 callable(createCircle, joinCircle, submitQuestion)은 requireActiveUser(uid)로 방금 삭제·정지된 계정을 "이용할 수 없는 계정이에요"(permission-denied)로 거부합니다. → 보안 규칙

Circle callable ​

공통 상수(circles/common.ts): 사용자당 Circle 20개, Circle당 멤버 50명, 초대 코드 유효 30일·사용 50회.

함수권한하는 일
createCircle로그인 사용자그룹 문서, 초대 코드, 생성자의 groupIds를 한 트랜잭션에 생성. 이름 1~30자, 설명 100자 이하, 욕설·혐오 표현 거절. 끝나면 배지 평가("함께하기")
joinCircle로그인 사용자코드 확인 → 이미 멤버면 alreadyMember: true(사용 횟수 미차감, groupIds 복구) → 차단·만료·사용 횟수·정원·Circle 수 확인 → memberIds·groupIds·useCount 갱신. 새로 참여했으면 배지 평가("함께하기")
leaveCircle멤버memberIds와 groupIds에서 제거. 관리자는 불가. 그룹이 없거나 멤버가 아니면 groupIds 정리만 (오래된 ID 정리용)
removeCircleMember관리자멤버 제거 + removedIds에 추가 + 그 사람의 groupIds에서 제거
unbanCircleMember관리자removedIds에서 제거 (자동 재참여는 아님)
deleteCircle관리자멤버들의 groupIds 정리 → 초대 코드 전부 삭제 → 그룹 문서 삭제(마지막) → Circle 사진(circlePhotos/{groupId}/) 삭제. 500개 단위 배치. 감사 글은 보존. 운영자의 Circle 삭제(moderate)도 같은 deleteCircleData를 씀
regenerateInviteCode관리자기존 코드 전부 삭제 + 새 코드 발급 + groups.inviteCode 갱신 (원자적)

users.groupIds는 삭제된 Circle이나 내보내진 Circle의 ID가 남아 있을 수 있습니다. createCircle·joinCircle은 트랜잭션 안에서 각 그룹 문서를 읽어 실제로 멤버인 것만 Circle 수에 세고(readUserCircles), groupIds를 그 목록으로 다시 씁니다.

질문 callable ​

질문 제안과 운영자 검토입니다(functions/src/questions/). 기능 설명은 질문 제안과 선정, 데이터는 데이터 모델을 보세요. 순수 함수는 questions/text.ts(문구 정규화·중복 키·한도·하루 한도 문서 ID·상태 전이·기본 질문 파싱)와 utils/contentFilter.ts(내용 필터)에 있고 node:test로 테스트합니다. 공통 메시지와 검증은 questions/common.ts에 있습니다.

submitQuestion ​

  1. 문구 정규화(NFC, 보이지 않는 문자·제어 문자 제거, 공백 정리) → 5~80자 → 내용 필터 → 종류(opening/followup, 없으면 opening). 여기서 거절되면 Firestore를 읽지 않습니다.
  2. 대기 중인 질문이 전체 300개 이상이면 거절(검토 대기열 보호). 트랜잭션 밖의 count() 집계라 근사치입니다.
  3. 한 트랜잭션에서: 오늘 시도 30번 → 오늘 제안 5개 → 검토 중 20개 → 검토 중·선정된 질문과 중복(dupKey) 확인. 거절되어도 시도 수는 기록하고, 받아들여지면 제안 수도 늘린 뒤 pending 문서를 만듭니다.
  4. authorPublicName은 같은 트랜잭션에서 읽은 publicProfiles/{uid}.publicName을 복사하되, 이름이 없거나 내용 필터에 걸리면 null입니다.
  5. 하루 한도 문서 questionQuota/{uid}_{YYYYMMDD}(KST)의 expireAt은 다음 날 끝이고 TTL로 지워집니다.

reviewQuestion ​

운영자(users/{uid}.isAdmin == true)만 부를 수 있습니다.

작업가능한 상태하는 일
approvepending, hidden문구·종류 수정(선택, 다시 검증), approvedAt, 공개 이름 갱신, 배지 평가, 처음 선정이면 제안자에게 알림 한 번

  • 공개 이름 확인. 선정 때 제안자의 현재 공개 이름(내용 필터 적용)을 읽어, 운영자 화면에 보이던 이름(expectedAuthorPublicName, 없으면 문서에 저장된 이름)과 다르면 선정하지 않고 새 이름만 저장한 뒤 failed-precondition을 돌려줍니다. 운영자는 목록을 다시 불러 새 이름을 확인하고 다시 선정합니다. 운영자가 보지 않은 이름이 질문과 함께 공개되지 않게 하기 위해서입니다.

  • 같은 문구. 선정된 질문끼리 dupKey가 같으면 거절합니다.
  • 모든 작업은 같은 트랜잭션에서 adminAuditLogs에 기록합니다(utils/adminAudit.ts). 질문 문서에는 운영자 정보를 남기지 않습니다.
  • 선정 뒤 부가 작업. 사용자 질문(source: "user")을 선정하면 트랜잭션이 커밋된 뒤 evaluateBadges(authorId)를 부르고, 처음 선정(approvedAt이 없던 질문)이면 question_selected 알림을 보냅니다(notificationLogs/question_selected_{id}로 한 번만). 둘 다 실패해도 로그만 남기고 선정 결과는 그대로 돌려줍니다. → 질문 선정 알림

내용 필터 ​

utils/contentFilter.ts는 Firebase에 의존하지 않는 모듈이라 다른 곳에서도 씁니다. 질문 제출은 욕설과 연락처를 모두 거절하고, 자동 숨김과 Circle·공개 이름 검사는 욕설·혐오 표현만 봅니다(moderation/policy.ts의 moderationViolation).

  • 욕설·혐오 표현(한국어·영어 짧은 목록): NFKC, 보이지 않는 문자 제거, 소문자로 맞춘 뒤 비교합니다. 단어 안의 구두점·숫자·이모지, 띄어 쓴 글자("씨 발"), 흔한 바꿔 쓰기(sh!t), 악센트(shît), 키릴·그리스 문자로 바꿔 쓴 글자를 정리합니다. 단어마다 띄어쓰기를 넘어 찾을지 정해 "아저씨 발걸음" 같은 문장은 막지 않고, "시발점", "감염병" 같은 단어는 허용 목록에 둡니다.
  • 연락처: URL·도메인(짧은 링크, naver[.]com 같은 표기 포함), 이메일, 8자리 이상 숫자(여러 구분자 허용). 날짜(2026.10.08), 연도 범위(2020~2024), 통화 단위가 붙은 금액은 전화번호로 보지 않습니다.
  • 모든 질문은 운영자가 검토하므로, 놓치는 것보다 정상 문장을 막는 쪽을 더 조심합니다. 목록은 BLOCKED_WORDS·ALLOWED_WORDS에서 늘립니다.

onGratitudeCreated 파이프라인 ​

글이 만들어지면 네 단계를 순서대로 실행합니다. 각 단계는 try/catch로 분리되어 한 단계가 실패해도 다음 단계는 실행됩니다.

  1. 자동 숨김 — Circle 글의 제목·내용이 욕설·혐오 표현 필터에 걸리면 숨기고 시스템 신고를 만듭니다. 최대한 빨리 숨기려고 맨 앞에 둡니다. 깨끗한 글은 필터만 돌고 읽기가 없습니다. → 자동 숨김
  2. 통계 — userStats/{uid}를 KST 기준으로 갱신합니다. 마커 statsLogs/gratitude_{id}를 같은 트랜잭션에서 만들어 중복 실행 시 두 번 세지 않습니다. 글이 이미 지워졌으면 세지 않습니다. 시각은 글의 createdAt(없으면 이벤트 시각)을 씁니다.
  3. 배지 — 방금 갱신된 통계로 배지를 평가합니다. 통계가 먼저여야 하므로 순서가 고정입니다. → 통계와 배지
  4. 알림 — Circle 글이면 작성자를 뺀 멤버 중 circlePostNotice를 끄지 않았고 작성자를 차단하지 않은 사람에게 보냅니다. 필터에 걸린 글은 숨기기에 실패했더라도 알리지 않습니다. 끝나면 notificationLogs/circle_post_{id}를 남깁니다.

onReportCreated ​

reports/{reportId}가 만들어지면(사용자 신고, 자동 숨김·이름 필터의 시스템 신고, 차단 신고):

shareRenderer ​

/share/gratitude/{id}, /share/calendar/{uid}/{YYYY-MM}, /share/badge/{badgeId}/{uid}, /invite/{code} 요청을 받아 SPA 템플릿에 페이지별 메타 태그와 본문을 넣어 돌려줍니다.

  • 템플릿: Hosting의 /index.html을 1.5초 제한으로 받아 1분 캐시합니다. 실패하면 마지막으로 성공한 템플릿, 그것도 없으면 함수 빌드에 포함된 share-template.html을 씁니다. 에뮬레이터에서는 항상 포함된 템플릿을 씁니다(SHARE_TEMPLATE_URL로 변경 가능).
  • 삽입(injectMeta.ts): <title>, description, canonical, Open Graph, Twitter 카드, 필요하면 noindex, JSON-LD, window.__SHARE_DATA__, 크롤러용 본문. 모든 값은 HTML 이스케이프하고, <script> 안의 JSON은 safeJsonForScript로 <, >, &, U+2028/2029를 이스케이프합니다. String.replace는 함수 치환자를 써서 사용자 내용의 $& 같은 패턴이 해석되지 않게 합니다.
  • 캐시: 공개 여부가 걸린 페이지(글·캘린더·배지)는 캐시하지 않음(private, no-store: 공개 취소·삭제가 바로 반영되도록), 초대 페이지는 5분(CDN 10분). 오류 시 no-store와 최소 메타로 200 응답.
  • 공개 판단은 외부 공유에 정리되어 있습니다. 숨긴 글(moderation.status == "hidden")은 공개 상태여도 "비공개 감사"로 보여 줍니다(검토 중이라는 사실도 드러내지 않음).

seedQuestions 스크립트 ​

functions/src/scripts/seedQuestions.ts는 함수로 배포되지 않는 스크립트입니다(index.ts에서 내보내지 않음). 실행할 때마다 저장소의 src/content/questions.json을 읽어(빌드된 lib/scripts/에서 저장소 루트 기준 경로로) 기본 질문을 맞춥니다. 배포 때 실행합니다. → 배포: 기본 질문 시드

  • questions/system_opening_01..30, system_followup_01..10을 만들거나 고칩니다(source: "system", status: "approved"). 이미 있는 문서는 운영자가 정한 approved/hidden을 유지하고, 그 밖의 상태(없음 포함)는 approved로 고칩니다. 문구·종류는 JSON으로 되돌리므로, 기본 질문은 문서가 아니라 JSON에서 고칩니다.

  • 배지 컬렉션이 비어 있으면 기본 배지를 먼저 만들고, 질문 배지 3개(questions_selected_1/3/10)는 없을 때만 만듭니다. 있는 배지는 덮어쓰지 않습니다. 질문 배지를 없애려면 지우지 말고 enabled: false로 둡니다.

  • JSON에 없는 system_* 문서는 건드리지 않고 목록만 출력합니다.

  • Application Default Credentials가 필요합니다. 에뮬레이터에 실행하려면 FIRESTORE_EMULATOR_HOST를 설정합니다.

purgeAiData 스크립트 ​

functions/src/scripts/purgeAiData.ts도 함수로 배포되지 않는 1회성 스크립트입니다. 없앤 AI 글쓰기 기능이 남긴 컬렉션 세 개의 문서를 모두 지웁니다. 사용자의 질문·답변이 들어 있고 더 쓸 곳이 없기 때문입니다. → 결정 기록 #10

  • 문서를 500개 이하씩 배치로 지우고, 컬렉션별 삭제 수와 합계를 출력합니다.
  • --dry-run은 지우지 않고 컬렉션별 문서 수만 셉니다.
  • 멱등적이라 다시 실행하면 0개로 끝나는지 확인할 수 있습니다. 지운 데이터는 되돌릴 수 없습니다.
  • 실행 시점: 기능을 없앤 릴리스(함수·규칙·Hosting)를 배포한 뒤. 그래야 그 사이에 새 문서가 생기지 않습니다.
