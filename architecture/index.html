시스템 구성 ​

Grato는 Firebase 위에서 동작하는 SPA(React)입니다. 클라이언트는 보안 규칙이 허용하는 범위에서 Firestore를 직접 읽고 쓰고, 권한 판단이나 비밀값이 필요한 일은 Cloud Functions가 맡습니다.

전체 구성도 ​

  • 리전: 모든 함수는 asia-northeast3(서울)에 배포됩니다. 클라이언트도 getFunctions(app, 'asia-northeast3')로 같은 리전을 호출합니다.
  • Admin SDK는 보안 규칙을 거치지 않습니다. 그래서 서버 전용 데이터(멤버십, 통계, 배지, 댓글 수, 질문, 숨김, 신고 처리, 계정 잠금)는 규칙에서 클라이언트 쓰기를 모두 막고 함수만 씁니다.

주요 요청 흐름 ​

1. 감사 글 작성 ​

2. Circle 참여 ​

클라이언트는 joinCircle({code})만 호출하고, 함수가 트랜잭션 안에서 초대 코드·정원·차단 목록을 확인한 뒤 groups.memberIds와 users.groupIds를 함께 바꿉니다. → Circle 참여 흐름

3. 질문으로 쓰기 ​

클라이언트가 선정된 질문(questions, status == "approved")을 세션에 한 번 읽어 질문을 고릅니다. 읽지 못하면 앱 안의 기본 질문(src/content/questions.json)을 씁니다. 답변을 이어 붙여 초안을 만드는 것은 기기 안에서 하고, 저장은 1번과 같은 경로로 합니다. 작성 내용을 외부 AI 서비스로 보내지 않습니다. → 질문으로 쓰기

4. 질문 제안과 선정 ​

제안한 질문은 운영자가 선정하기 전까지 제안자와 운영자만 읽을 수 있습니다. → 질문 제안과 선정

5. 공유 링크 열기 ​

작성자가 공개하지 않은 글·캘린더 월·배지는 내용 없이 "비공개" 페이지(noindex)를 돌려줍니다. → 외부 공유

Hosting ​

firebase.json의 Hosting 설정:

경로처리
/share/**shareRenderer 함수 (asia-northeast3)
/invite/**shareRenderer 함수 — 초대 링크 미리보기(Circle 이름, 인원)
/.well-known/apple-app-site-association, /.well-known/assetlinks.json정적 파일 (public/.well-known/). 초대·공유 링크를 앱으로 여는 연결 파일. AASA는 Content-Type: application/json 헤더, appAssociation: "NONE" → 링크로 앱 열기
그 밖의 모든 경로정적 파일이 있으면 그 파일, 없으면 /index.html (SPA). /assets/**, /.well-known/**은 SPA로 돌리지 않음
  • 정적 파일이 rewrite보다 우선합니다. prerender가 만든 SEO 페이지(/what-is-grato/index.html 등)는 그대로 서빙됩니다.
  • shareRenderer는 Hosting의 /index.html을 직접 받아와 템플릿으로 씁니다. 그래서 Hosting만 다시 배포해도 공유 페이지가 새 JS·CSS 번들을 가리킵니다.

시간대 ​

서버의 날짜 계산은 모두 KST(Asia/Seoul, UTC+9, 서머타임 없음) 기준입니다. 클라이언트도 같은 규칙의 헬퍼(src/lib/kst.js)로 "오늘", "이번 달"을 판단합니다. 이유는 결정 기록 #7을 보세요.
