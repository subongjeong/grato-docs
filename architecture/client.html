클라이언트 ​

React 18 + Vite 5 SPA입니다. 상태는 Zustand, 라우팅은 React Router 6, 스타일은 Tailwind CSS를 씁니다. 같은 코드가 웹(grato.today)과 iOS·Android 앱(Capacitor)에서 돌고, 앱에서만 쓰는 부분은 네이티브 레이어에 모여 있습니다.

진입점 ​

src/main.jsx가 (앱이면 <html>에 native 클래스를 붙이고) initAuth()로 Firebase Auth 구독을 시작한 뒤 <ErrorBoundary><App /></ErrorBoundary>를 렌더링합니다. initAuth는 앱 전체에서 한 번만 구독합니다. 첫 화면이 지연 로딩 페이지(공유·SEO 페이지 등)이면 그 페이지 코드를 먼저 받은 뒤 렌더링해, 미리 렌더링된 내용 위에 로딩 화면이 깜빡이지 않게 합니다. → 성능

  • 홈·로그인·온보딩을 뺀 페이지는 src/routes.jsx에서 페이지별 코드로 나뉘어(lazyPage) 처음 열 때 받습니다.
  • PrivateRoute는 로그인하지 않았으면 /login으로, PublicRoute는 로그인했으면 /home으로 보냅니다. 인증 상태를 확인하는 짧은 동안에는 전체 로딩 화면 대신 페이지 뼈대(PageSkeleton)를 보여 줍니다.
  • PrivateRoute는 ConsentGate로 감싸여, 현재 약관에 동의하지 않은 사용자를 /consent로 보냈다가 동의 후 원래 경로로 돌려보냅니다. 판단은 consentStatus(state)(ok | needed | unknown)이고, 프로필을 모르는 동안(unknown)은 화면을 막지 않습니다. /consent, /settings/delete-account는 동의 없이 들어갑니다. /consent에서는 아래 탭 막대를 숨깁니다.
  • 초대 링크로 들어온 비로그인 사용자는 코드를 localStorage의 pendingInviteCode에 저장해 두고, 로그인 후 PublicRoute가 /invite/{code}로 되돌려 보냅니다.
  • 공유·초대 페이지는 shareRenderer가 넣어 준 window.__SHARE_DATA__가 있으면 그것으로 먼저 그립니다.
  • 웹 페이지가 열려 있을 때 받은 푸시는 App.jsx가 브라우저 Notification으로 띄우고(앱은 네이티브로 처리), 클릭하면 글 상세, /write, 질문 선정 알림이면 /mypage#questions, 운영자 신고 알림이면 /admin?tab=reports로 이동합니다.

상태 (Zustand) ​

authStore ​

상태설명
userFirebase Auth 사용자
userProfileusers/{uid} 문서 (실시간 구독, 재방문 땐 기기 캐시에서 즉시). undefined=아직 모름, null=문서 없음
loading첫 인증 상태 확인 전 true (Firestore는 기다리지 않음)
profileReady로그인 동기화가 끝났는지. 신규 사용자의 초대 참여는 이 값을 기다립니다(클라이언트가 users/{uid}를 먼저 만들도록). 첫 글·댓글도 whenProfileReady()로 동기화를 기다립니다
lastPostDateKey이번 세션에서 글을 쓴 KST 날짜. 통계 트리거가 반영되기 전까지 화면이 "오늘 기록함"으로 보이게 함. 그 글을 지우면 비움
freshAccount방금 만든 계정의 첫 로그인(Auth 메타데이터, 네트워크 없음). 프로필을 기다리지 않고 동의 화면을 띄우는 데 씀
consentAcceptedUid이번 세션에 현재 약관에 동의한 uid (users.consent 쓰기가 아직 도착하지 않았어도 통과)

로그인 시 흐름: 화면 렌더링 → users/{uid} 구독 시작 → 뒤에서 createOrUpdateUser(바뀐 것이 있을 때만 users + publicProfiles + 이름 선점을 한 배치로) → profileReady = true → 화면이 뜬 뒤 이미 허용된 경우에만 푸시 토큰 등록. 같은 기기에서 하루 안에 같은 값으로 동기화했다면 읽기·쓰기 없이 넘어갑니다(src/lib/profileSync.js). 로그아웃 시 groupStore.reset()으로 이전 사용자의 Circle 상태를 비우고, 이 기기의 Firestore 캐시를 지운 뒤 다시 불러옵니다.

groupStore ​

상태설명
groups, activeGroupId내 Circle 목록과 선택된 Circle
homeTab홈에서 보이는 탭: mine(내 기록, 기본) 또는 circle
feeds{ [피드 키]: { live, older, lastDoc, hasMore, paged, error } } — 키는 __mine__(내 기록) 또는 groupId. 없음(undefined)=로딩 중
retryFeed(key)실패한 피드를 로딩 상태로 되돌리고 구독을 다시 붙임
removeGroup()탈퇴·삭제·내보내진 Circle을 지우고 남은 Circle(없으면 내 기록)로 선택을 옮김

feeds[key]가 없는 동안은 로딩으로 보고, 구독 오류는 error로 따로 표시해 "글이 없음"과 구분합니다. → 결정 기록 #5

  • useGroups 훅은 userProfile.groupIds로 그룹 문서를 읽어 목록을 만듭니다. 읽을 수 없는 Circle은 로컬에서 숨기고, 문서가 사라진 것이 확인된 Circle은 leaveCircle을 호출해 서버의 groupIds에서도 지웁니다. /write와 MyPage는 Circle 이름이 필요해 useGroups({ skipIfLoaded: true })를 씁니다(스토어의 목록이 groupIds와 같으면 다시 읽지 않음).
  • showMyFeed(), openCircleFeed(groupId)가 홈 탭을 바꿉니다. 글을 저장하면 글이 간 곳(내 기록 또는 그 Circle)을 열어 둔 채 홈으로 갑니다.

홈 피드: 내 기록 + Circle 탭 ​

홈 피드는 탭으로 나뉩니다. 첫 탭이자 기본 탭은 내 기록(homeTab: 'mine')이고 Circle이 없어도 있습니다. Circle 탭은 그 뒤에 이어집니다. → 결정 기록 #12, 감사 글: 내 기록

탭피드 키실시간 첫 페이지"더 보기"카드
내 기록__mine__subscribeToUserGratitudes: userId == 나, createdAt 내림차순, 20개loadMoreUserGratitudes작성자 대신 공개 범위 표시(showVisibility): 나만 보기 / 링크 공개 / Circle 이름
CirclegroupIdsubscribeToGroupGratitudes: groupId == X, createdAt 내림차순, 20개loadMoreGroupGratitudes작성자 표시
  • useHomeFeeds 훅(홈에서만)은 내 기록을 항상, Circle 피드는 그 탭을 처음 열 때부터 실시간 구독하고, 홈을 떠날 때 모두 해제합니다. 두 쿼리 모두 규칙이 허용하는 list 형태이고 기존 복합 인덱스를 씁니다.
  • 선택된 Circle이 목록에 없으면(탈퇴·삭제) 내 기록을 보여 줍니다.
  • 구독이 실패하면 error가 표시된 상태가 들어오고, 화면은 "기록을 불러오지 못했어요"(Circle은 "Circle 소식을 불러오지 못했어요")와 "다시 시도"를 보여 줍니다. 이미 글이 보이면 위쪽에 작은 안내로만 보여 줍니다. "다시 시도"는 retryFeed(key)입니다.
  • src/lib/feed.js(순수 함수, 테스트 있음)가 실시간 첫 페이지와 "더 보기" 페이지를 합칩니다. 새 글로 첫 페이지에서 밀려난 글은 이전 페이지 앞에 붙이고, 다시 붙은 구독의 첫 페이지가 이전 첫 페이지와 겹치지 않으면(사이에 빠진 글이 있을 수 있음) 새 첫 페이지부터 다시 시작합니다. 끝까지 읽은 피드는 실시간 갱신 뒤에도 "더 보기"를 다시 보이지 않습니다.
  • Circle이 없으면 탭 아래에 Circle 만들기·참여 안내 카드가 함께 보입니다.

화면 스타일 ​

  • 배경: 크림 #FFF7ED(body, bg-orange-50). 카드(.card): 흰색 + 따뜻한 테두리 #F1E4D1 + 그림자로 배경에서 띄웁니다. 카드 안의 bg-amber-50·bg-orange-50 칸은 연한 무채색 #F7F7F5(크림 칸이 흰 카드 옆에서 바랜 종이처럼 보여서, 2026-10).

  • 사진: common/Photo(이름 첫 글자 위에 사진이 받아지면 서서히 나타남, 이번 세션에 이미 본 사진은 바로), 로고는 common/Brand(인라인 SVG). 올리는 사진은 512px로 줄이고 1년 캐시 → Storage 규칙

푸시 권한 흐름 ​

브라우저 권한 요청은 반드시 사용자 동작(버튼 클릭) 안에서만 합니다.

  • registerPushToken(uid)는 기본적으로 묻지 않습니다. enablePushNotifications(uid)(= {prompt: true})만 권한 창을 띄웁니다.
  • 홈의 PushPromptCard는 권한이 default이고 FCM을 지원하는 브라우저에서만 보이며, 닫으면 localStorage(push-prompt-dismissed)에 기억합니다.
  • MyPage의 알림 설정에서도 같은 방식으로 켤 수 있습니다.

앱은 같은 원칙(버튼을 눌렀을 때만 묻기)으로 OS 권한을 요청하고, 권한 하나로 푸시와 휴대폰 자체 매일 알림을 함께 켭니다. 자세한 내용은 알림, 알림: 앱을 보세요.

네이티브 레이어 (iOS·Android 앱) ​

앱은 같은 React 코드를 Capacitor 웹뷰에 담아 돌립니다. 앱에서만 필요한 일은 src/lib/platform.js의 isNative 분기와 src/lib/native/에 모여 있고, 웹사이트의 번들과 동작은 바뀌지 않습니다. 빌드·설정·출시 절차는 iOS·Android 앱에 있습니다.

규칙 ​

  • 플랫폼 판단은 platform.js로. isNative는 @capacitor/core를 가져오지 않고 앱이 문서 시작 전에 넣는 window.Capacitor를 읽습니다. core를 정적으로 가져오면 웹사이트의 첫 화면 코드에 들어가기 때문입니다.
  • 앱 코드는 isNative 안에서 동적으로. 플러그인(@capacitor/*, @capacitor-firebase/*)과 src/lib/native/*는 if (isNative) 안의 import()로만 불러옵니다. 웹 빌드에는 따로 떨어진 조각으로만 남고 받지 않습니다.
  • 시작을 막지 않음(ADR-13). App.jsx는 앱에서만 NativeBridge를 lazy로 붙이고, 그 안의 각 부분은 첫 화면 뒤에 따로 시작하며 실패해도 화면에 영향이 없습니다.
  • 기기 밖으로 나가는 링크는 siteUrl(). 앱의 출처는 capacitor://localhost(iOS), https://localhost(Android)라서 window.location.origin으로 만든 공유·초대 링크는 다른 사람에게 열리지 않습니다.
  • 앱 전용 CSS는 html.native 아래. main.jsx가 앱에서만 <html>에 native, native-ios / native-android를 붙입니다.

시작 순서 ​

  • 화면을 막지 않음: 예전에는 프로필 동기화(읽기·쓰기 6~7번 왕복)가 끝나야 첫 화면이 나왔습니다. 지금은 인증 확인 직후 그립니다.
  • 기기 캐시: Firestore persistentLocalCache(IndexedDB, 여러 탭 공유). IndexedDB가 없는 브라우저(일부 인앱 브라우저·사생활 모드)는 메모리 캐시로 동작합니다. 로그아웃하면 캐시를 지웁니다.
  • 로그인 준비 파일: getAuth 대신 initializeAuth(팝업·리다이렉트 리졸버 없이)로 시작해, 휴대폰·Safari에서 매번 받던 구글 iframe 4개를 시작 경로에서 뺐습니다. 휴대폰·Safari는 로그인 화면에서 미리 받고, 데스크톱은 구글 버튼에 마우스를 올리거나 포커스할 때 받습니다. getRedirectResult는 리다이렉트 로그인을 실제로 시작했을 때만 호출합니다.
  • 코드 분할: 첫 화면에는 React와 Firebase App·Auth·Firestore만 싣습니다. Functions(lib/callable.js), Storage(lib/storage.js), Messaging은 처음 쓸 때 받고, 로그인 1.5초 뒤 유휴 시간에 미리 받아 둡니다(데이터 절약 모드·느린 연결에서는 생략).
  • 배포 직후·오프라인: 지연 로딩 코드가 없으면(lib/chunkLoad.js) 온라인일 땐 새 버전으로 한 번 새로고침하고, 오프라인일 땐 앱 안에서 안내한 뒤 연결되면 다시 불러옵니다. 없는 코드 파일 주소는 HTML 대신 404를 받습니다(firebase.json 재작성 규칙).
  • 캐시 헤더: /assets/**는 immutable 1년, HTML·서비스 워커는 no-cache(배포 직후에도 새 HTML을 받음).
  • 글꼴·연결: Noto Sans KR은 첫 화면을 막지 않게 받고, 한국어 시스템 글꼴을 대체 서체로 둡니다. 인증·Firestore 서버에 미리 연결(preconnect)합니다. SEO 페이지는 주소 끝 / 리다이렉트 없이 바로 응답합니다(trailingSlash: false).
  • 페이지 데이터: 마이페이지 목록은 20개씩, 캘린더는 보고 있는 KST 달만 읽고 지난달은 세션 동안 다시 읽지 않습니다(오프라인 캐시로 채운 달은 보관하지 않음). 홈의 "오늘의 Circle 활동"은 첫 화면 뒤에 계산합니다.
