출시 준비 체크리스트 ​

iOS·Android 앱 출시와 국내 서비스 운영에 필요한 요건을 정리한 체크리스트입니다. 스토어 정책, 국내 법령, 보안·운영, 접근성 네 영역을 검토했습니다.

검토 기준

  • 마지막 검토: 2026-10-07. 각 요건을 그 시점의 공식 원문(Apple·Google 정책 페이지, 국가법령정보센터)과 대조했습니다.
  • 상태 갱신: 2026-10-08, 2단계 코드 기준(배포 예정). 웹에서 동작하는 것은 ✅로 표시했고, 네이티브 앱에서 다시 확인할 부분은 3단계 항목에 있습니다. 3단계 항목은 2026-10-09 앱 코드 기준(실제 기기 확인 전)이며 🔶는 "코드 완료, 기기·제출 확인 남음"입니다. → iOS·Android 앱: 출시 체크리스트
  • 법률 자문이 아닙니다. 약관과 처리방침 최종본은 운영자가 확인해야 합니다.
  • 정책은 자주 바뀌므로 스토어 제출 직전에 한 번 더 확인합니다.

  • 차단은 개발자에게도 알림: 차단하면 운영자 대기열에 낮은 우선순위 신고가 남습니다(Apple 1.2). 차단 확인 창에도 "운영자에게는 검토를 위해 알려요"라고 씁니다.

🟡 권장 ​

스토어·정책

  • 감사 글 삭제 기능 ✅ 2단계 (감사 글: 삭제)
  • 공개 공유 페이지에 로그인 없이도 신고·삭제를 요청할 수 있는 경로 (정보통신망법 제44조의2) ✅ 공유 페이지의 "신고하기"(이메일), 약관 제11조의 권리 침해 신고·임시 조치
  • Play 아동 안전 표준 공개: 앱을 소셜 카테고리로 등록하는 경우 해당
  • 수출 규정 신고: ITSAppUsesNonExemptEncryption = false
  • 기기 변경 시 로그인 복원: Play, 2027년부터

보안·운영

  • App Check: 웹은 reCAPTCHA Enterprise, iOS는 App Attest, Android는 Play Integrity
  • Hosting 보안 헤더: HSTS, CSP, X-Content-Type-Options, Referrer-Policy
  • Universal Links·App Links 파일: Hosting 설정의 appAssociation과 함께 정리
  • 운영·개발 Firebase 프로젝트 분리, Crashlytics, 에러·예산 알림
  • CI에서 테스트 3종 자동 실행, 의존성 취약점 정리
  • 이메일 존재 여부 노출 방지, 비밀번호 정책
  • 프로젝트 삭제 방지(lien), IAM 정리
  • 업로드 사진의 위치 정보(EXIF) 제거

접근성·품질 (WCAG 2.2 AA / KWCAG 2.2 기준)

  • 아이콘 버튼 이름, 입력란 레이블과 오류 안내, 색 대비 4.5:1
  • 대화상자 의미 구조와 포커스 관리, window.confirm/alert를 앱 내 컴포넌트로 교체 (🔶 삭제·차단·Circle 설정은 ConfirmDialog로 바꿈, 일부 화면은 남음)
  • 터치 영역 24px 이상(권장 44pt/48dp), 포커스 표시, 화면 전환 시 제목 갱신
  • 동작 줄이기·글자 크기 확대 대응, 다크 모드 또는 color-scheme: light 명시
  • 모바일에서 포그라운드 알림을 Service Worker로 표시
  • 한글 입력 조합 중 Enter 처리
  • 오프라인·오류·빈 화면을 구분해 안내, 404 화면
