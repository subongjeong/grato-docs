이미지 테마 템플릿 (작가 콜라보) ​

작가가 템플릿에 색과 그림만 넣어 건네면, 코드를 고치지 않고 새 이미지 테마(배지 보상)로 올립니다. 템플릿은 resources/theme-template/, 등록은 스크립트 한 번입니다. → 배지 보상: 이미지 테마, 캘린더 칸 아이콘

한눈에 ​

  1. 작가에게 resources/theme-template/ 폴더를 건넵니다(아래 작가에게 줄 것).
  2. 작가가 돌려준 폴더를 resources/themes/<id>/(저장소 밖이어도 됨)에 둡니다.
  3. node resources/theme-template/add-theme.mjs <폴더> --dry-run → 문제가 없으면 --dry-run 없이.
  4. npm test → PR → 병합.
  5. 배포: 규칙·함수(firestore, functions — 테마 id 목록) → Hosting(그림 파일·웹) → 앱 새 빌드.
  6. 관리자 › 배지에서 보상으로 줄 배지의 "이미지 테마"에 새 테마를 고릅니다.

새 테마는 그 테마를 아는 앱(그 빌드 이후)과 웹에서만 보입니다. 예전 앱은 같은 배지를 받아도 기본 테마로 그립니다(받은 테마는 남아 있다가 새 앱에서 보임).

색 토큰 ​

colors는 모두 #RRGGBB(그림자만 rgba(r,g,b,a))입니다. 스크립트가 대비를 검사해 모자라면 등록하지 않습니다.

토큰쓰는 곳대비
bg이미지 바탕
card, border, shadow흰 카드, 카드 테두리(1px), 그림자
text, sub, muted제목·본문, 보조 글, 가장 옅은 글bg·card 위에서 4.5:1 이상 (앱 규칙: text-gray-400보다 옅게 쓰지 않음)
accent강조 숫자("기록한 날")bg·card 위에서 4.5:1
chipBg, chipText"오늘의 감사" 같은 라벨글자 4.5:1
recFill기록한 날 동그라미(아이콘이 없을 때)날짜 숫자(text) 4.5:1
ring오늘 테두리card 위에서 3:1
tile배지 아이콘 칸
swatch테마 고르기 칩의 색 점
iconFill, iconLine칸 아이콘의 몸통·선 (cell-icon.svg가 있을 때 필수)숫자/몸통 4.5:1, 선/카드 3:1

칸 아이콘 cell-icon.svg ​

  • viewBox="0 0 32 32". 층(그룹) 이름이 색을 정합니다: body…는 iconFill(연한 몸통 — 날짜 숫자가 그 위에 올라감), line…은 iconLine(진한 선·꾸밈). 문서 순서대로 그립니다(예: line-back → body → line-front). guide 층은 무시합니다.
  • 채우기만 씁니다. 선은 "윤곽선 만들기"로 도형으로 바꾸고, 변형(회전·크기)은 적용한 뒤 저장합니다. 쓸 수 있는 도형은 패스·원·타원·사각형·다각형, 모두 합쳐 8개까지(패스 하나 2000자 이하). 구멍은 fill-rule="evenodd".
  • 숫자 자리(가운데 가로 14 × 세로 10)는 몸통 안에 있어야 읽힙니다. 한 달 내내 같은 아이콘 하나가 기록한 날마다 찍힙니다.
  • 내장 아이콘을 쓰려면 SVG 대신 theme.json에 "cellIcon": "fruit" | "star" | "sun".

작가에게 줄 것 ​

  • resources/theme-template/ 폴더 전체(템플릿 theme.json, cell-icon.svg, layout-*.svg 세 장)와 이 문서.
  • 샘플: resources/theme-template/samples/winter/ — 앱의 겨울 테마를 이 템플릿으로 다시 만든 것(눈 결정 띠, 위·아래 그림, 별 아이콘). 등록하면 앱의 겨울 테마와 같은 이미지가 나옵니다.
  • 실제로 등록한 예: resources/themes/harvest/ — 가을 테마(GRATO-111). 그림 원본은 SVG와 그 SVG를 쓰는 draw.mjs(손으로 적은 도형, node resources/themes/harvest/draw.mjs로 PNG를 다시 만듦), 칸 아이콘은 층(line-back → body → line-front)으로 그린 감.
  • 지켜 주세요: 작가가 직접 그린 그림만(Grato는 생성형 AI를 쓰지 않아, 생성 도구로 만든 그림은 받지 않음 — ADR-10), 다른 캐릭터·브랜드·로고를 닮게 그리지 않기, 특정 종교 상징을 앞세우지 않기, 사람 얼굴·실제 장소 사진 넣지 않기, 그림 안에 글자 넣지 않기.
  • 저작권·사용 범위 동의: 계약서 문구는 오너가 정합니다. 최소한 담을 것 — 이용 허락 범위(Grato 앱·웹 안의 이미지 테마, 사용자가 만든 이미지의 공유 포함, 홍보물에 테마 미리보기 사용), 기간(무기한 또는 정한 기간, 끝나도 이미 받은 사용자의 테마는 남음), 작가 이름 표기 여부, 수정 허락(크기·색 대비 맞춤), 제3자 권리 침해가 없다는 보증.

등록 ​

bash
node resources/theme-template/add-theme.mjs path/to/folder --dry-run   # 검사만
node resources/theme-template/add-theme.mjs path/to/folder             # 등록
npm test

스크립트(resources/theme-template/add-theme.mjs, 검사는 순수 모듈 src/lib/themeFile.js)가 하는 일:

  • theme.json·색 대비·아이콘·PNG 크기와 용량 검사(하나라도 틀리면 아무것도 쓰지 않음)
  • PNG를 public/themes/<id>/에 복사(웹 Hosting과 앱 빌드에 함께 들어감)
  • src/content/imageThemes.json에 항목 추가(같은 id면 바꿈) — src/lib/themes.js가 내장 테마 뒤에 읽음
  • functions/src/badges/themes.json과 firestore.rules의 imageThemeIds()에 id 추가(세 목록이 같아야 하는 기존 규칙, themes.test.js가 확인)

앱 코드는 바뀌지 않습니다. 그림은 이미지를 그릴 때 한 번 내려받고(같은 출처라 캔버스에 그대로 그려짐), 못 받으면 그 층만 빠지고 색은 그대로입니다.

배포 순서 ​

  1. 규칙·함수: firestore(배지에 새 테마 id를 달 수 있게), functions(새 테마를 지급할 수 있게)
  2. Hosting: public/themes/<id>/ 그림과 새 테마를 아는 웹
  3. 앱 새 빌드(1.0.1 (7) 이후)
  4. 관리자 › 배지 › 이미지 테마에서 연결. 배지에 달기 전에는 아무에게도 지급되지 않습니다.

규칙 배포 전에 배지에 새 테마를 달면 규칙이 거절합니다. 앱 업데이트 없이 테마를 더하는 것(서버 테마 문서·Storage 업로드)은 GRATO-106에서 다룹니다.
