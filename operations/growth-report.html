그로스 리포트 주소 ​

클라우드에서 도는 그로스 세션이 운영 데이터를 직접 읽고 오너에게 보고할 수 있게 하는 읽기 전용 주소입니다(GRATO-123, ADR-48). 클라우드 세션은 오너 맥의 구글 로그인을 쓸 수 없어서, 비밀 토큰 하나로 여는 HTTPS 함수 growthReport를 둡니다.

  • 읽기만 합니다. 무엇도 쓰거나 바꾸지 않습니다.
  • 사람은 가명으로만 나갑니다. 이름·uid·이메일·글 내용·초대 코드는 나가지 않습니다(아래).
  • 숫자는 관리자 › 분석과 같습니다. 습관·전체·모두의 감사방 지표는 분석 화면이 부르는 계산을 그대로 씁니다.

부르는 법 ​

GET https://asia-northeast3-<프로젝트>.cloudfunctions.net/growthReport?days=7&include=events,activity
Authorization: Bearer <토큰>
매개변수값기본
days이벤트를 볼 기간(지금부터 거꾸로), 1–30일7
includeevents, activity, metrics, openCircle을 쉼표로events,activity
  • 토큰은 Authorization 헤더로만 받습니다. 주소(?token=)에 넣으면 거부합니다(로그에 남지 않게).
  • 범위를 벗어난 값이나 모르는 이름은 기본값으로 바뀝니다. 오류 대신 기본 보고가 옵니다.
  • 응답: 토큰이 없거나 틀리면 401, GET이 아니면 405, 비밀값이 아직 없으면 503, 서버 오류는 500. 내용은 {error} 한 줄입니다.

돌려주는 것 ​

맨 위에 generatedAt(KST ISO 시각), timezone: "Asia/Seoul", sections(실제로 담은 칸), docsRead(읽은 문서 수)가 있고, 고른 칸마다 아래가 붙습니다.

events: 기간의 이벤트 ​

analyticsEvents에서 기간 안의 이벤트를 오래된 것부터, 최대 5,000개(넘으면 최근 것을 남기고 truncated: true).

  • window — {days, from, to}(KST ISO).
  • summary — 운영자 계정을 뺀 합계: events, people, byEvent(이벤트마다 {events, people}, 많은 순). 뺀 운영자 이벤트는 operatorEvents, 사람이 없는 이벤트(캠페인 링크 열기, 탈퇴한 사람)는 anonymousEvents.
  • people — 기간에 이벤트를 남긴 사람: id(가명 p_ + 16진 10자), operator(운영자 계정이면 true), joined(가입한 KST 날짜), signupPlatform, events(기간의 이벤트 수).
  • events — 한 줄에 {at, event, platform, person, props}. 가입 수는 signup_completed가 아니라 activity.signups·metrics.totals(계정 기준)로 봅니다 — 이 이벤트는 2026-11-02 전에는 이메일 가입만 남았습니다(GRATO-127). 이벤트 이름의 뜻은 src/lib/eventLabels.js(EVENT_LABELS, 관리자 › 분석 › 최근 이벤트와 같은 문장)에 있습니다. person은 가명이나 null, platform은 web·ios·android(서버가 남긴 이벤트는 null).
  • droppedPropKeys — 허용 목록에 없어 뺀 props 키 이름(값은 없음). 새 이벤트 속성이 생겼다는 뜻이라, 비어 있지 않으면 개발 세션에 알려 확인하게 합니다.

activity·metrics·openCircle ​

  • activity — 습관 지표(adminActivityMetrics와 같은 값: 쓴 사람 DAU·MAU, 습관층, 코호트, 관문, 새 가입 signups: {today, weeks}). 매일 밤 집계와 최근 8주 가입 계정만 읽어 싸고, 기본으로 담깁니다.
  • metrics — 분석 화면의 전체 지표(adminMetrics와 같은 값: 가입·유입 경로·D1/D7/D30·Circle·초대·첫 나눔·쓰기 계획). 사용자 전체와 120일 글의 메타데이터를 읽어 비싸므로 필요할 때만 고릅니다.
  • openCircle — 모두의 감사방 지표(첫 멤버가 참여한 날–오늘, 최대 92일). 방이 없으면 {room: null}. 1–2명에 기대는 칸은 분석 화면처럼 가립니다.

나가지 않는 것 ​

  • 이름·uid·이메일: 사람마다 가명 하나만 나갑니다. 가명은 비밀값으로 만든 HMAC이라, 비밀값이 같으면 같은 사람은 늘 같은 가명이고 비밀값 없이는 uid로 되돌릴 수 없습니다. 비밀값을 바꾸면 모두 새 가명이 됩니다.
  • 글·댓글 내용: 글 내용은 읽지 않습니다. metrics·openCircle은 분석 화면처럼 글의 작성자·시각·Circle 같은 메타데이터만 읽고 개수로만 돌려주므로, "나만 보기" 글도 개수에만 들어갑니다.
  • props: 허용 목록(ALLOWED_PROPS, functions/src/admin/growthReportCalc.ts)에 있는 키만, 그것도 짧은 값(64자 이하 문자열·숫자·참거짓)만 나갑니다. 초대 코드(code)는 늘 빠지고, Circle id(groupId)는 가명(g_…)으로 바뀝니다. 앱에 새 이벤트 속성을 더하면, 내보내도 되는 값인지 보고 이 목록에 더해야 리포트에 나옵니다.

처음 설정 (오너) ​

stg에서 먼저 확인하고 운영에 같은 순서로 합니다. 비밀값은 프로젝트마다 따로 만듭니다.

함수 배포 전에 비밀값부터

이 함수가 들어간 뒤로는 그 프로젝트에 GROWTH_REPORT_SECRET이 없으면 모든 함수 배포가 실패합니다(CI 배포 포함). 프로젝트마다 1번을 먼저 합니다.

  1. 비밀값 만들기 — 값을 클립보드에 만들어 Secret Manager에 넣습니다. 같은 값을 5번에 씁니다.
    openssl rand -hex 32 | tr -d '\n' | pbcopy
pbpaste | firebase functions:secrets:set GROWTH_REPORT_SECRET --data-file=- --project stg
  2. 배포 — firebase deploy --only functions:growthReport --project stg. 배포가 함수의 서비스 계정에 비밀값 읽기 권한을 줍니다. 처음 만들 때는 공개 호출 권한을 정해야 해서 배포하는 계정에 cloudfunctions.functions.setIamPolicy(Cloud Functions 관리자·소유자)가 필요합니다. 없으면 "Missing required permission … to deploy new HTTPS functions"로 멈추니, 그 권한이 있는 계정으로 --account <계정>을 붙여 다시 배포합니다.
  3. 공개 호출 허용 — 토큰이 유일한 문이라 Cloud Run 호출은 누구나 할 수 있어야 합니다. CLI가 이 권한을 못 붙이면(배포 끝에 "Failed to set the IAM Policy") 직접 붙입니다.
    gcloud run services add-iam-policy-binding growthreport --region asia-northeast3 --project <프로젝트 ID> --member=allUsers --role=roles/run.invoker
  4. 확인 — 토큰 없이 부르면 401, 토큰을 붙이면 200과 JSON이 와야 합니다.
    curl -s -o /dev/null -w '%{http_code}\n' https://asia-northeast3-<프로젝트 ID>.cloudfunctions.net/growthReport
curl -s -H "Authorization: Bearer $(pbpaste)" 'https://asia-northeast3-<프로젝트 ID>.cloudfunctions.net/growthReport?days=1' | head -c 300
  5. 클라우드 환경 — 그로스 세션이 도는 클라우드 환경에 토큰을 네트워크 시크릿으로 넣습니다. claude.ai/code 새 세션 화면 → 메시지 상자 아래 첫 번째 컨트롤(환경 선택) → Cloud 아래 환경 줄의 설정 아이콘 → Network secrets → Add secret: 종류 Bearer(또는 Token), 호스트 asia-northeast3-<프로젝트 ID>.cloudfunctions.net, 헤더 Authorization·접두어 Bearer·값은 1번 토큰. 에이전트 프록시가 그 호스트로 나가는 요청에만 헤더를 붙이므로 토큰이 세션 안(환경 변수·파일)에 들어가지 않고, 이 호스트는 네트워크 접근 수준과 상관없이 열립니다. 환경 변수(KEY=value)로 넣는 방법도 되지만 그 환경을 쓰는 모든 세션이 값을 읽을 수 있고 네트워크 허용도 따로 해야 합니다.

그로스 세션이 부를 때 ​

curl -s "https://asia-northeast3-grato-44d47.cloudfunctions.net/growthReport?days=7&include=events,activity"

네트워크 시크릿이 헤더를 붙이므로 세션은 Authorization을 직접 넣지 않습니다. 401이 오면 시크릿이 없거나 값이 틀린 것입니다. 지금은 클라우드 루틴 "Grato 그로스 리포트"가 매일 09:00(KST, 월요일은 30일 주간 보고) 이 주소를 읽고 Jira GRATO-124에 댓글로 보고합니다.

보고할 때 지킬 것:

  • 운영자 계정을 뺀 숫자로 말합니다. summary가 이미 뺀 값입니다. 사용자가 적을 때는 운영자(오너 본인)의 이벤트가 원시 목록의 대부분일 수 있습니다.
  • 원시 개수와 사람 수를 구분합니다. 예를 들어 writing_plan_shown은 홈을 열 때마다 한 번씩 남으므로, "몇 명이 봤는지"는 byEvent[…].people로 봅니다.
  • 작은 표본은 관찰로만 씁니다. 몇 명의 행동으로 결론을 내리지 않고 사람 수를 함께 적습니다.
  • 가명을 실제 사람과 이어 보려 하지 않습니다. 보고에는 가명 대신 "사람 A·B"처럼 써도 됩니다. 응답 원문을 다른 곳에 옮겨 두지 않습니다.
  • droppedPropKeys가 비어 있지 않으면 개발 세션에 알립니다.

토큰 바꾸기·끊기 ​

토큰이 새었거나 그로스 세션을 끊으려면 1번으로 새 값을 넣고 growthReport를 다시 배포합니다(함수는 배포할 때의 최신 비밀값을 씁니다). 이전 토큰은 바로 401이 되고, 가명도 모두 바뀝니다. 클라우드 환경의 네트워크 시크릿도 지우고 새 값으로 다시 넣습니다(시크릿은 고칠 수 없고 지운 뒤 다시 추가). 아예 막으려면 3번의 공개 호출 권한을 지웁니다(remove-iam-policy-binding).

비용 ​

  • events — 기간의 이벤트 수 + 그 사람들의 users 문서(필드 3개만). 지금 규모로는 하루에 수십–수백 개입니다.
  • activity — 약 170개(매일 밤 집계) + 최근 8주에 가입한 계정 수.
  • metrics — 사용자 전체 + 120일 글 + Circle·초대 코드·이벤트 일부. 가장 비쌉니다.
  • openCircle — 기간의 글 메타데이터·이벤트·신고.

함수는 동시에 하나만 돌고(maxInstances: 1) 캐시하지 않습니다. 그로스 세션이 하루 몇 번 부르는 정도를 전제로 합니다.
