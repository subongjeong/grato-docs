변경 이력 ​

사용자에게 보이는 변경과 운영에 영향을 주는 변경을 최신순으로 기록합니다.

2026-10-10 — App Store 심사 1.2 대응 (iOS 빌드 3으로 재제출, 웹 2026-10-10 배포) ​

첫 App Store 심사에서 가이드라인 1.2(사용자 생성 콘텐츠)로 반려됐습니다. 필요한 장치(약관 동의, 자동 필터, 신고, 차단, 24시간 처리)는 이미 있었고, 화면에서 더 분명히 보이게 했습니다.

  • 가입·동의 화면: "이용약관에 동의해요" 바로 아래에 무관용 원칙(불쾌하거나 해로운 콘텐츠와 괴롭힘 금지, 확인되면 삭제·이용 정지)을 보여 줌
  • 로그인 화면 아래: 만 14세 이상·약관 동의 후 이용, 무관용 원칙 한 줄
  • 차단 확인 창: "상대에게는 알리지 않고, 운영자에게는 검토를 위해 알려요"
  • 심사 회신: 실제 기기에서 약관 동의·신고·차단을 보여 주는 화면 녹화 → 심사 메모

2026-10-09 — 전체 기능 QA 수정 (2026-10-10 배포) ​

QA 계정으로 모든 기능을 점검하고 찾은 문제를 고쳤습니다. 웹과 앱에 함께 적용됩니다.

Circle·댓글 ​

  • 오류 문구 끝에 붙던 "[404]" 같은 숫자를 없앰
  • 초대 링크·코드 복사가 실패하면 그렇다고 알림(전에는 아무 반응 없음)
  • 한글 입력 중 Enter로 글자를 확정할 때 댓글이 반쯤 전송되던 문제
  • 로그인하지 않고 초대 링크를 열면 로그인 화면으로 바로 넘어가지 않고 Circle 이름·소개·멤버 수와 "로그인하고 참여하기"를 보여 줌
  • Circle 목록의 멤버 수·이름이 최신으로, 댓글은 새로고침 없이 바로 보임
  • 글을 보고 돌아오면 홈 피드의 스크롤 위치가 그대로
  • 피드 끝의 마지막 카드가 글쓰기 버튼에 가리지 않음, 긴 Circle 이름이 닫기 버튼과 겹치지 않음, 나간 Circle의 글은 "지난 Circle", 볼 권한이 없어진 글은 "찾을 수 없어요" 대신 "볼 수 없는 Grato예요"

개인 기록·계정 ​

  • 프로필 이름 저장이 연결이 불안정할 때 계속 돌던 문제: 8초 안에 끝나지 않으면 화면에 먼저 반영하고 "연결되면 자동으로 저장돼요"라고 알림
  • 직접 쓰던 글이 다른 화면에 다녀와도 남아 있음("작성 중인 글 이어 쓰기")
  • 없는 주소는 빈 화면 대신 "페이지를 찾을 수 없어요"
  • 로그인 화면의 안내 문구가 다른 화면에 다녀온 뒤 다시 뜨지 않음, 입력을 고치면 오류 문구가 사라짐, 브라우저 기본 검사 말풍선 대신 앱 문구
  • 공유 페이지: 공개를 취소하거나 글을 지우면 바로 사라짐(전에는 1분 캐시), 볼 수 없는 공유 글은 "삭제되었거나 공유가 취소되었을 수 있어요"
  • 캘린더 이미지: 지난달은 "최장 연속"(그 달 안), 이번 달은 "연속일". 공유 캘린더의 연속 기록은 "현재 연속 기록"으로 표시
  • 마이페이지 탭이 다른 화면에 다녀와도 유지, 안내 페이지(FAQ 등) 아래가 탭에 가리지 않고 뒤로 가기가 앱 밖으로 나가지 않음
  • 화면 읽기 프로그램: 아이콘 버튼에 이름, 알림 설정은 스위치, 바텀 시트는 대화상자로 읽힘

서버 ​

  • shareRenderer: 글·캘린더·배지 공유 페이지 캐시를 private, no-store로 (함수 shareRenderer와 Hosting만 배포, 규칙·인덱스 변경 없음) → shareRenderer

2026-10 — 3단계: iOS·Android 앱 (진행 중) ​

Capacitor로 iOS·Android 앱을 만들고 있습니다. 코드와 단위 테스트는 들어갔고, 실제 기기 확인·서버 배포·스토어 제출이 남았습니다. 웹사이트(grato.today)의 화면과 동작은 바뀌지 않습니다. → iOS·Android 앱, 로드맵 3단계

앱 ​

  • iOS·Android 앱 프로젝트 (cc.mknw.grato, Capacitor 8.5, iOS는 Swift Package Manager, Android target SDK 36). iPhone 세로 화면, 라이트 모드
  • Google·Apple 로그인을 휴대폰의 로그인 화면으로. 웹과 같은 계정(같은 uid)으로 로그인되고, 로그인 창을 닫으면 오류 없이 그대로. iPhone에서 Apple로 처음 가입하면 Apple이 알려 준 이름을 씀 → 결정 기록 #17
  • 계정 삭제의 본인 확인도 같은 로그인 화면. Apple 연결 해제 포함
  • 푸시 알림: Circle 새 글, 공감, 질문 선정, (운영자) 신고. 앱을 열어 둔 동안에도 표시되고 누르면 그 화면으로. 알림 권한은 버튼을 눌렀을 때만 물음
  • 매일 감사 알림을 휴대폰이 직접: 고른 시각(15분 단위)에 인터넷 없이도 오고, 그날 이미 기록했으면 쉼. 앱이 알림을 맡는 동안 서버 알림은 보내지 않아 하루 한 번 → 결정 기록 #16
  • 초대·공유 링크로 앱 열기 (Universal Links / App Links). 앱 안의 grato.today 링크는 그 화면으로, 다른 사이트는 앱 안 브라우저로
  • 공유는 휴대폰 공유 시트로, 캘린더 이미지는 공유 시트에서 사진에 저장 가능. 공유·초대 링크는 항상 https://grato.today 주소
  • 노치·홈 인디케이터를 피하는 화면, 상태 표시줄, 스플래시, 키보드가 올라오면 아래 탭 숨김, Android 뒤로 가기(열린 시트 닫기 → 이전 화면 → 첫 화면에서 앱 나가기)
  • 앱에서는 PWA 설치 배너와 "앱 내 브라우저" 경고를 보이지 않음
  • 개발: npm run dev가 로컬 Firebase 에뮬레이터(가짜 프로젝트)에서 돌아 실제 서비스에 닿지 않음. 실제 프로젝트용 개발 서버는 npm run dev:prod → 결정 기록 #19
  • 고침: iPhone 위젯이 로그인 상태인데도 "로그인하고 감사 기록을 시작해요"로 남던 문제, Circle을 만들면 목록에 같은 Circle이 두 번 보이던 문제
  • 웹사이트(grato.today) 반영: 아래 디자인·사진·초대 변경은 2026-10-09 Hosting과 shareRenderer 배포로 웹에도 적용됨
  • 초대가 쉬워짐: 카카오톡·LINE에서 초대 링크를 열면 휴대폰 브라우저(앱이 있으면 앱)로 바로 넘어가 로그인이 막히지 않음, Circle을 만들면 곧바로 초대하기 카드, 초대 메시지에 초대 코드 포함
  • 앱: 연속 7일·30일을 기록한 날 스토어 평점 요청(120일에 한 번까지)
  • 프로필·Circle 사진이 빨리 뜸: 올릴 때 512px로 줄여 수 MB → 수십 KB, 1년 캐시를 붙여 한 번 받은 사진은 기기에서 바로. 사진 파일은 10MB까지 고를 수 있음(웹에도 적용)
  • 화면이 흐릿하던 느낌을 정리: 카드에 따뜻한 테두리와 그림자, 카드 안 크림색 칸은 연회색, 옅은 회색 글씨는 한 단계 진하게(웹에도 적용)
  • 앱 상단의 "Grato" 글자를 로고 글자로, 모든 화면 상단은 새싹 마크 + 제목(본문과 같은 고딕 굵게; 잠시 함렛 세리프를 썼다가 되돌림). 프로필·Circle 사진은 이름 첫 글자를 먼저 보여 주고 사진이 받아지면 부드럽게 바뀜(빈칸에서 갑자기 나타나지 않음, 사진 서버에 미리 연결)
  • 새 아이콘과 로고: 한 줄기에서 돋은 두 잎(새싹) 마크와 Fraunces 이탤릭 로고 글자. 홈 상단은 마크와 로고 글자를 나란히. 앱 아이콘·스플래시·로그인 화면·알림 아이콘·위젯·웹 파비콘에 적용하고, 링크를 공유하면 로고가 든 큰 미리보기 이미지가 나옴(웹에도 적용) → 아이콘과 브랜드
  • 홈 화면 위젯 (iOS·Android, iOS 잠금 화면 포함): 연속일, 오늘 기록 여부, 이번 주 기록, 오늘의 질문. 누르면 글쓰기, 질문을 누르면 그 질문으로 "질문으로 쓰기". 감사 글 내용은 나오지 않음 → 위젯, 결정 기록 #18
  • iPhone: 화면 왼쪽 가장자리에서 밀어 뒤로 가기(다른 iPhone 앱과 같은 제스처). 링크를 길게 눌러도 미리보기가 뜨지 않음
  • 캘린더 이미지 저장(웹·앱): 날짜 숫자가 동그라미 아래로 쏠리던 문제를 고침. 화면을 캡처하지 않고 직접 그려 항상 가로 1080px로 선명하게 저장

서버·운영 (2026-10-09 배포) ​

  • sendToUser가 토큰의 platform에 따라 메시지 모양을 고름: 웹은 데이터 전용 그대로, 앱은 notification 페이로드 → 알림: 메시지 모양
  • sendDailyReminder가 앱이 로컬 알림을 맡은 사용자(notificationSettings.dailyReminderChannel == 'local', 14일 안)를 건너뜀
  • Hosting: /.well-known/apple-app-site-association, /.well-known/assetlinks.json과 헤더, appAssociation: "NONE"
  • 앱 빌드를 배포하기 전에 함수와 Hosting을 먼저 올리고, iOS 푸시용 APNs 키를 Firebase에 등록해야 함 → 서버·Hosting 먼저 배포, APNs 키 (2026-10-09 완료)
  • 웹 Apple 로그인 복구: 2단계 배포 뒤 웹의 "Apple로 계속하기"가 "지금은 이 방법으로 로그인할 수 없어요"로 실패했음. Firebase Apple 공급업체의 OAuth 코드 흐름 구성(Team ID·Key ID·비공개 키)이 빠져 있었고, 웹·Android에는 필수였음. 콘솔 설정으로 해결(코드 변경 없음) → Apple 로그인 설정
  • 기반 작업: Firebase JS SDK 10 → 12 (Capacitor 인증 플러그인 요구), Firebase에 iOS·Android 앱 등록

2026-10-08 — 매일 알림 15분 단위 (배포 완료) ​

  • 매일 알림 시간을 15분 단위로 고를 수 있음(예: 오후 8시 15분). 서버가 15분마다 그 시각을 고른 사람에게 보냄
  • 예전에 시 단위로 고른 설정은 그 시 정각에 그대로 감
  • 앱(3단계)에서는 휴대폰 자체 알림으로 고른 시각에 정확히 띄울 예정 → 결정 기록 #16

2026-10-08 — 2단계: 스토어 필수 기능 (배포 완료) ​

앱 스토어 출시에 필요한 기능입니다. 약관·개인정보 처리방침은 2026년 10월 8일부터 시행하며, 기존 사용자는 다음 접속 때 동의 화면을 거칩니다. Apple 로그인은 Apple 개발자 콘솔과 Firebase 콘솔 설정을 마친 뒤 동작합니다. 매일 알림이 정각이 아니라 매시 40분에 가던 문제도 함께 고쳤습니다(스케줄 0 * * * *). → 이번 릴리스 배포

로그인과 가입 ​

  • Apple로 로그인 추가. "Google로 계속하기"와 같은 크기로 나란히 표시. "이메일 가리기" 주소도 사용 가능 → 계정
  • Apple로 가입하면 이름이 없어 홈에 "이름을 알려주세요" 카드를 보여 줌
  • 가입할 때 약관 동의와 만 14세 이상 확인. 이메일 가입 폼에 체크리스트, Google·Apple은 로그인 뒤 동의 화면. 기존 사용자도 다음에 열 때 한 번 동의함 → 약관 동의
  • 만 14세 미만이라고 답하면 계정을 지우고 로그아웃
  • 이용 정지된 계정, 다른 방법으로 이미 가입한 이메일에 대한 안내 문구

계정 삭제 ​

  • MyPage › 설정 › 계정 삭제. 지워지는 것과 남는 것을 먼저 보여 주고, "계정 삭제"를 입력한 뒤 본인 확인(재로그인)을 거쳐 삭제 → 계정 삭제, 결정 기록 #15
  • 관리하던 Circle은 가장 오래 함께한 멤버에게 넘어가고, 혼자 있던 Circle은 삭제
  • Apple 사용자는 Apple 계정과의 연결도 해제
  • 로그인 없이 볼 수 있는 계정 삭제 안내 페이지(/account-deletion)와 이메일 요청 방법

신고·차단 ​

  • 글·댓글의 "⋯" 메뉴에서 신고하기(사유 7가지, 자세한 내용 선택)와 차단하기. Circle 멤버와 Circle도 신고 가능 → 신고·차단과 자동 숨김, 결정 기록 #14
  • 차단하면 그 사람의 글·댓글이 보이지 않고 그 사람 때문에 오는 알림도 오지 않음. MyPage › 설정 › 차단한 사용자에서 해제
  • 공개 공유 페이지에 로그인 없이 쓸 수 있는 "신고하기"(이메일)
  • 욕설·혐오 표현이 든 Circle 글·공개 글·댓글은 자동으로 숨기고 운영자가 확인. 작성자에게는 "검토 중이에요"로 보임
  • 부적절한 Circle 이름은 만들 때 거절, 공개 이름·Circle 이름 변경은 운영자가 확인

글 ​

  • 내 감사 글 삭제. 달린 댓글도 함께 지워지고, 연속일·이번 달 기록 수는 남은 글로 다시 계산. 받은 배지는 유지 → 감사 글: 삭제
  • Circle에 공유하거나 링크로 공개하기 전에 민감한 내용(건강·종교 등)을 한 번 더 확인하라는 안내
  • 확인 창을 앱 안의 대화상자로 바꿈(글·댓글 삭제, Circle 설정의 내보내기·탈퇴·삭제 등)

운영 ​

  • 관리자 페이지 첫 탭 신고: 처리 대기·스팸 의심 목록, 대상 미리보기, 숨기기·숨김 해제·삭제·이용 정지·문제 없음. 새 신고는 운영자 기기로 푸시(24시간 안 처리)
  • 새 callable moderate, deleteAccount. 새 트리거 onGratitudeDeleted, onReportCreated, onBlockCreated, onPublicNameWritten, onCircleNameWritten. 글·댓글 생성 트리거에 자동 숨김, 알림에 차단 반영
  • 새 컬렉션 reports, users/{uid}/blocks, disabledUsers와 규칙·인덱스·TTL. 글·댓글 생성에 약관 동의 확인, 작성자의 글 삭제 허용
  • 약관·개인정보 처리방침 전면 개정, 고객지원 페이지(/support). 약관 시행일 등이 비어 있으면 Hosting 배포를 막는 검사
  • 함수 엔드투엔드 테스트(npm run test:e2e, 에뮬레이터) 추가 → 테스트

2026-10-08 — 로딩 속도 개선 (배포 완료) ​

로그인과 페이지 이동이 느리다는 문제를 측정한 뒤 고쳤습니다. 수치는 클라이언트 › 성능에 있습니다.

  • 앱이 바로 뜸: 로그인 확인이 끝나면 곧바로 화면을 그림. 예전에는 프로필 동기화(서버 왕복 6~7번)가 끝날 때까지 "잠시만요..." 화면이었음
  • 프로필은 로컬 캐시에서 즉시 표시되고, 동기화는 화면이 뜬 뒤 뒤에서 처리(바뀐 것이 없으면 쓰기 없음)
  • 기기에 데이터 캐시: 다시 열 때 최근 데이터가 바로 보임. 로그아웃하면 이 기기의 캐시를 지움(공용 기기 보호)
  • 페이지별로 코드를 나눠 받음. 첫 화면 앱 코드 57KB → 30KB(gzip). 로그인 후 쓸 페이지는 잠시 뒤 미리 받아 둠
  • 휴대폰·Safari에서 매번 받던 구글 로그인 준비 파일을 시작 경로에서 제외. 데스크톱은 구글 버튼에 마우스를 올릴 때 준비
  • 글꼴이 첫 화면을 막지 않음. 소개 페이지 주소 끝 / 리다이렉트 제거
  • 마이페이지: 목록 20개씩, 캘린더는 보고 있는 달만(KST 기준)
  • 배포 직후 열려 있던 탭은 새 버전으로 한 번 자동 새로고침. 오프라인이면 앱 안에서 안내하고 연결되면 다시 불러옴

2026-10-08 — 질문 제안·선정, 개인 기록 기본값 (배포 완료) ​

배포 순서가 바뀌었습니다: 함수·규칙·인덱스 → 인덱스 완료 확인 → 기본 질문 시드(seedQuestions) → Hosting. → 배포 순서, 이번 릴리스

작성과 홈 ​

  • 새 감사 글은 기본이 "나만 보기". 작성 화면의 "누가 볼 수 있나요?"에서 "Circle에 공유"와 Circle을 직접 골라야 공유됨 (Circle을 미리 선택하지 않음). 저장 버튼도 "저장하기" / "Circle에 공유하기"로 구분 → 결정 기록 #12
  • 홈 피드 첫 탭에 "내 기록"(기본 탭, Circle이 없어도 있음). 내 글을 실시간으로 보여 주고 "더 보기"로 이어서 읽음
  • 내 기록과 MyPage 글 목록의 카드에 "나만 보기" / "링크 공개" / Circle 이름 표시
  • Circle이 없으면 내 기록과 함께 Circle 만들기·참여 안내 카드 표시 (예전에는 안내만 보였음)
  • 피드를 불러오지 못하면 "기록이 없어요" 대신 오류와 "다시 시도"를 보여 줌
  • "함께하기" 배지를 Circle을 만들거나 참여할 때 받음 (글을 Circle에 공유하지 않아도)

질문 제안·선정 ​

  • 질문으로 쓰기는 운영자가 선정한 질문을 사용 (기본 질문 40개 + 선정된 사용자 질문). 읽지 못하면 앱 안의 기본 질문으로 대신함. 사용자가 제안해 선정된 질문에는 "💡 이름 #태그님의 질문" 표시 → 결정 기록 #11
  • "질문 제안하기"(질문으로 쓰기 화면, MyPage). 하루 5개, 내용 필터(욕설·연락처), 중복 확인. 선정되면 공개 이름이 함께 표시된다는 안내 → 질문 제안과 선정
  • MyPage "내가 제안한 질문": 검토 중 / 선정됨 / 반려됨(사유) / 숨김
  • 처음 선정되면 알림("제안한 질문이 선정됐어요 🎉"), 선정 수에 따라 배지 3종(첫 질문 선정, 질문 큐레이터, 질문 장인)
  • 관리자 페이지 "질문" 탭: 상태별 개수, 검토 대기열(오래된 순), 선정(문구·종류 수정 가능)·반려(사유)·숨김·다시 선정. 배지 조건에 "선정된 질문 수" 추가

운영 ​

  • 새 callable submitQuestion, reviewQuestion. 새 컬렉션 questions, questionOriginals, questionQuota(TTL), adminAuditLogs(운영자 작업 기록)와 규칙·인덱스
  • 기본 질문 원본을 src/content/questions.json으로 옮기고, seedQuestions 스크립트로 Firestore에 넣음
  • 재사용 가능한 내용 필터(utils/contentFilter.ts)

2026-10-07 — 1단계: 보안·안정화 (배포 완료) ​

2026-10-07에 프로덕션에 배포했습니다. 클라이언트·함수·규칙을 함께 배포했고, 이때만 필요한 1회성 작업도 함께 했습니다. → 1회성 작업

Circle ​

  • Circle 생성·참여·탈퇴·멤버 내보내기·삭제·초대 코드 재발급을 서버 함수(callable)로 이전
  • 새 초대 코드는 8자리(헷갈리는 0 O 1 I 제외), 30일 유효, 50회 사용. 기존 6자리 코드도 계속 사용 가능
  • Circle당 최대 50명, 사용자당 최대 20개 Circle
  • 내보낸 멤버는 관리자가 다시 허용하기 전까지 초대 코드로 재참여 불가. Circle 설정에 "내보낸 멤버" 목록과 "다시 허용" 추가
  • 이미 참여 중인 Circle의 초대 링크를 열면 "이미 참여 중이에요"로 안내
  • 삭제되었거나 더 이상 속하지 않은 Circle은 목록에서 자동 정리
  • 오류 메시지를 상황별 한국어 문구로 통일

프로필 ​

  • 공개 이름(이름 #태그)을 전역에서 유일하게 관리. 같은 이름·태그는 한 사람만 사용

공유 ​

  • 외부 공유는 작성자가 공개를 선택한 경우에만 내용 표시 (감사 글, 캘린더 월, 배지)
  • 공개 전 확인 창, 공개 취소 기능. 공유 페이지 캐시를 줄여 1분 안에 반영
  • 비공개·없는 페이지는 검색엔진 색인 제외(noindex)
  • 공유 페이지가 항상 최신 앱 화면을 쓰도록 템플릿을 Hosting에서 받아옴

기록과 배지 ​

  • 연속일·이번 달 기록 수를 서버에서 한국 시간(KST) 기준으로 계산, 중복 집계 방지
  • 연속일은 오늘이나 어제 기록했을 때만 표시. 글을 쓴 직후 바로 반영되어 보이도록 개선
  • 댓글 수를 서버에서 관리
  • 배지 평가를 글 작성 처리 흐름(통계 → 배지 → 알림)에 통합. 감사 글을 공개하면 '공개한 감사 수' 배지 평가

알림 ​

  • 매일 알림은 그날 이미 감사를 기록한 사용자에게 보내지 않음
  • 알림 권한은 사용자가 "알림 받기"를 눌렀을 때만 요청. 홈에 닫을 수 있는 알림 안내 카드 추가

작성 ​

  • AI 질문 모드를 없애고 "질문으로 쓰기"로 바꿈. 앱에 들어 있는 질문에 1~2개 답하면(두 번째 질문은 건너뛰기 가능) 답변으로 초안을 만들고, 제목을 붙여 다듬은 뒤 저장. 질문이 마음에 들지 않으면 "다른 질문"으로 바꾸기. 작성 내용은 외부 AI 서비스로 보내지 않음
  • 서버 함수 generateQuestion·generateGratitude를 없애고, 기존 AI 작성 기록(aiSessions, aiUsage, aiCache)은 정리 스크립트로 삭제

운영 ​

  • Cloud Functions 런타임 Node 22, 모든 함수 서울 리전(asia-northeast3)
  • 서버 로그 컬렉션에 TTL 적용
  • 보안 규칙 테스트(에뮬레이터), 함수·클라이언트 단위 테스트 추가
  • 개발 문서 사이트 공개
