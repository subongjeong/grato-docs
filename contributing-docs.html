문서 작성 규칙 ​

이 문서 사이트는 비공개 저장소 subongjeong/Grato의 docs/ 폴더에서 만들어져, main에 반영될 때마다 공개 저장소 subongjeong/grato-docs의 GitHub Pages로 자동 배포됩니다.

언제 업데이트하나요 ​

코드를 바꿀 때 같은 커밋(또는 같은 PR)에서 관련 문서도 함께 고칩니다. 특히 아래가 바뀌면 반드시 갱신합니다.

  • Firestore 데이터 모델(컬렉션, 필드)
  • 보안 규칙(firestore.rules, storage.rules)
  • Cloud Functions(이름, 입력·출력, 트리거)
  • 배포 절차, 환경 변수, 비밀값의 이름
  • 모바일 앱 빌드·출시 절차
  • 주요 결정 → 결정 기록에 추가
  • 사용자에게 보이는 변경 → 변경 이력 조각 파일 하나 추가 (변경 이력 쓰기)

변경 이력 쓰기 ​

docs/changelog.md를 직접 고치지 않습니다. PR마다 조각 파일 하나를 docs/changelog/unreleased/<티켓>.md로 만듭니다(예: GRATO-80.md). 열린 PR끼리 같은 줄을 고치지 않아 충돌하지 않습니다. → ADR-36

md
## 무엇이 바뀌었는지 짧게 {#ascii-id}

- 사용자에게 보이는 변경, 운영에 영향을 주는 변경
- 필요한 배포(함수·규칙·Hosting·앱 빌드) → [관련 문서](/features/notifications#ios-web)
  • 첫 줄은 ## 제목 {#ascii-id} 하나. 날짜와 "(배포 전)"은 쓰지 않습니다(합칠 때 날짜가 붙음). 파일 하나에 ## 항목 하나.
  • id는 changelog.md와 다른 조각에서 쓰지 않은 것. 파일 이름은 영문·숫자·-(티켓 키).
  • 같은 PR에서 내용을 바꾸면 그 파일만 고칩니다. 티켓 하나가 PR 여러 개면 GRATO-80-2.md처럼 나눕니다.
  • 문서 사이트는 조각을 변경 이력 맨 위 "아직 합치지 않은 변경"에 보여 줍니다. 조각 링크는 문서 빌드가 검사하지 않으므로 node scripts/mergeChangelog.mjs --check가 형식·중복 id·링크한 페이지가 있는지를 봅니다(CI 문서 job에서도 돔).
  • 배포할 때 합치기 (PO 또는 배포하는 사람): main에서 새 브랜치를 만들어 npm run changelog(날짜는 오늘 KST, 다른 날은 -- --date 2026-10-24) → 조각이 날짜를 달고 changelog.md의 <!-- changelog:merge-here --> 아래로 옮겨지고 파일은 지워짐 → PR. 미리 보려면 npm run changelog -- --dry-run.
  • 2026-10-17 전에 열린 PR은 changelog.md 맨 위에 직접 쓴 채로 둡니다(병합 때 PO가 정리).

공개 문서이므로 쓰지 않는 것 ​

이 사이트는 누구나 볼 수 있습니다. 다음은 절대 적지 않습니다.

  • API 키, 비밀값, 토큰의 값 (이름만 적기)
  • 관리자 계정, 실제 사용자 정보, uid
  • 아직 프로덕션에 배포되지 않은 보안 문제의 세부 내용
  • 내부 대시보드 주소, 개인 연락처

한글 제목에 링크할 때 ​

VitePress가 한글 제목에서 자동으로 만드는 앵커는 손으로 쓴 링크와 맞지 않아, 링크가 조용히 깨집니다. 다른 페이지에서 링크하는 제목에는 ASCII id를 직접 붙입니다.
