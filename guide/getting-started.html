설치 ​

이 저장소에는 package.json이 네 개 있습니다. 각각 따로 설치합니다.

bash
npm install                      # 루트: React 앱
cd functions && npm install      # Cloud Functions
cd ../tests/rules && npm install # 보안 규칙 테스트
cd ../../docs && npm install     # 문서 사이트

환경 변수 (.env) ​

bash
cp .env.example .env

Firebase 콘솔의 프로젝트 설정에서 값을 채웁니다. .env는 커밋하지 않습니다.

변수내용
VITE_FIREBASE_API_KEY웹 앱 설정
VITE_FIREBASE_AUTH_DOMAIN로그인 도메인 (커스텀 도메인 사용)
VITE_FIREBASE_PROJECT_ID프로젝트 ID
VITE_FIREBASE_STORAGE_BUCKETStorage 버킷
VITE_FIREBASE_MESSAGING_SENDER_IDFCM 발신자 ID
VITE_FIREBASE_APP_ID웹 앱 ID
VITE_FIREBASE_VAPID_KEYFCM 웹 푸시 인증서(VAPID) 공개 키

개발 서버 ​

bash
npm run dev        # 에뮬레이터 + 앱: http://localhost:5173, 에뮬레이터 UI http://127.0.0.1:4000
npm run dev:prod   # 실제 Firebase 프로젝트(.env)에 붙는 개발 서버 — 꼭 필요할 때만

npm run dev는 실제 서비스에 닿지 않습니다(scripts/dev.mjs).

  1. 함수를 빌드하고, Firebase 에뮬레이터(Auth 9099, Firestore 8080, Functions 5001, Storage 9199)를 가짜 프로젝트 demo-grato로 띄웁니다. demo- 프로젝트는 Google 서버로 요청을 보내지 않습니다.
  2. 선정된 기본 질문과 배지를 넣습니다(scripts/seedEmulator.mjs → seedQuestions).
  3. 앱을 에뮬레이터 모드(vite --mode emulator, .env.emulator)로 띄웁니다. src/lib/firebase.js의 useEmulators가 Auth·Firestore·Functions·Storage를 에뮬레이터에 연결하고, 푸시(FCM)는 끕니다.
  4. 가입은 아무 이메일로 하면 됩니다. 만든 계정·데이터는 .emulator-data/(Git 제외)에 저장되어 다음 실행에도 남습니다. 지우려면 그 폴더를 삭제합니다.
  • Firestore 에뮬레이터에 JDK 21이 필요합니다(JAVA_HOME이 없으면 Homebrew openjdk@21을 씁니다).
  • 운영 빌드(npm run build)는 에뮬레이터 설정이 섞이면 실패합니다(vite.config.js). 운영 코드에는 에뮬레이터 연결이 남지 않습니다.
  • QA와 스토어 스크린샷도 이 에뮬레이터에서 합니다(resources/store-tools). 실제 서비스에서 확인할 일이 있으면 QA 전용 계정만 씁니다.

npm run dev:prod는 실제 서비스입니다

.env의 운영 프로젝트(Auth·Firestore·Functions)를 그대로 씁니다. 데이터를 지우거나 대량으로 만드는 실험은 npm run dev에서 하세요.

Cloud Functions 빌드 ​

bash
npm run build                    # 루트: dist/ 생성 (+ prerender)
cd functions && npm run build    # tsc → lib/, dist/index.html을 공유 페이지 템플릿으로 복사

함수 빌드는 dist/index.html을 functions/lib/share/share-template.html로 복사합니다. shareRenderer가 Hosting에서 최신 템플릿을 받지 못할 때 쓰는 예비본이므로, 루트 빌드를 먼저 하세요.

에뮬레이터 ​

루트 firebase.json에는 에뮬레이터 포트 설정이 없어 기본 포트를 씁니다. 실제 리소스를 건드리지 않도록 demo- 접두사 프로젝트로 띄우는 것을 권장합니다.

bash
cd functions && npm run build && cd ..
firebase emulators:start --project demo-grato --only auth,firestore,functions,storage
  • demo-* 프로젝트는 에뮬레이터 전용이라 실수로 운영 데이터에 접근할 수 없습니다.
  • 함수 에뮬레이터만 단독으로 띄우면(functions 폴더의 npm run serve) Admin SDK가 실제 프로젝트의 Firestore에 접근할 수 있으니 Firestore 에뮬레이터와 함께 띄우세요.
  • 에뮬레이터의 shareRenderer는 운영 Hosting 대신 빌드에 포함된 템플릿을 씁니다.

에뮬레이터를 이용한 엔드투엔드 확인 방법은 테스트를 보세요.

JDK 21 설정 (규칙 테스트) ​

Firebase 에뮬레이터는 JDK 21 이상이 필요합니다. macOS + Homebrew 예시:

bash
brew install openjdk@21
export JAVA_HOME="$(brew --prefix openjdk@21)/libexec/openjdk.jdk/Contents/Home"
export PATH="$JAVA_HOME/bin:$PATH"
java -version   # 21.x 확인

셸 설정 파일(~/.zshrc 등)에 JAVA_HOME을 넣어 두면 편합니다.
