Circle ​

Circle은 감사를 함께 나누는 소규모 비공개 그룹입니다. 공개 목록이나 검색은 없고 초대 코드로만 참여합니다. 사용자는 여러 Circle에 참여할 수 있습니다. 글은 기본이 "나만 보기"이고, 글을 쓸 때 "Circle에 공유"와 Circle을 직접 고른 경우에만 그 Circle에 보입니다. → 공개 범위

멤버십 변경(생성·참여·탈퇴·내보내기·삭제·초대 코드)은 모두 callable 함수가 처리합니다. 클라이언트는 그룹의 이름·설명·사진만 직접 고칠 수 있고, 그것도 관리자만 가능합니다. → 결정 기록 #3

한도 ​

항목값확인 위치
사용자당 참여 Circle20개createCircle, joinCircle
Circle당 멤버50명joinCircle
초대 코드 유효 기간발급 후 30일joinCircle
초대 코드 사용 횟수50회joinCircle
Circle 이름1~30자함수, 규칙(관리자 수정)
Circle 설명100자 이하함수, 규칙(관리자 수정)
Circle 사진이미지, 5MB 미만, 관리자만Storage 규칙

Circle 수를 셀 때는 users.groupIds를 그대로 믿지 않고, 함수가 각 그룹 문서를 읽어 실제로 멤버인 Circle만 셉니다. 삭제된 Circle이나 내보내진 Circle의 ID가 남아 있어도 한도에 걸리지 않고, 그 자리에서 정리됩니다.

역할 ​

역할할 수 있는 일
관리자 (adminId, 생성자)이름·설명·사진 수정, 초대 코드 재발급, 멤버 내보내기·다시 허용, Circle 삭제. 탈퇴는 불가
멤버글 읽기·쓰기, 리액션, 댓글, 탈퇴

관리자 위임 기능은 아직 없습니다. 다만 관리자가 계정을 삭제하면 가장 오래 함께한 멤버(memberIds의 참여 순서)가 자동으로 관리자가 되고, 혼자였다면 Circle이 삭제됩니다.

멤버는 Circle 설정의 멤버 목록에서 다른 멤버를 신고·차단할 수 있고, 관리자가 아닌 멤버는 "Circle 신고하기"로 Circle 자체를 신고할 수 있습니다. 차단은 내 화면만 바꾸고 멤버십은 그대로입니다. → 신고·차단

생성 ​

createCircle({name, description}) → {groupId, inviteCode}

한 트랜잭션에서 그룹 문서(memberIds: [나], adminId: 나, plan: "free"), 초대 코드 문서, 내 groupIds를 함께 만듭니다. 초대 코드가 이미 쓰이고 있으면 최대 5번까지 다시 뽑습니다. 이름·설명에 욕설·혐오 표현이 있으면 "Circle 이름이나 설명에 쓸 수 없는 표현이 있어요"로 거절합니다.

초대 코드 ​

새 코드예전 코드
형식8자리, ABCDEFGHJKLMNPQRSTUVWXYZ23456789 (헷갈리는 0 O 1 I 제외)대부분 6자리 영숫자
생성crypto.randomInt (암호학적 난수, 편향 없음)-
만료·사용 횟수30일, 50회필드가 없으면 무제한
  • 입력은 앞뒤 공백 제거 후 대문자로 바꿉니다(normalizeInviteCode). 영숫자 1~16자가 아니면 "초대 코드를 찾을 수 없어요"입니다.
  • 초대 링크는 https://grato.today/invite/{코드} 형식입니다. 링크 미리보기(Circle 이름, 인원)는 shareRenderer가 만듭니다.
  • 클라이언트는 아는 코드 하나만 조회할 수 있고 코드 목록은 볼 수 없습니다.

참여 ​

  • 이미 멤버면 오류가 아니라 alreadyMember: true이고 사용 횟수를 차감하지 않습니다.
  • 검사 순서: 코드 존재 → Circle 존재 → 이미 멤버 → 내보낸 사용자 → 만료 → 사용 횟수 → 정원 → 내 Circle 수.
  • 신규 사용자는 클라이언트가 users/{uid}를 먼저 만들도록 profileReady를 기다린 뒤 참여합니다.
  • 인앱 브라우저(카카오톡 등)에서는 Google 로그인이 막힙니다. 카카오톡·LINE에서 초대 링크를 열면 초대 페이지가 한 번 자동으로 휴대폰 브라우저에 넘깁니다(카카오톡 kakaotalk://web/openExternal, LINE openExternalBrowser=1). 앱이 설치된 휴대폰이면 이때 Universal Link·App Link로 앱의 초대 화면이 열립니다. 넘기지 못하면(다른 인앱 브라우저, 세션당 한 번 시도 뒤) 브라우저 열기·링크 복사 안내를 보여 줍니다. src/lib/inAppBrowser.js의 externalBrowserUrl.
  • 초대 메시지(inviteMessage)에는 링크와 함께 초대 코드가 들어 있어, 앱에서 "Circle 참여하기"에 코드를 넣어도 됩니다.
  • Circle을 만들면 바로 "초대하기" 카드(공유 시트, 카카오톡 포함)가 나옵니다. 혼자인 Circle은 쓰이지 않아서입니다.

오류 메시지 전체는 Cloud Functions에 있습니다.

탈퇴 ​

leaveCircle({groupId}) — 내 uid를 memberIds에서, Circle을 내 groupIds에서 뺍니다. 관리자는 탈퇴할 수 없습니다(먼저 Circle을 삭제해야 함).

Circle이 이미 없거나 내가 멤버가 아니면 groupIds만 정리하고 성공합니다. 클라이언트는 이것을 이용해 삭제가 확인된 Circle의 오래된 ID를 서버에서도 지웁니다.

멤버 내보내기와 다시 허용 ​

함수동작
removeCircleMember({groupId, memberId})memberIds에서 제거, removedIds에 추가, 그 사람의 groupIds에서 제거
unbanCircleMember({groupId, memberId})removedIds에서 제거
  • 내보낸 사람은 이미 알고 있는 초대 코드로 다시 들어올 수 없습니다. "이 Circle에서 내보내져 다시 참여할 수 없어요. Circle 관리자에게 문의해주세요" 오류를 받습니다.
  • 관리자는 Circle 설정의 "내보낸 멤버" 목록에서 다시 허용할 수 있습니다. 다시 허용해도 자동으로 멤버가 되지는 않고, 초대 코드로 다시 참여해야 합니다.
  • 초대 코드를 바꾸지 않아도 차단이 유지되므로, 한 사람을 내보내려고 모든 멤버에게 새 코드를 나눠 줄 필요가 없습니다.
  • 내보내진 사람이 그 Circle에 쓴 글은 작성자 본인에게 계속 보입니다. 그 사람은 더 이상 Circle 피드를 읽거나 새 글을 올릴 수 없습니다.

Circle 삭제 ​

deleteCircle({groupId}) — 관리자만 가능합니다.

  1. 모든 멤버의 users.groupIds에서 이 Circle 제거 (없는 사용자 문서는 건너뜀)
  2. 이 Circle을 가리키는 초대 코드 전부 삭제
  3. 그룹 문서 삭제 (마지막)
  4. Circle 사진(circlePhotos/{groupId}/) 삭제 (실패해도 로그만)

운영자가 신고된 Circle을 지울 때(moderate)도 같은 처리를 씁니다. 500개 단위 배치로 나눠 커밋합니다. 그룹 문서를 마지막에 지우므로 중간에 실패해도 다시 호출하면 이어서 정리됩니다.

감사 글은 지우지 않습니다. 그룹 문서가 사라지면 다른 멤버는 그 글을 읽을 수 없게 되지만, 작성자는 자기 글을 개인 기록으로 계속 봅니다. → 결정 기록 #4

초대 코드 재발급 ​

regenerateInviteCode({groupId}) → {inviteCode} — 관리자만. 기존 코드 문서를 모두 지우고 새 코드를 만든 뒤 groups.inviteCode를 바꿉니다. 한 트랜잭션이라 중간 상태가 없습니다. 기존 링크·코드는 즉시 쓸 수 없게 됩니다.

Circle 정보 수정 ​

관리자는 Firestore에 직접 name(1~30자), description(100자 이하), photoURL만 수정할 수 있습니다. 이름·설명을 바꾸면 서버가 내용 필터로 검사해, 걸리면 그대로 두고 운영자에게 알립니다(onCircleNameWritten). 사진은 Storage circlePhotos/{groupId}/에 올리며, Storage 규칙이 Firestore의 adminId를 교차 확인합니다. → 보안 규칙

피드 ​

  • Circle별로 최신 20개를 실시간 구독하고, "더 보기"는 커서(startAfter) 기반으로 20개씩 읽습니다.
  • 여러 Circle을 한 번에 합친 피드는 지원하지 않습니다. 규칙의 교차 읽기 한도 때문에 Circle마다 쿼리를 따로 보냅니다. → 보안 규칙
  • 홈의 "오늘의 Circle 활동"은 최대 10개 Circle에 대해 오늘(KST) 글 수와 리액션 수를 병렬로 집계합니다.
  • 구독 중 권한이 사라지면(내보내짐 등) 빈 피드로 처리해 로딩이 끝나지 않는 일을 막습니다.
