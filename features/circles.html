Circle ​

Circle은 감사를 함께 나누는 소규모 비공개 그룹입니다. 공개 목록이나 검색은 없고 초대 코드로만 참여합니다. 사용자는 여러 Circle에 참여할 수 있습니다. 글은 기본이 "나만 보기"이고, 글을 쓸 때 "Circle에 공유"와 Circle을 직접 고른 경우에만 그 Circle에 보입니다. → 공개 범위

모임 리더를 위한 공개 안내 페이지는 grato.today/circle-guide입니다(SEO_PAGES['circle-guide'], 미리 렌더링). → Circle 가이드 페이지

멤버십 변경(생성·참여·탈퇴·내보내기·삭제·초대 코드)은 모두 callable 함수가 처리합니다. 클라이언트는 그룹의 이름·설명·사진만 직접 고칠 수 있고, 그것도 관리자만 가능합니다. → 결정 기록 #3

예외로, 운영자가 여는 Circle 하나 "모두의 감사방"은 초대 코드 없이 원하는 사람이 별명으로 참여합니다. 처음에는 꺼져 있습니다. → 모두의 감사방

역할 ​

역할할 수 있는 일
관리자 (adminId, 생성자)이름·설명·사진 수정, 초대 코드 재발급, 멤버 내보내기·다시 허용, Circle 삭제. 탈퇴는 불가
멤버글 읽기·쓰기, 리액션, 댓글, 탈퇴

관리자 위임 기능은 아직 없습니다. 다만 관리자가 계정을 삭제하면 가장 오래 함께한 멤버(memberIds의 참여 순서)가 자동으로 관리자가 되고, 혼자였다면 Circle이 삭제됩니다.

멤버는 Circle 설정의 멤버 목록에서 다른 멤버를 신고·차단할 수 있고, 관리자가 아닌 멤버는 "Circle 신고하기"로 Circle 자체를 신고할 수 있습니다. 차단은 내 화면만 바꾸고 멤버십은 그대로입니다. → 신고·차단

생성 ​

createCircle({name, description}) → {groupId, inviteCode}

한 트랜잭션에서 그룹 문서(memberIds: [나], adminId: 나, plan: "free"), 초대 코드 문서, 내 groupIds를 함께 만듭니다. 초대 코드가 이미 쓰이고 있으면 최대 5번까지 다시 뽑습니다. 이름·설명에 욕설·혐오 표현이 있으면 "Circle 이름이나 설명에 쓸 수 없는 표현이 있어요"로 거절합니다.

초대 코드 ​

새 코드예전 코드
형식8자리, ABCDEFGHJKLMNPQRSTUVWXYZ23456789 (헷갈리는 0 O 1 I 제외)대부분 6자리 영숫자
생성crypto.randomInt (암호학적 난수, 편향 없음)-
만료·사용 횟수30일, 50회필드가 없으면 무제한
  • 입력은 앞뒤 공백 제거 후 대문자로 바꿉니다(normalizeInviteCode). 영숫자 1~16자가 아니면 "초대 코드를 찾을 수 없어요"입니다.
  • 초대 링크는 https://grato.today/i/{코드} 형식입니다(짧은 링크). 전에 보낸 https://grato.today/invite/{코드}도 같은 초대 페이지를 엽니다. 링크 미리보기(Circle 이름, 인원)는 shareRenderer가 만듭니다.
  • 앱·웹의 초대하기·복사는 링크 끝에 보낸 사람의 참조 ?from={참조}를 붙입니다(GRATO-15). 참조는 사람마다 하나인 8자리 코드(초대 코드와 같은 글자)로, uid가 아닙니다. 초대 화면이 열릴 때 getInviterRef로 한 번 받아 두고, 아직 없으면 참조 없이 보냅니다(공유를 기다리게 하지 않음). 짧은 링크 /i/{코드}?from=과 긴 링크 /invite/{코드}?from= 모두 동작합니다(서버 미리보기는 쿼리를 보지 않고, 앱 딥링크는 쿼리를 넘김). → 초대 배지
  • 클라이언트는 아는 코드 하나만 조회할 수 있고 코드 목록은 볼 수 없습니다.

참여 ​

  • 이미 멤버면 오류가 아니라 alreadyMember: true이고 사용 횟수를 차감하지 않습니다.
  • 검사 순서: 코드 존재 → Circle 존재 → 이미 멤버 → 내보낸 사용자 → 만료 → 사용 횟수 → 정원 → 내 Circle 수.
  • 신규 사용자는 클라이언트가 users/{uid}를 먼저 만들도록 profileReady를 기다린 뒤 참여합니다.
  • 인앱 브라우저(카카오톡 등)에서는 Google 로그인이 막힙니다. 카카오톡·LINE에서 초대 링크를 열면 초대 페이지가 한 번 자동으로 휴대폰 브라우저에 넘깁니다(카카오톡 kakaotalk://web/openExternal, LINE openExternalBrowser=1). 앱이 설치된 휴대폰이면 이때 Universal Link·App Link로 앱의 초대 화면이 열립니다. 넘기지 못하면(다른 인앱 브라우저, 세션당 한 번 시도 뒤) 브라우저 열기·링크 복사 안내를 보여 줍니다. src/lib/inAppBrowser.js의 externalBrowserUrl.
  • 초대 메시지(inviteMessage)에는 링크와 함께 초대 코드가 들어 있어, 앱에서 "Circle 참여하기"에 코드를 넣어도 됩니다.
  • Circle을 만들면 바로 "초대하기" 카드(공유 시트, 카카오톡 포함)가 나옵니다. 혼자인 Circle은 쓰이지 않아서입니다.

오류 메시지 전체는 Cloud Functions에 있습니다.

초대 배지: 초대한 사람 기록 ​

배지 조건 초대(invites_joined, 1 · 마음의 다리 / 3 · 온기를 잇는 이 / 10 · 모임의 등불)는 내 링크로 처음 Circle에 들어온 사람 수입니다. 앱이 남기는 분석 이벤트(invite_joined)는 조작할 수 있어 쓰지 않고, 서버가 참여 때 기록합니다. → ADR-44

  • inviterRefs/{참조} = {uid, createdAt} — getInviterRef가 처음 부를 때 만들고 그 뒤로는 같은 것을 돌려줌.
  • circleJoins/{groupId}_{uid} = {groupId, joinerId, inviterId, createdAt} — 그 사람이 그 Circle에 처음 들어올 때 joinCircle이(만든 사람은 createCircle이) 씁니다. 링크의 참조가 있고, 보낸 사람이 들어오는 사람과 다르고, 지금 그 Circle의 멤버이면 inviterId에 보낸 사람, 아니면 null.
  • 세지 않는 것: 이미 멤버(alreadyMember), 나갔다 다시 들어옴(기록이 이미 있음), 자기 참조, 보낸 사람이 나간 Circle, 모르는 참조. 한 사람이 같은 사람의 Circle 두 곳에 들어와도 1명. 코드만 입력해 들어오면 보낸 사람을 모릅니다.
  • 보낸 사람이 기록되면 그 사람의 배지를 바로 평가합니다(축하 카드). 참여 결과(alreadyMember)는 그대로이고 기록 여부는 알려 주지 않습니다.
  • 두 컬렉션은 서버만 씁니다(규칙 match 없음). 계정을 지우면 내 참조와 내 참여 기록은 지우고, 나로 기록된 다른 사람의 참여 기록은 inviterId만 null로 둡니다(다시 들어옴을 막는 기록이라 남김).
  • 알려진 한계: 이 기능 전에 들어왔다 나간 사람은 기록이 없어, 다시 들어오면 처음으로 셉니다. 한 사람이 여러 계정을 만들면 막지 못합니다(배지 보상만 걸려 있음).

순서 바꾸기 ​

Circle 탭 "내 Circle" 목록 위의 [순서 바꾸기] → 각 Circle에 ↑·↓ 버튼이 나오고, 누를 때마다 바로 저장됩니다(users.circleOrder). [완료] 로 닫습니다. Circle이 2개 이상일 때만 보입니다.

  • 홈의 Circle 탭(내 기록 다음), Circle 목록, 쓰기 화면의 Circle 선택이 모두 이 순서입니다. 홈 "오늘 Circle 활동"도 앞쪽 Circle부터 셉니다.
  • 순서를 정한 뒤 새로 참여한 Circle은 맨 뒤에 붙고, 나간 Circle은 순서에서 무시됩니다.
  • 내 기기에만이 아니라 계정에 저장되어 다른 기기에서도 같은 순서입니다. 다른 멤버에게는 영향이 없습니다.
  • 정렬은 순수 함수 src/lib/circleOrder.js(orderCircles, moveCircle)가 하고 groupStore가 목록을 이 순서로 둡니다.

나가기 ​

leaveCircle({groupId}) — 내 uid를 memberIds에서, Circle을 내 groupIds에서 뺍니다. 관리자는 나갈 수 없습니다(먼저 Circle을 삭제해야 함).

화면은 Circle 설정 맨 아래 "주의해 주세요" 카드의 [Circle 나가기] → 확인 창("Circle에서 나갈까요?", 버튼 "나가기")입니다. 같은 카드에 관리자는 [Circle 삭제], 멤버는 [Circle 신고하기]가 있습니다(모두의 감사방은 신고 버튼 없음).

Circle이 이미 없거나 내가 멤버가 아니면 groupIds만 정리하고 성공합니다. 클라이언트는 이것을 이용해 삭제가 확인된 Circle의 오래된 ID를 서버에서도 지웁니다.

멤버 내보내기와 다시 허용 ​

함수동작
removeCircleMember({groupId, memberId})memberIds에서 제거, removedIds에 추가, 그 사람의 groupIds에서 제거
unbanCircleMember({groupId, memberId})removedIds에서 제거
  • 내보낸 사람은 이미 알고 있는 초대 코드로 다시 들어올 수 없습니다. "이 Circle에서 내보내져 다시 참여할 수 없어요. Circle 관리자에게 문의해주세요" 오류를 받습니다.
  • 관리자는 Circle 설정의 "내보낸 멤버" 목록에서 다시 허용할 수 있습니다. 다시 허용해도 자동으로 멤버가 되지는 않고, 초대 코드로 다시 참여해야 합니다.
  • 초대 코드를 바꾸지 않아도 차단이 유지되므로, 한 사람을 내보내려고 모든 멤버에게 새 코드를 나눠 줄 필요가 없습니다.
  • 내보내진 사람이 그 Circle에 쓴 글은 작성자 본인에게 계속 보입니다. 그 사람은 더 이상 Circle 피드를 읽거나 새 글을 올릴 수 없습니다.

Circle 삭제 ​

deleteCircle({groupId}) — 관리자만 가능합니다. 모두의 감사방은 거부합니다(위).

  1. 모든 멤버의 users.groupIds에서 이 Circle 제거 (없는 사용자 문서는 건너뜀)
  2. 이 Circle을 가리키는 초대 코드 전부 삭제, 첫 나눔 표시(circleFirstShares, 첫 나눔 알림) 삭제
  3. 그룹 문서 삭제 (마지막)
  4. Circle 사진(circlePhotos/{groupId}/) 삭제 (실패해도 로그만)

운영자가 신고된 Circle을 지울 때(moderate)도 같은 처리를 씁니다. 500개 단위 배치로 나눠 커밋합니다. 그룹 문서를 마지막에 지우므로 중간에 실패해도 다시 호출하면 이어서 정리됩니다.

감사 글은 지우지 않습니다. 그룹 문서가 사라지면 다른 멤버는 그 글을 읽을 수 없게 되지만, 작성자는 자기 글을 개인 기록으로 계속 봅니다. → 결정 기록 #4

초대 코드 재발급 ​

regenerateInviteCode({groupId}) → {inviteCode} — 관리자만. 기존 코드 문서를 모두 지우고 새 코드를 만든 뒤 groups.inviteCode를 바꿉니다. 한 트랜잭션이라 중간 상태가 없습니다. 기존 링크·코드는 즉시 쓸 수 없게 됩니다.

Circle 정보 수정 ​

관리자는 Firestore에 직접 name(1~30자), description(100자 이하), photoURL만 수정할 수 있습니다. 이름·설명을 바꾸면 서버가 내용 필터로 검사해, 걸리면 그대로 두고 운영자에게 알립니다(onCircleNameWritten). 사진은 Storage circlePhotos/{groupId}/에 올리며, Storage 규칙이 Firestore의 adminId를 교차 확인합니다. → 보안 규칙

피드 ​

  • Circle별로 최신 20개를 실시간 구독하고, "더 보기"는 커서(startAfter) 기반으로 20개씩 읽습니다.
  • 여러 Circle을 한 번에 합친 피드는 지원하지 않습니다. 규칙의 교차 읽기 한도 때문에 Circle마다 쿼리를 따로 보냅니다. → 보안 규칙
  • 홈의 "오늘의 Circle 활동"은 최대 10개 Circle에 대해 오늘(KST) 글 수와 리액션 수를 병렬로 집계합니다.
  • 구독 중 권한이 사라지면(내보내짐 등) 빈 피드로 처리해 로딩이 끝나지 않는 일을 막습니다.

첫 나눔 ​

한 사람이 그 Circle에 처음 나눈 글은 혼자 남지 않게 조금 다르게 보입니다(GRATO-51). 판정은 서버가 합니다 → 첫 나눔 알림.

  • 멤버 알림: 새 글 알림이 "{이름}님이 Circle에 처음 감사를 나눴어요 🌱"로 바뀜(알림 수는 같음). 24시간 동안 반응이 없으면 리더에게 한 번 → 리더 알림
  • 피드 카드 표시: Circle 피드에서 그 글의 작성자 이름 아래에 작은 표시 "처음 나눈 감사"(새싹 아이콘)가 만든 지 7일 동안 붙습니다. 서버가 쓰는 gratitudes.firstShare를 보고 그립니다(클라이언트는 쓸 수 없음, 규칙 테스트). 내 기록·저장한 감사에는 붙이지 않습니다. 계산은 src/lib/firstShare.js(showsFirstShareBadge, 테스트)
  • 저장 직후 안내: Circle에 저장한 뒤 그 Circle 피드 위에 **"Circle 멤버에게 알렸어요"**가 5초 보입니다. 이 기기에 이미 읽어 둔 그 Circle 피드에 내 글이 하나도 없을 때만(추가 요청 없이 추측, ADR-13). 틀려도 해가 없습니다: 멤버는 Circle 글마다 알림을 받습니다. 몇 명에게 갔는지는 쓰지 않습니다
  • 쓰는 사람에게 반응 수·읽음·"아직" 같은 상태는 어디에도 보이지 않습니다
  • 모두의 감사방: 표시도 안내도 없습니다(새 글 알림이 없는 방)
  • 웹은 Hosting 배포로, 앱은 **iOS 1.0.1 (5)**부터. 예전 앱은 firstShare를 무시해 그대로 동작합니다

모두의 감사방 (별명 Circle) ​

운영자가 여는 Circle 하나로, 누구나 원하면 별명을 정해 참여합니다(자동 참여는 없음). 기능은 꺼진 채로 배포되고, 운영자가 켜기 절차를 마친 뒤 켭니다. 꺼져 있는 동안에는 아무것도 보이지 않고 참여도 거부됩니다. → 결정 기록 #21, 데이터 모델

참여 화면. 기능이 켜져 있고 아직 참여하지 않았으면 Circle 탭의 "내 Circle" 위에 방 이름·설명과 [별명 정하고 참여] 카드가 보입니다. 이름·설명은 appConfig/openCircle의 사본입니다(멤버가 아니면 그룹 문서와 멤버 목록을 읽을 수 없음, 관리자가 이름을 바꾸면 운영자가 --sync). 누르면 아래 시트가 열립니다.

  • 안내: "이 방에서는 내 이름 대신 별명만 보여요." / "신고 처리를 위해 운영자는 작성자를 확인할 수 있어요." / "불쾌한 콘텐츠와 괴롭힘은 무관용 원칙으로 금지해요." / 글은 지금처럼 기본이 나만 보기
  • "이 방에서 쓸 별명" 입력(2~12자). 서버가 거절하면 그 이유("이미 쓰는 별명이에요", "운영자로 오해할 수 있는 별명은 쓸 수 없어요", "인원이 가득 찼어요" 등)를 보여 줍니다. → 오류 메시지
  • [별명으로 참여하기] → 참여하면 Circle 탭에 그대로 머물며 "…에 참여했어요" 안내가 보이고, 내 Circle 목록에 이 방이 들어옵니다. 홈을 열면 이 방의 피드 탭이 선택되어 있습니다(초대 코드로 참여할 때와 같음).
  • 전각 문자는 반각으로 저장됩니다("ＨＡ" → "HA").
  • 별명은 참여한 뒤에도 Circle 설정에서 바꿀 수 있습니다(아래).

참여한 뒤. 다른 Circle처럼 내 Circle 목록과 홈 탭, 쓰기 화면의 Circle 선택에 나오고, 목록에는 "별명: 햇살가득"이 붙습니다. 쓰기 화면에서 이 방을 고르면 "별명 '햇살가득'(으)로 올라가요"가 보입니다. 이 방 글에 다는 댓글도 별명으로 올라갑니다. 홈 "오늘 Circle 활동"에도 들어갑니다.

Circle 설정. 초대 코드와 멤버 목록 대신 "이 방에서 쓰는 별명"과 짧은 태그(이름·사진 대신 별명 / 누구나 참여 / 멤버 목록 비공개 / 별명은 7일에 한 번 변경)가 보입니다. 운영자가 작성자를 확인할 수 있다는 안내는 참여 시트에 있습니다.

별명 바꾸기. 별명 오른쪽의 [바꾸기] → 시트에 지금 별명이 채워져 있고, 새 별명을 넣고 [별명 바꾸기](지금 별명과 같으면 꺼짐). 규칙은 참여할 때와 같고(겹치지 않음, 금지어, 2~12자), 7일에 한 번 바꿀 수 있습니다(참여한 뒤 첫 변경은 바로). 너무 이르면 "별명은 7일에 한 번 바꿀 수 있어요. 10월 23일 14:05부터 바꿀 수 있어요"처럼 언제부터인지 보여 줍니다. 바꾸면 "별명을 바꿨어요. 이 방에 쓴 글과 댓글에도 곧 반영돼요." — 이번 참여 뒤 이 방에 쓴 글·댓글이 몇 초 안에 새 별명으로 바뀝니다(예전 참여 때 쓴 글은 그때 별명 그대로). 예전 별명은 바로 다른 사람이 쓸 수 있습니다. 차단 목록에는 차단할 때의 별명이 남습니다. → renameOpenCircleAlias 방 자체는 운영자가 운영해 [Circle 신고하기]가 없습니다(글·댓글·사람 신고는 평소처럼). 나가기는 다른 Circle과 같고, 나가면 별명이 지워져 다른 사람이 쓸 수 있습니다(다시 참여할 때 새로 정함). 관리자(운영 계정)는 이름·설명·사진을 다른 Circle처럼 고치고(이름·설명을 바꾸면 운영자가 setupOpenCircle --sync로 참여 카드에 반영), "Circle 삭제" 버튼은 없습니다.

별명은 가명입니다. 글에는 userId가 그대로 있어 규칙·삭제·통계·신고가 평소처럼 동작하고, 운영자는 신고된 글의 작성자를 운영자 화면에서 확인합니다. 앱은 이 방에서 작성자의 실제 프로필을 찾아 보여 주지 않습니다(멤버 목록 없음, 차단 목록은 별명으로 표시). 규칙도 이 방 멤버가 다른 사람의 공개 프로필을 읽는 것을 다른 Circle을 함께 쓰는 사람(과 본인, 운영자)으로 줄입니다. 그래서 이 방에서만 만난 사람의 실제 이름·사진은 볼 수 없고, 같은 일반 Circle 멤버는 그 Circle에서처럼 보입니다. 다른 사람이 볼 수 없는 프로필은 화면에 "사용자"(멤버 목록)·"알 수 없는 사용자"(차단 목록)로 나옵니다. → 보안 규칙

예전 앱. 이 방이 생기기 전 앱(iOS 1.0.0)에는 이 방의 화면이 없습니다. 웹이나 새 앱에서 참여한 뒤 예전 앱을 열면 이 방이 보통 Circle처럼 보이지만, 작성자가 별명이 아니라서 글·댓글은 저장되지 않습니다("이 Circle에는 더 이상 글을 남길 수 없어요" 등). 앱을 최신 버전으로 업데이트하면 정상으로 씁니다.

신고·차단. 신고는 평소와 같습니다. 별명 글·댓글에서 차단하면 차단 문서에 별명이 함께 저장되고, 차단한 사용자 화면에 "햇살가득 · 모두의 감사방 별명"으로 보입니다. 차단은 사람(uid) 단위라 그 사람의 다른 Circle 글도 함께 가려집니다.

계정 삭제와 정리. 탈퇴·내보내기·계정 삭제 때 별명과 선점이 함께 지워집니다. 내보낸 사람은 다시 참여할 수 없습니다. 운영 계정을 삭제해도 방은 멤버에게 넘어가거나 지워지지 않고 관리자 없이 남으며, 운영자가 설정 스크립트로 새 관리자를 정합니다.

방 삭제. 앱에서는 지울 수 없습니다. deleteCircle(관리자)과 moderate의 Circle 삭제(운영자)가 "모두의 감사방은 운영자가 관리해서 앱에서 삭제할 수 없어요"로 거부합니다. 지우려면 운영자가 setupOpenCircle --delete를 실행합니다(다른 Circle 삭제와 같은 정리 + 모든 별명·선점 + appConfig/openCircle, 글은 개인 기록으로 남음). → 스크립트

오늘의 주제 ​

모두의 감사방 맨 위에 매일 07:00(KST) 주제 하나가 올라갑니다(Reddit의 daily thread처럼). 답은 댓글이 아니라 감사 글로 저장되어 기록한 날·감사 수·배지·연속일에 그대로 쌓이고, 방에서는 주제 아래에 모여 보입니다. 운영 규칙(요일별 결, 문구 규칙, 4주 초안, 운영자 체크리스트)은 내부 운영 안(GRATO-3)을 따릅니다. → 결정 기록 #31, 데이터 모델

주제 카드 (홈 › 모두의 감사방 탭, 피드 위)

  • "오늘의 주제 · 월 · 작은 일상"과 주제 문구. 선정된 사용자 질문이면 "💡 Grato 사용자가 제안한 질문" — 이 방에서는 제안자의 실제 이름을 보이지 않습니다.
  • 숫자는 "오늘 n명이 답했어요" 하나뿐입니다. 이 방에 나눈 답의 사람 수이고, 숨김 글과 내가 차단한 사람은 빼고 셉니다. 3명 미만이면 숫자 대신 "첫 답을 남겨 보세요"(내가 답했으면 "답을 남겼어요. 다른 답을 기다리고 있어요").
  • [답하기] → 쓰기 화면. "오늘 주제 말고 자유롭게 써도 돼요" → 보통 쓰기 화면. 답하지 않아도 되고, 답하지 않은 날을 따로 표시하거나 알리지 않습니다.
  • 주제의 하루는 07:00부터 다음 날 06:59까지입니다. 그 사이에 쓴 답은 같은 주제의 답이고, 기록한 날은 지금처럼 쓴 KST 날짜로 셉니다. 그날 주제가 없으면 카드가 보이지 않습니다.

답 목록 (카드 아래, "오늘의 답 · 새 답이 위에 있어요")

  • 시간순, 새 답이 위. 인기순·공감순·베스트 답·운영자 추천 고정은 없습니다.
  • 내가 답하기 전에는 새 답 3개만 보이고 "답하면 오늘의 답을 모두 볼 수 있어요"가 나옵니다. 나만 보기로 답해도 전부 열립니다. 이 잠금은 쓰게 하려는 안내일 뿐 보안 장치가 아닙니다(멤버는 원래 이 방의 글을 모두 읽을 수 있음).
  • 다 열린 뒤에는 10개씩 "답 더 보기". 카드는 답을 최근 200개까지 읽습니다(그보다 많으면 "n명 넘게").
  • 답에도 공감·댓글·저장·신고·차단은 다른 글과 같습니다. 다만 답의 공감 숫자는 작성자 본인에게만 보입니다(다른 사람에게는 이모지만). 운영자는 신고 확인 화면에서 숫자를 봅니다.
  • 오늘 주제의 답은 피드에서 빠지고 카드 아래에만 나옵니다. 지난 주제의 답은 피드에 보통 글처럼, 글 위에 작게 "오늘의 주제: …"를 달고 보입니다.

답 쓰기 (/write?topic=YYYY-MM-DD)

  • 맨 위에 "오늘의 주제에 답하기"와 주제 문구, X(주제 없이 쓰기). "질문으로 쓰기" 안내는 숨깁니다.
  • 제목은 쓰지 않아도 됩니다(한 줄 답도 됨). 내용은 다른 글과 같은 기준입니다.
  • 공개 범위는 지금처럼 나만 보기가 기본이고 이 방을 미리 고르지 않습니다. 고를 수 있는 Circle은 모두의 감사방뿐입니다(다른 Circle에는 답을 올릴 수 없음). 이 방을 고르면 버튼이 "이 방에 나누기", 별명으로 올라갑니다.
  • 저장하면 이 방 탭으로 돌아가 답 목록이 열립니다. 내 기록의 그 글 위에도 "오늘의 주제: …"가 보입니다.
  • 운영자가 문구를 막 고쳐 저장이 거부되면 주제를 다시 읽어 한 번 더 저장합니다.

운영자 화면 (관리자 › 주제)

  • 날짜(오늘의 주제 날부터 92일 뒤까지), 출처(운영자 / 선정 질문 / 시즌), 문구, 결(요일 기본값)을 고르고 [주제 예약하기]. 하루에 하나입니다.
  • 서버가 막는 것: 5~80자 밖, 링크·연락처·욕설, "AI"·"인공지능", 앞뒤 8주 안의 같은 문구. 화면은 권장(질문 하나, 15–50자, 물음표)을 안내합니다.
  • 선정 질문은 질문 탭에서 선정한 사용자 질문(첫 질문) 중에서 고릅니다. 시즌 주제는 seasonKey(예: 2026-thanks, 배지·시즌 질문과 같은 형식)를 붙입니다(GRATO-66).
  • 올라간 주제는 문구를 고칠 수 있고(그 뒤의 답부터 새 문구), 지울 수는 없습니다. 예약 중인 주제는 지울 수 있습니다.
  • 쓰기는 모두 manageDailyTopic callable이고 adminAuditLogs에 남습니다. 운영 계정("Grato 운영팀")으로 답하거나 공감하지 않습니다. → Cloud Functions

이용 기록: topic_card_viewed(주제마다 세션에 한 번, answered), topic_unlock_prompt_viewed, topic_write_started, gratitude_created의 topicId. 주제·답 문구는 넣지 않습니다.

Circle 가이드 페이지 ​

/circle-guide는 교회 소그룹, 독서모임, 가족, 친구 모임의 리더를 위한 공개 페이지입니다. 본문과 자주 묻는 질문은 src/content/seoPages.js(SEO_PAGES['circle-guide'], CIRCLE_GUIDE_FAQ), 화면은 src/pages/CircleGuidePage.jsx입니다.

  • 이 문서의 한도(50명, 20개, 초대 코드 30일·50회), 탈퇴·내보내기·삭제 동작, 관리자 위임이 없다는 점을 그대로 씁니다. 이 동작을 바꾸면 페이지 문구도 같이 고칩니다.
  • 시작 버튼: 웹에서 로그인하지 않았으면 "웹에서 시작하기"(/login)와 App Store 배지(AppDownload, 웹에서만), 로그인했거나 앱 안이면 "Circle 만들러 가기"(/group).
  • 앱에서도 열리는 페이지라 본문에 다른 플랫폼 이름을 쓰지 않습니다(App Store 심사 가이드라인 2.3.10). seoPages.test.js가 확인합니다.
  • Circle이 하나도 없으면 Circle 탭의 빈 화면에 "모임에서 Circle 쓰는 법 보기" 링크가 있습니다.
