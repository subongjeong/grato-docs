질문 제안과 선정 ​

"질문으로 쓰기"에 나오는 질문은 사용자가 제안하고 운영자가 골라 선정합니다. 선정된 질문만 다른 사용자에게 보이고, 사용자가 제안해 선정된 질문에는 제안자의 공개 이름이 함께 표시됩니다. 제안자는 처음 선정될 때 알림을 받고, 선정된 수에 따라 배지를 받습니다. → 결정 기록 #11

누가무엇을어디서
사용자질문 제안, 내 제안의 검토 상태 확인질문으로 쓰기 화면, MyPage "내가 제안한 질문"
운영자 (users/{uid}.isAdmin == true)선정(문구·종류 수정 가능), 반려, 숨김관리자 페이지 "질문" 탭
서버모든 쓰기: 검증, 한도, 상태 변경, 배지, 알림, 운영 기록submitQuestion, reviewQuestion callable

반려된 질문은 다시 선정할 수 없습니다. 제안자는 같은 질문을 새로 제안할 수 있습니다(반려·숨김 질문은 중복으로 보지 않음).

질문 제안하기 ​

질문으로 쓰기 화면 아래의 "좋은 질문이 떠올랐나요? 질문 제안하기"와 MyPage "내가 제안한 질문"의 "질문 제안하기"에서 바텀 시트(SuggestQuestionSheet)를 엽니다.

  • 종류: 첫 질문("오늘을 떠올리게 하는 질문") / 이어지는 질문("첫 답변을 더 깊게 묻는 질문"). 질문으로 쓰기에서 열면 지금 보고 있는 단계의 종류가 미리 골라져 있습니다(쓰던 질문이 없을 때).
  • 질문: 최대 80자, 글자 수 표시. 보내기 전에 서버와 같은 방식으로 정리하고 5~80자인지 먼저 확인합니다.
  • 안내: "운영자가 검토해 선정한 질문만 다른 사람들에게 보여요. 선정되면 공개 이름(예: 홍길동 #1234)이 질문과 함께 표시돼요."
  • 오류: 서버가 돌려준 메시지를 그대로 보여 줍니다. → 오류 메시지
  • 성공: "제안해 주셔서 고마워요! 선정되면 알려드릴게요. 검토 결과는 마이페이지에서 볼 수 있어요." 시트를 닫았다 열어도 쓰던 질문은 남아 있고, 제안에 성공하면 비웁니다.
  • 성공하면 분석 이벤트 question_submitted({ kind })를 남깁니다.

제출 규칙 ​

submitQuestion이 아래 순서로 확인합니다. 길이·내용 필터·종류에서 걸리면 Firestore를 읽지 않습니다.

항목기준거절 메시지
길이정리한 뒤 5~80자 (코드 포인트 단위)질문은 5~80자로 써주세요
내용 필터욕설·혐오 표현, URL·도메인, 이메일, 8자리 이상 숫자(전화번호)부적절한 표현이나 연락처는 질문에 넣을 수 없어요
종류opening 또는 followup (없으면 opening)질문 종류가 올바르지 않아요
전체 검토 대기모든 사용자의 pending이 300개 미만지금은 검토를 기다리는 질문이 많아요. 잠시 후 다시 제안해주세요
하루 시도사용자당 KST 하루 30번 (거절된 시도 포함)오늘은 질문 제안을 너무 많이 시도했어요. 내일 다시 제안해주세요
하루 제안사용자당 KST 하루 5개 (받아들여진 것만 셈)오늘은 질문을 5개까지 제안할 수 있어요
내 검토 대기사용자당 pending 20개 미만검토 중인 질문이 많아요. 검토가 끝난 뒤 다시 제안해주세요
중복검토 중이거나 선정된 질문과 같은 문구가 아님이미 등록되었거나 검토 중인 질문이에요
  • 정리(정규화): NFC, 보이지 않는 문자(폭 없는 공백, 한글 채움 문자 등)와 제어 문자 제거, 줄바꿈을 포함한 연속 공백을 한 칸으로, 앞뒤 공백 제거. 저장되는 text가 이 결과입니다.
  • 같은 문구: NFKC 후 보이지 않는 문자를 빼고 소문자로 바꾼 뒤 글자와 숫자만 남긴 키(dupKey)가 같으면 같은 질문으로 봅니다. "오늘 감사한 일은?"과 "오늘 감사한 일은"은 같은 질문입니다.
  • 하루 한도는 questionQuota/{uid}_{YYYYMMDD}(KST) 문서로 세고, 하루 시도·하루 제안·내 검토 대기·중복 확인과 새 문서 생성은 한 트랜잭션에서 합니다. 동시에 여러 번 보내도 한도를 넘거나 같은 질문이 두 번 저장되지 않습니다.

내용 필터 ​

functions/src/utils/contentFilter.ts는 Firebase에 의존하지 않는 순수 모듈이라 나중에 댓글·이름에도 쓸 수 있습니다. 한국어·영어 욕설과 혐오 표현을 짧은 목록으로 막고, 띄어 쓰거나 구두점·숫자·기호를 끼워 넣거나 비슷한 글자로 바꿔 쓴 것도 정리한 뒤 비교합니다. "시발점", "감염병"처럼 정상 단어는 허용 목록에 둡니다.

모든 질문은 운영자가 검토하므로, 필터는 놓치는 것보다 정상 문장을 막는 쪽을 더 조심합니다. 자세한 규칙은 Cloud Functions: 내용 필터에 있습니다.

제안자 표시 ​

선정된 사용자 질문은 질문으로 쓰기의 질문 아래에 "💡 홍길동 #1234님의 질문"처럼 제안자의 공개 이름을 보여 줍니다. 기본 질문에는 표시하지 않습니다.

  • 이름(authorPublicName)은 제안할 때 publicProfiles/{uid}.publicName에서 복사하고, 선정할 때 다시 읽어 갱신합니다. 선정한 뒤에 이름을 바꾸면 질문에 보이는 이름은 다음 선정 전까지 그대로입니다.
  • 이름이 비어 있거나 내용 필터에 걸리면 이름을 저장하지 않고(null) 표시하지도 않습니다.
  • 선정할 때 이름 확인: 운영자 화면에 보이던 이름과 제안자의 지금 이름이 다르면 선정하지 않고 새 이름만 저장합니다. 운영자에게는 "제안한 사람의 공개 이름이 바뀌었어요. 바뀐 이름을 확인한 뒤 다시 선정해주세요"가 보이고, 목록을 다시 불러 새 이름을 보여 줍니다. 운영자가 확인하지 않은 이름이 질문과 함께 공개되지 않게 하기 위해서입니다.

내가 제안한 질문 (MyPage) ​

MyPage의 "내가 제안한 질문" 카드(id="questions", 주소 /mypage#questions)입니다.

  • 본인 제안을 최신순으로 최대 50개 실시간으로 보여 줍니다. 처음에는 5개, 더 있으면 "전체 보기 (n)".
  • 상태 칩: 검토 중 / 선정됨 / 반려됨(반려 사유가 있으면 함께 표시) / 숨김. 종류(첫 질문 / 이어지는 질문)와 제안 날짜도 보여 줍니다.
  • 제안한 질문이 없으면 "첫 질문 제안하기" 버튼을 보여 줍니다.
  • 주소가 #questions로 끝나면 목록을 그린 뒤 이 카드로 스크롤합니다. 질문 선정 알림을 누르면 여기로 옵니다.

운영자 검토 ​

관리자 페이지(/admin)의 첫 탭 "질문"(QuestionManager)에서 처리합니다. 모든 작업은 reviewQuestion callable로 하고, 운영자도 Firestore에 직접 쓰지 않습니다.

위쪽의 상태별 개수(검토 중 / 선정됨 / 숨김 / 반려됨)가 목록 탭을 겸합니다.

목록정렬할 수 있는 일
검토 중오래된 순 (검토 대기열)이대로 선정, 수정 후 선정(문구·종류), 반려(사유 100자 이내, 선택)
선정됨사용자 질문 먼저, 최근 선정 순숨기기 (확인 창)
숨김사용자 질문 먼저다시 선정
반려됨최신순보기만
  • 카드에는 질문, 종류, 제안자의 공개 이름(없으면 "이름 없음", 기본 질문은 "기본 질문"), 반려 사유가 보입니다.
  • 수정 후 선정: 고친 문구도 제안과 같은 길이·내용 필터를 거칩니다. 이미 선정된 다른 질문과 같은 문구면 "이미 선정된 같은 질문이 있어요"로 거절합니다. 고치기 전 제안 원문은 운영자만 읽을 수 있는 questionOriginals/{id}에 처음 한 번 남기고, 카드에 "원문 (운영자만 보여요)"로 보입니다. 공개되는 질문 문서에는 원문을 남기지 않습니다.
  • 작업이 실패하면 카드에 서버 메시지를 보여 주고 목록을 다시 불러옵니다.
  • 모든 작업은 같은 트랜잭션에서 adminAuditLogs에 기록됩니다. 검토한 운영자의 정보는 질문 문서에 남지 않으므로 제안자는 누가 검토했는지 볼 수 없습니다.
  • 기본 질문도 선정됨 목록에 함께 나오며, 숨기거나 다시 선정할 수 있습니다. 문구는 questions.json에서 고칩니다. → 기본 질문

선정 뒤에 일어나는 일 ​

일내용
질문으로 쓰기선정된 질문은 세션에 한 번 읽으므로, 다음에 앱을 열 때부터 나옵니다. → 질문으로 쓰기
배지사용자 질문이면 제안자의 배지를 평가합니다. 숨겨도 이미 받은 배지는 유지됩니다. → 질문 배지
알림처음 선정될 때 한 번만 제안자에게 푸시를 보냅니다. 숨겼다가 다시 선정해도 다시 보내지 않습니다. → 알림

항목값

질문 배지 ​

ID이름아이콘조건
questions_selected_1첫 질문 선정💡제안한 질문이 처음으로 선정됐어요

기본 질문 ​

  • 원본은 src/content/questions.json({ "opening": [30개], "followup": [10개] })입니다.
  • seedQuestions 스크립트가 questions/system_opening_01..30, system_followup_01..10으로 넣습니다(source: "system", authorId: null, status: "approved"). 배포 때 실행합니다. → 배포: 기본 질문 시드
  • 운영자가 숨긴 기본 질문은 다시 시드해도 숨김으로 남습니다. 문구와 종류는 JSON 기준으로 되돌리므로 기본 질문 문구는 JSON에서 고칩니다.
  • 앱도 같은 JSON을 들고 있어, 선정된 기본 질문을 읽지 못하면 대신 씁니다. → 질문으로 쓰기
