알림 ​

푸시는 Firebase Cloud Messaging(FCM)으로 보냅니다. 서버는 Cloud Functions 트리거와 스케줄러, 웹 클라이언트는 서비스 워커(public/firebase-messaging-sw.js)와 src/lib/pushNotifications.js가 담당합니다. iOS·Android 앱은 네이티브 푸시(src/lib/native/push.js)를 쓰고, 매일 알림은 서버 푸시 대신 휴대폰이 직접 띄웁니다. → 앱 (iOS·Android)

알림 종류 ​

종류 (data.type)언제받는 사람끄는 설정클릭 시중복 방지 키
circle_postCircle에 새 글 (onGratitudeCreated). 그 Circle의 첫 나눔이면 variant: "first" → 첫 나눔작성자를 뺀 Circle 멤버 (작성자를 차단한 멤버 제외). 자동 숨김된 글은 보내지 않음circlePostNotice/gratitude/{id}circle_post_{gratitudeId}
circle_post (variant: "first_followup")첫 나눔 뒤 24시간 동안 다른 사람의 공감·댓글이 없음 (firstShareFollowup, Cloud Tasks). 밤(KST 22:00–08:59)이면 다음 09:00 → 리더 알림그 Circle의 리더 한 명. 리더당 하루(KST) 1회circlePostNotice/gratitude/{id}first_followup_{gratitudeId} (+ 하루 상한 first_followup_leader_{uid}_{YYYYMMDD})
reaction내 글에 새 리액션 (onReactionUpdated)글 작성자 (본인 리액션, 작성자가 차단한 사람의 리액션 제외)reactionNotice/gratitude/{id}reaction_{gratitudeId}_{reactorUid}_{emoji}

알림 문구 예:

  • Circle 새 글: "{공개 이름}님이 감사를 기록했어요" / 본문은 글 제목. 이름을 모르면 "누군가 감사를 기록했어요". 모두의 감사방 글은 보내지 않음
  • Circle 첫 나눔: "{공개 이름}님이 Circle에 처음 감사를 나눴어요 🌱" / 본문은 글 제목. 이름을 모르면 "새 멤버가 Circle에 처음 감사를 나눴어요 🌱" → 첫 나눔
  • 첫 나눔 리더 알림: "{공개 이름}님이 처음 나눈 감사가 있어요" / "{글 제목} · 공감이나 댓글로 반겨 줄 수 있어요". 이름을 모르면 "새 멤버가 처음 나눈 감사가 있어요" → 리더 알림
  • 리액션: "{공개 이름}님이 공감했어요 ❤️" / 본문은 글 제목. 모두의 감사방 글이면 공개 이름 대신 공감한 사람의 그 방 별명. 이름(별명)이 없으면 "누군가 공감했어요 ❤️"("누군가님이"라고 쓰지 않음, utils/noticeCopy.ts)
  • 매일 알림: "오늘의 감사를 기록해보세요 🙏" / "하루를 돌아보며 감사한 순간을 적어볼까요?" — 쓰기로 한 때를 골랐으면 그 때를 말함 → 매일 알림 문구
  • 질문 선정: "제안한 질문이 선정됐어요 🎉" / 본문은 질문 문구 → 질문 선정 알림
  • 신고(운영자): "새 신고가 접수됐어요" / "감사 글 · 욕설·괴롭힘. 24시간 안에 확인해주세요". 잠금 화면에 보이므로 신고된 내용과 이름은 넣지 않음 → 신고

차단은 그 사람 때문에 오는 알림(새 글, 리액션)을 막습니다. 차단 여부는 보내기 전에 받는 사람의 차단 목록(users/{uid}/blocks)을 읽어 확인합니다. → 차단

첫 나눔 알림 ​

한 사람이 그 Circle에 처음 나눈 글은 멤버가 받는 새 글 알림의 문구만 바뀝니다. 받는 사람·설정·횟수는 보통 새 글 알림과 같습니다(알림이 늘지 않음). 처음 나눈 글이 혼자 남지 않게, 멤버가 반겨 줄 기회를 만드는 장치입니다(GRATO-51).

항목내용
판정onGratitudeCreated의 4단계(Circle 알림)에서 claimFirstShare(notifications/firstShare.ts). 표시 문서 circleFirstShares/{groupId}_{uid}가 없을 때만 트랜잭션으로 만들고, 처음 만든 글이면 첫 나눔 → 데이터 모델
예전부터 쓴 사람표시 문서가 없더라도 그 Circle에 이미 쓴 글이 있으면(작성자·Circle로 최대 3개 조회, 이 글보다 먼저인 글) 첫 나눔이 아님 → legacy: true 표시만 남기고 문구는 그대로
지웠다 다시 쓰기표시 문서는 글을 지워도 남아서 두 번 "처음"이 되지 않음
빼는 글자동 숨김된 글(알림도 없음, 표시도 만들지 않아 다음 글이 첫 나눔), 모두의 감사방 글(새 글 알림 없음), "나만 보기" 글
리더 자신의 첫 글같은 문구로 멤버에게 감
알림 datatype: "circle_post" 그대로 + variant: "first". 클릭 경로(/gratitude/{id})가 같아 앱 업데이트 없이 동작
글 표시첫 나눔이면 같은 트랜잭션에서 글에 firstShare: true(Circle 피드의 "처음 나눈 감사", 앱 iOS 1.0.1 (5)부터) → 첫 나눔
판정 실패오류가 나면 보통 새 글 알림으로 보냄(로그만)
쓰는 사람에게아무것도 보이지 않음. "반응 없음"·읽음 표시 없음

판단은 순수 함수 notifications/firstSharePlan.ts(test/firstShare.test.ts), 문구는 utils/noticeCopy.ts의 firstShareNoticeTitle입니다. 두 글을 거의 동시에 한 Circle에 처음 올리면 둘 다 보통 문구가 될 수 있습니다(표시 문서는 한 번만 만들어짐, 해는 없음).

알림을 눌러 생기는 notification_clicked 이벤트는 props.variant에 "first"를 담습니다(웹 포그라운드 알림과 앱). 웹의 백그라운드 알림 클릭은 서비스 워커가 처리해 지금은 이벤트를 남기지 않습니다(종류와 상관없이 같음).

24시간 뒤 리더에게 한 번 ​

첫 나눔에 실제 사람의 반응이 닿을 두 번째 기회입니다. 모임을 연 리더에게만, 필요할 때 한 번 갑니다(GRATO-77). 쓰는 사람에게는 아무것도 가지 않습니다.

메시지 모양: 웹은 데이터 전용, 앱은 notification ​

utils/messaging.ts의 sendToUser는 사용자의 토큰마다 buildPushMessage로 메시지를 만듭니다. 토큰 문서의 platform(web · ios · android, 없거나 모르는 값은 web)에 따라 모양이 다릅니다. 어느 쪽이든 data에 title, body, type, gratitudeId 등이 들어갑니다.

플랫폼메시지이유
web데이터 전용 (최상위 notification 키 없음)notification 키가 있으면 브라우저가 알림을 자동으로 띄우고 서비스 워커도 띄워 두 번 보임. 표시는 서비스 워커(백그라운드)와 페이지(포그라운드)가 전적으로 맡음
ios, androidnotification(제목·본문) + 같은 data, APNs 기본 소리, Android 채널 grato_push·높은 우선순위iOS는 데이터 전용 메시지를 시스템 알림으로 보여 주지 않고, Android도 백그라운드에서 데이터 전용 메시지를 표시하지 않음. 앱이 꺼져 있어도 OS가 표시

발송 흐름 ​

  • 토큰이 없는 사용자는 오류가 아니라 건너뜁니다.
  • messaging/invalid-registration-token, messaging/registration-token-not-registered 오류가 나면 그 토큰 문서를 지웁니다.
  • 기록은 발송 뒤에 남기므로, 발송 직후 함수가 죽으면 재시도 때 한 번 더 갈 수 있습니다(최선 노력 방식의 중복 방지).

웹 클라이언트 ​

앱의 차이는 아래에 있습니다.

토큰 등록 ​

pushTokens/{uid}/tokens/{token}에 {token, platform: 'web', userAgent, createdAt}을 저장합니다(앱은 {token, platform: 'ios' | 'android', createdAt} → 앱). 토큰 문자열을 문서 ID로 써서 같은 기기를 다시 등록해도 문서가 하나입니다.

  • 로그인할 때마다 registerPushToken(uid)를 부르지만, 권한이 이미 granted일 때만 토큰을 저장합니다. 권한 창을 자동으로 띄우지 않습니다.
  • 권한 요청은 사용자가 버튼을 눌렀을 때만 합니다(enablePushNotifications). 브라우저는 사용자 동작 없는 권한 요청을 막거나 사용자가 거부하기 쉬우므로, 거부되면 다시 물을 수 없기 때문입니다.

권한 UX ​

위치동작
홈 PushPromptCard권한이 default이고 FCM을 지원하는 브라우저에서만 표시. "알림 받기"를 누르면 권한 요청. 닫으면 localStorage의 push-prompt-dismissed에 기억

가입 직후 /welcome/plan"이 시간에 알려 주세요"를 누를 때만 권한 요청(askNotificationPermission: 웹은 권한 답을 받는 즉시 돌아오고 토큰 등록은 뒤에서, 앱은 OS 권한). 다른 버튼은 묻지 않음 → 언제 감사를 떠올릴까요?

MyPage 알림 설정기기의 푸시 상태(지원 여부, 권한, 등록된 토큰 수)를 보여 주고 켜기 버튼 제공. 종류별 토글과 매일 알림 시각 선택. 이 브라우저가 알림을 지원하지 않으면 시각 아래 설명이 "이 브라우저에서는 알림이 오지 않아요. 위 안내를 확인해 주세요"

iPhone·iPad 웹: App Store 앱 안내 ​

iPhone·iPad의 브라우저는 모두 같은 엔진이라 Safari 탭, Chrome, 카카오톡 안 브라우저 모두 웹 알림을 띄우지 못합니다(Notification이 없음). "다른 브라우저"는 답이 아니므로 App Store의 Grato 앱을 안내합니다. 같은 계정으로 로그인하면 기록과 알림 설정(시각 포함)이 그대로 이어집니다.

  • 판정은 기능 감지와 기기 판별만 씁니다(src/lib/pushHelp.js, 순수 함수 + 테스트). iOS 기기는 isIOSDevice({userAgent, platform, maxTouchPoints})(src/lib/platform.js): iPhone·iPad·iPod, 그리고 데스크톱 사이트를 요청하는 iPadOS(MacIntel + 터치 지점 2개 이상). 설정 카드는 getPushStatus의 supported(FCM isSupported()까지)와 iosWeb으로, 홈 카드는 FCM을 불러오지 않고 API 유무(webPushCapable)로 정합니다.
  • 홈 화면에 추가한 웹 앱(iOS 16.4 이상)은 웹 푸시 API가 있을 수 있어, 있으면 다른 브라우저처럼 권한 단계 안내를 따릅니다. FCM이 그곳을 지원하지 않는다고 하면 설정 카드는 App Store 안내가 됩니다(홈 카드는 API 유무만 보므로 나오지 않음).
  • 웹에서만 보입니다. 앱(isNative)에서는 getPushStatus가 언제나 iosWeb: false이고 홈 카드도 그리지 않아, 앱 화면에 다른 플랫폼 이름이 들어가지 않습니다. Android 앱은 Play 정식 출시 전이라 Android 웹에는 앱을 안내하지 않습니다.
  • 분석: App Store 버튼을 누르면 app_store_link_click({from: 'push_status' | 'home_card', standalone}), standalone은 홈 화면에 추가한 웹 앱에서 눌렀는지.

  • 백그라운드: 서비스 워커의 onBackgroundMessage가 data.title/data.body로 알림을 띄웁니다. 클릭하면 data.type에 맞는 경로(위 표의 "클릭 시")로, 열린 창이 있으면 그 창을 이동·포커스하고, 없으면 새 창을 엽니다.
  • 포그라운드: App.jsx가 onMessage로 받아 브라우저 Notification을 띄우고, 클릭 시 같은 경로로 이동하며 notification_clicked 이벤트를 남깁니다.

  • 시즌 문구와 겹칠 때: JSON의 seasons({seasonKey, from, to, title, core?, body?}, KST 날짜 포함 범위, 시즌 질문과 같은 날짜 — 클라이언트 테스트가 확인)에 든 기간에는 시즌 문구가 이기고, 고른 때가 있으면 앞의 단서와 이모지만 붙입니다: "{lead}, {core} {emoji}" → "잠들기 전, 한 해 돌아보기 질문 하나 🌙". 때가 없으면 시즌 title. 지금 seasons는 비어 있습니다(시즌 문구는 별도 작업에서 채움).

  • 때 문구로 보낸 알림은 data.cue를 싣고, 누르면 notification_clicked {type: 'daily_reminder', cue}가 남습니다(웹 포그라운드·앱 푸시·앱 휴대폰 알림). 웹에서 브라우저가 띄운 알림(백그라운드)을 누른 것은 지금처럼 기록되지 않습니다.

매일 알림: 휴대폰 자체 알림 ​

앱에서는 서버 푸시 대신 @capacitor/local-notifications로 휴대폰이 직접 띄웁니다(src/lib/native/localReminders.js). → 결정 기록 #16

  • 시각은 웹과 같은 설정(KST, 15분 단위). 앞으로 14일 치를 하루씩 예약하고, 오늘 이미 썼거나 시각이 지났으면 오늘은 뺍니다.
  • 문구는 서버와 같은 매일 알림 문구를 날마다 계산합니다(시즌이 시작되는 날부터 시즌 문구). 예약하기 전에 서버 시즌을 최대 4초 기다리고(loadSeasons), 늦으면 앱 안 문구로 예약했다가 다음 예약 때 바뀝니다. 쓰기로 한 때나 문구가 바뀌면 다시 예약합니다.
  • 앱 시작·복귀, 설정 변경, 글 저장, 권한 허용 때 다시 맞춥니다. 설정 화면 안내: "매일 이 시간에 이 휴대폰으로 알려드려요. 기록한 날은 쉬어요 (15분 단위)".
  • Android 채널 daily_reminder("매일 감사 알림"). 정확한 알람 권한은 쓰지 않아 절전 중에는 몇 분 늦을 수 있습니다.
  • 예약하는 동안 notificationSettings.dailyReminderChannel = 'local'과 dailyReminderLocalAt(서버 시각)을 한 번에 씁니다. 서버는 이 표시가 14일 안이면 그 사용자에게 매일 알림을 보내지 않습니다(웹 브라우저 포함, 하루 한 번만). 알림을 끄거나 권한이 없거나 로그아웃하면 null로 되돌려 서버 알림이 다시 갑니다. 앱을 지워 되돌리지 못해도 14일 뒤 만료됩니다.
