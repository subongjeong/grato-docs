알림 ​

푸시는 Firebase Cloud Messaging(FCM)으로 보냅니다. 서버는 Cloud Functions 트리거와 스케줄러, 웹 클라이언트는 서비스 워커(public/firebase-messaging-sw.js)와 src/lib/pushNotifications.js가 담당합니다. iOS·Android 앱은 네이티브 푸시(src/lib/native/push.js)를 쓰고, 매일 알림은 서버 푸시 대신 휴대폰이 직접 띄웁니다. → 앱 (iOS·Android)

알림 종류 ​

종류 (data.type)언제받는 사람끄는 설정클릭 시중복 방지 키
circle_postCircle에 새 글 (onGratitudeCreated)작성자를 뺀 Circle 멤버 (작성자를 차단한 멤버 제외). 자동 숨김된 글은 보내지 않음circlePostNotice/gratitude/{id}circle_post_{gratitudeId}
reaction내 글에 새 리액션 (onReactionUpdated)글 작성자 (본인 리액션, 작성자가 차단한 사람의 리액션 제외)reactionNotice/gratitude/{id}reaction_{gratitudeId}_{reactorUid}_{emoji}
daily_reminder설정한 시각 (sendDailyReminder). 앱은 휴대폰 자체 알림오늘 아직 쓰지 않은 사용자 (앱이 로컬 알림을 맡은 사용자 제외)dailyReminder/writedaily_reminder_{uid}_{YYYYMMDD}_{HHMM}
question_selected제안한 질문이 처음 선정됨 (reviewQuestion)제안자없음/mypage#questionsquestion_selected_{questionId} (+ 처음 선정일 때만 보냄)
report새 신고 접수 (onReportCreated)운영자(isAdmin) 전원없음/admin?tab=reportsreport_{reportId} (+ 대상의 첫 열린 신고일 때만, 차단 신고는 보내지 않음)

알림 문구 예:

  • Circle 새 글: "{공개 이름}님이 감사를 기록했어요" / 본문은 글 제목
  • 리액션: "{공개 이름}님이 공감했어요 ❤️" / 본문은 글 제목
  • 매일 알림: "오늘의 감사를 기록해보세요 🙏" / "하루를 돌아보며 감사한 순간을 적어볼까요?"
  • 질문 선정: "제안한 질문이 선정됐어요 🎉" / 본문은 질문 문구 → 질문 선정 알림
  • 신고(운영자): "새 신고가 접수됐어요" / "감사 글 · 욕설·괴롭힘. 24시간 안에 확인해주세요". 잠금 화면에 보이므로 신고된 내용과 이름은 넣지 않음 → 신고

차단은 그 사람 때문에 오는 알림(새 글, 리액션)을 막습니다. 차단 여부는 보내기 전에 받는 사람의 차단 목록(users/{uid}/blocks)을 읽어 확인합니다. → 차단

알림 설정 ​

users/{uid}.notificationSettings (MyPage에서 변경):

키기본값비고
dailyRemindertrue서버는 == true인 사용자만 조회. 필드가 없으면 보내지 않음
dailyReminderHour210~23, KST 시
dailyReminderMinute00·15·30·45, KST 분. 없으면 0(분 단위 도입 전 설정)
reactionNoticetrue필드가 없으면 켜진 것으로 취급
circlePostNoticetrue필드가 없으면 켜진 것으로 취급
dailyReminderChannel없음앱만 씀. 'local'이면 그 사용자의 휴대폰 앱이 매일 알림을 로컬 알림으로 띄우는 중 → 서버가 보내지 않음. 알림을 끄거나 로그아웃하면 null
dailyReminderLocalAt없음앱이 'local'을 쓸 때의 서버 시각. 하루에 한 번까지 갱신, 14일이 지나면 서버가 'local'을 무시

설정은 notificationSettings.<키> 점 표기법으로 한 키씩 갱신해, 클라이언트가 모르는 새 키를 지우지 않습니다.

메시지 모양: 웹은 데이터 전용, 앱은 notification ​

utils/messaging.ts의 sendToUser는 사용자의 토큰마다 buildPushMessage로 메시지를 만듭니다. 토큰 문서의 platform(web · ios · android, 없거나 모르는 값은 web)에 따라 모양이 다릅니다. 어느 쪽이든 data에 title, body, type, gratitudeId 등이 들어갑니다.

플랫폼메시지이유
web데이터 전용 (최상위 notification 키 없음)notification 키가 있으면 브라우저가 알림을 자동으로 띄우고 서비스 워커도 띄워 두 번 보임. 표시는 서비스 워커(백그라운드)와 페이지(포그라운드)가 전적으로 맡음
ios, androidnotification(제목·본문) + 같은 data, APNs 기본 소리, Android 채널 grato_push·높은 우선순위iOS는 데이터 전용 메시지를 시스템 알림으로 보여 주지 않고, Android도 백그라운드에서 데이터 전용 메시지를 표시하지 않음. 앱이 꺼져 있어도 OS가 표시

발송 흐름 ​

  • 토큰이 없는 사용자는 오류가 아니라 건너뜁니다.
  • messaging/invalid-registration-token, messaging/registration-token-not-registered 오류가 나면 그 토큰 문서를 지웁니다.
  • 기록은 발송 뒤에 남기므로, 발송 직후 함수가 죽으면 재시도 때 한 번 더 갈 수 있습니다(최선 노력 방식의 중복 방지).

웹 클라이언트 ​

앱의 차이는 아래에 있습니다.

토큰 등록 ​

pushTokens/{uid}/tokens/{token}에 {token, platform: 'web', userAgent, createdAt}을 저장합니다(앱은 {token, platform: 'ios' | 'android', createdAt} → 앱). 토큰 문자열을 문서 ID로 써서 같은 기기를 다시 등록해도 문서가 하나입니다.

  • 로그인할 때마다 registerPushToken(uid)를 부르지만, 권한이 이미 granted일 때만 토큰을 저장합니다. 권한 창을 자동으로 띄우지 않습니다.
  • 권한 요청은 사용자가 버튼을 눌렀을 때만 합니다(enablePushNotifications). 브라우저는 사용자 동작 없는 권한 요청을 막거나 사용자가 거부하기 쉬우므로, 거부되면 다시 물을 수 없기 때문입니다.

권한 UX ​

위치동작
홈 PushPromptCard권한이 default이고 FCM을 지원하는 브라우저에서만 표시. "알림 받기"를 누르면 권한 요청. 닫으면 localStorage의 push-prompt-dismissed에 기억
MyPage 알림 설정기기의 푸시 상태(지원 여부, 권한, 등록된 토큰 수)를 보여 주고 켜기 버튼 제공. 종류별 토글과 매일 알림 시각 선택

표시 ​

  • 백그라운드: 서비스 워커의 onBackgroundMessage가 data.title/data.body로 알림을 띄웁니다. 클릭하면 data.type에 맞는 경로(위 표의 "클릭 시")로, 열린 창이 있으면 그 창을 이동·포커스하고, 없으면 새 창을 엽니다.
  • 포그라운드: App.jsx가 onMessage로 받아 브라우저 Notification을 띄우고, 클릭 시 같은 경로로 이동하며 notification_clicked 이벤트를 남깁니다.

질문 선정 알림 (question_selected) ​

제안한 질문을 운영자가 처음 선정하면 제안자에게 한 번 보냅니다. → 질문 제안과 선정

항목값
보내는 곳reviewQuestion callable — 선정이 커밋된 뒤 (실패해도 선정은 취소되지 않음)
대상사용자가 제안한 질문(source: "user")의 제안자. 기본 질문은 보내지 않음
조건선정 전에 approvedAt이 없던 질문(처음 선정)만. 숨겼다가 다시 선정해도 다시 보내지 않음
중복 방지notificationLogs/question_selected_{questionId}
끄는 설정없음 (자기 제안에 대한 결과 안내)
메시지제목 "제안한 질문이 선정됐어요 🎉", 본문 질문 문구, data: { type: "question_selected", questionId }
클릭 시/mypage#questions
  • 백그라운드: 서비스 워커가 /mypage#questions로 이동합니다.
  • 포그라운드: App.jsx가 이미 MyPage에 있으면 "내가 제안한 질문" 카드로 스크롤만 하고, 아니면 /mypage#questions로 이동합니다.
  • MyPage의 MyQuestionsSection은 목록을 그린 뒤 주소의 해시가 #questions이면 그 카드로 스크롤합니다.
  • 반려는 알림을 보내지 않습니다. 제안자는 MyPage에서 상태와 사유를 봅니다.

매일 알림 (sendDailyReminder) ​

웹(과 앱이 로컬 알림을 맡지 않은 사용자)의 서버 발송입니다. 앱의 휴대폰 자체 알림은 아래에 있습니다.

항목값
스케줄15분마다 */15 * * * *, 시간대 Asia/Seoul (예전 every 1 hours는 작업 생성 시각 기준이라 매시 40분에 돌았음)
대상 조회dailyReminder == true, dailyReminderHour == 현재 KST 시, 그리고 정각이 아니면 dailyReminderMinute == 현재 15분 구간 (복합 인덱스). 정각 실행은 분 필드가 없는 예전 설정도 함께 처리
건너뛰기userStats로 확인해 오늘(KST) 이미 쓴 사용자. 그리고 앱이 로컬 알림을 맡은 사용자(dailyReminderChannel == 'local', dailyReminderLocalAt이 14일 안, LOCAL_REMINDER_TTL_MS) — 조회 뒤 메모리에서 거름(reminderRecipients), 로그에 app-local 수
처리 단위100명씩 userStats를 한 번에 읽고 병렬 발송
중복 방지daily_reminder_{uid}_{YYYYMMDD}_{HHMM}
제한타임아웃 300초, 최대 인스턴스 3

조회 조건에 시각을 넣어, 읽는 문서 수가 전체 사용자 수가 아니라 그 시각의 대상자 수에 비례합니다.

앱 (iOS·Android) ​

앱은 웹과 같은 알림 종류·설정·클릭 경로를 쓰고, 받는 방법만 네이티브입니다. 설정 절차(APNs 키, 채널)는 iOS·Android 앱에 있습니다.

푸시 ​

항목앱에서
플러그인@capacitor-firebase/messaging (src/lib/native/push.js, 앱에서만 불러옴)
토큰pushTokens/{uid}/tokens/{token} = {token, platform: 'ios' | 'android', createdAt}. 권한이 이미 있을 때만 로그인 뒤 저장하고, 같은 토큰은 하루에 한 번까지 다시 씀. 토큰이 바뀌면(tokenReceived) 이 기기의 예전 문서를 지움
권한OS 권한 하나가 푸시와 매일 알림을 함께 덮음. 홈 PushPromptCard("매일 감사 알림과 Circle 소식을 알려드려요"), MyPage "알림 켜기", MyPage에서 매일 알림을 켤 때만 요청. 자동으로 묻지 않음
거부했을 때MyPage: "알림이 꺼져 있어요 / 휴대폰 설정 › Grato › 알림에서 허용해 주세요". 설정에서 허용하고 돌아오면 토큰을 저장
백그라운드OS가 notification 페이로드를 표시 → 메시지 모양
포그라운드iOS: OS가 배너·소리·배지로 표시. Android: 앱이 받아 같은 채널(grato_push)의 로컬 알림으로 표시
클릭웹 서비스 워커와 같은 경로(notifyHelpers.notificationPath). 이미 MyPage면 질문 카드로 스크롤만. notification_clicked 이벤트에 platform
로그아웃토큰 문서와 FCM 토큰을 지움(남은 문서가 있어도 아무에게도 가지 않음)

매일 알림: 휴대폰 자체 알림 ​

앱에서는 서버 푸시 대신 @capacitor/local-notifications로 휴대폰이 직접 띄웁니다(src/lib/native/localReminders.js). → 결정 기록 #16

  • 시각은 웹과 같은 설정(KST, 15분 단위). 앞으로 14일 치를 하루씩 예약하고, 오늘 이미 썼거나 시각이 지났으면 오늘은 뺍니다.
  • 앱 시작·복귀, 설정 변경, 글 저장, 권한 허용 때 다시 맞춥니다. MyPage 안내: "매일 이 시간에 이 휴대폰으로 알려드려요. 기록한 날은 쉬어요 (15분 단위)".
  • Android 채널 daily_reminder("매일 감사 알림"). 정확한 알람 권한은 쓰지 않아 절전 중에는 몇 분 늦을 수 있습니다.
  • 예약하는 동안 notificationSettings.dailyReminderChannel = 'local'과 dailyReminderLocalAt(서버 시각)을 한 번에 씁니다. 서버는 이 표시가 14일 안이면 그 사용자에게 매일 알림을 보내지 않습니다(웹 브라우저 포함, 하루 한 번만). 알림을 끄거나 권한이 없거나 로그아웃하면 null로 되돌려 서버 알림이 다시 갑니다. 앱을 지워 되돌리지 못해도 14일 뒤 만료됩니다.
