질문으로 쓰기 ​

"질문으로 쓰기"는 무엇을 써야 할지 모를 때 질문에 답하며 감사 글을 시작하는 작성 모드입니다. 쓰기 화면(직접 작성)의 저장 버튼 아래 카드에 질문이 보이고, [이 질문으로 감사 적기] 를 누르면 그 질문으로 시작합니다. 위젯의 질문을 눌러도 그 질문으로 바로 열립니다. 질문은 운영자가 선정한 질문(기본 질문 + 사용자가 제안해 선정된 질문)에서 고릅니다. 답변과 초안 만들기는 모두 기기 안에서 이루어지고, 작성 내용은 사용자가 저장할 때 일반 글 저장 경로로만 Firestore에 올라갑니다. → 결정 기록 #10, #11

흐름 ​

  1. 첫 번째 질문 — 쓰기 화면 카드에서 고른 질문입니다. 카드는 처음에 오늘의 질문(todayQuestion: 시즌 날에는 시즌 질문, 그 밖에는 요일별 결에서 하나 — 홈 화면 위젯과 같은 질문)을 보여 주고, "다른 질문"을 누르면 무작위로 바꿉니다. 답을 써야 다음으로 넘어갑니다.
  2. 두 번째 질문 — 이어지는 질문 풀에서 하나를 보여 줍니다. 답하거나 "이 질문은 건너뛸게요"로 바로 초안을 만들 수 있습니다.
  3. 초안 — 답변을 빈 줄로 이어 붙여 내용에 넣고, 제목은 비워 둡니다.
  4. 저장 — 첫 질문의 ID가 있으면 글에 questionId로 함께 남습니다(내용은 질문과 상관없이 내 글 그대로, → 내 질문으로 쓰인 감사). 제목과 내용이 모두 있어야 저장 버튼이 켜집니다. 공개 범위는 기본이 "나만 보기"이고(버튼 "저장하기"), "Circle에 공유"를 고르면 Circle을 골라야 저장할 수 있습니다(버튼 "Circle에 공유하기"). → 공개 범위

질문 카드의 "다른 질문"을 누르면 같은 풀에서 지금 질문과 다른 질문으로 바꿉니다. 사용자가 제안해 선정된 질문에는 "💡 홍길동 #1234님의 질문"처럼 제안자의 공개 이름이 함께 보입니다(기본 질문이나 이름이 없는 질문은 표시하지 않음). → 제안자 표시

첫 번째 질문 카드 아래에는 [이 질문 추천] 과 "추천 많은 질문"(추천받은 질문을 많은 순으로 모은 시트, 골라서 바로 쓰기)이 있습니다. → 질문 추천

질문 화면 아래의 "좋은 질문이 떠올랐나요? 질문 제안하기"로 질문을 제안할 수 있습니다. → 질문 제안과 선정

질문 풀 ​

질문은 운영자가 선정한 질문에서 고르고, 그것을 읽지 못하면 앱에 들어 있는 기본 질문 목록으로 대신합니다.

출처위치설명
선정된 질문questions (status == "approved")기본 질문(source: "system") + 사용자가 제안해 선정된 질문(source: "user")
앱 안의 기본 질문src/content/questions.json{ "opening": [{text, facet} 45개], "followup": [10개], "seasons": [...] }. seedQuestions 스크립트가 같은 파일을 Firestore의 system_* 문서로 넣음. seasons는 시즌 질문

src/lib/questionApi.js의 loadQuestionPools()가 풀을 만듭니다.

  • 선정된 질문을 세션에 한 번 읽습니다(where('status', '==', 'approved'), 최대 500개, 정렬 없음). 그래서 새로 선정된 질문은 다음에 앱을 열 때부터 나옵니다.
  • 읽기에 실패했거나 오프라인 캐시에서 온 결과는 저장하지 않아 다음에 다시 읽습니다. 4초 안에 오지 않으면 앱 안의 목록으로 먼저 시작합니다.
  • buildQuestionPools()가 종류(kind)별로 나눕니다. 어떤 종류에 선정된 기본 질문(시즌 질문 제외)이 하나도 없으면(시드 전, 읽기 실패) questions.json의 목록에 선정된 사용자 질문을 더해 씁니다. 사용자 질문 몇 개가 기본 질문 전체를 대신하지 않게 하기 위해서입니다.
  • 같은 문구(공백·구두점·보이지 않는 문자를 빼고 같은 것)는 한 번만 넣습니다.
  • 숨긴 질문(hidden)은 풀에 들어가지 않습니다.

src/content/questions.js는 JSON을 import할 뿐 React·Firebase를 import하지 않는 순수 모듈이라 node:test로 바로 테스트합니다(questions.test.js).

기본 질문을 추가·수정할 때는 questions.json을 고치고, 배포 때 seedQuestions를 실행합니다. 첫 질문은 맨 뒤에 더하고(문서 ID가 순서로 정해짐) facet을 붙입니다. 이어지는 질문은 첫 질문과 상관없이 고르므로 어떤 첫 질문 뒤에 와도 자연스러운 문장으로 씁니다. → 기본 질문

오늘의 질문: 요일별 결 ​

시즌 밖(시즌 질문이 없는 날)의 오늘의 질문은 요일마다 정한 결에서 고릅니다(GRATO-93). 모두의 감사방 오늘의 주제와 같은 요일 표라 하루의 결이 한 가지로 맞지만, 문장은 서로 다르게 씁니다. → ADR-43

요일결 (facet)묻는 것
월작은 것 small일상 속 작은 즐거움, 장소, 감각
화사람 people곁의 사람, 받은 친절, 대화
수없었다면 absence좋은 일·만남·장소가 없었다면 (사람을 잃는 장면은 묻지 않음)
목특정 순간 moment장면 하나
금고마움 잇기 forward고마움을 알려 주기, 건네기 ("갚기"가 아님)
토섞인 감정 mixed힘들었지만 고마운 것
일한 주 돌아보기 reflect한 주·하루 정리

고르는 규칙(questionForDay, KST 날짜):

  1. 그날이 시즌이면 그날의 시즌 질문. 끝.
  2. 요일 → 결.
  3. 그 결의 질문 목록(facet이 그 결이고 시즌 질문이 아닌 것, order 순)에서 주 번호(월요일 시작) % 목록 길이. 같은 결의 질문은 목록을 다 돌기 전에 다시 나오지 않습니다(결마다 6–9주에 한 번).
  4. 목록: 기본 질문은 questions.json 순서(order = 0부터의 위치), 결을 고른 사용자 질문은 그 뒤에 선정한 순서(order = 처음 결을 정해 선정한 시각, ms).
  5. 시드 전이라 문서에 facet이 없으면 앱 안 기본 질문의 결·순서를 문구로 찾아 씁니다. 그래서 읽기 실패·시드 전에도 같은 날 같은 질문입니다.
  6. 그 결의 질문이 하나도 없으면(운영자가 모두 숨김) 예전처럼 풀 전체를 하루 하나씩 돕니다.
  • 운영자가 사용자 질문을 선정할 때 결을 고르면 그 결의 순환에 들어갑니다. 고르지 않으면 순환에는 안 들어가고 "다른 질문"에만 나옵니다. 그래서 질문 하나가 선정돼도 다른 결의 날은 바뀌지 않습니다(같은 결의 날만 목록 길이가 바뀜). → 선정 화면
  • "다른 질문"은 지금처럼 풀 전체(결·시즌 상관없음)에서 무작위입니다. 한 줄만 써도 기록이 됩니다.
  • 위젯의 7일 치도 같은 함수라, 시즌 경계(11/14→11/15, 1/10→1/11)가 섞여도 쓰기 화면과 같습니다. Swift·Java 위젯은 받은 문장을 보여 주기만 해 바뀌지 않습니다.
  • 카드뉴스(월·수·금)는 이 결을 따르지 않고 지금처럼 주 단위로 돕니다. → 카드뉴스
  • 분석: 질문으로 쓰기의 gratitude_started·gratitude_created에 facet(결 이름만, 문구 없음)이 붙습니다.
  • 1.0.1 (6) 이하 앱은 예전처럼 문서 순서로 하루 하나씩 돕니다. 새 기본 질문 15개가 풀에 들어가 순서가 바뀔 뿐 깨지지 않습니다.

시즌 질문 ​

연말연초 시즌(GRATO-66)에는 그날의 질문(쓰기 화면 아래 카드, 홈 화면 위젯, 카드뉴스)이 날짜로 정해진 시즌 질문입니다. 서버가 날마다 바꾸지 않고, 앱이 KST 날짜로 계산합니다.

시즌 (seasonKey)날짜 (KST)그날의 질문
감사의 계절 (2026-thanks)11/15–11/22감사의 계절 질문 T1–T8
11/23–11/30T1–T8을 다시
한 해 돌아보기 (2026-winter)12/1–12/21연말 질문 1–21번을 날짜 순서로
12/22–12/271–6번을 다시
12/28–12/31마무리 질문 4개(M1–M4)
신년 감사 (2027-newyear)1/1–1/10신년 질문 1–10번
—1/11–11/14기본 순환
  • 데이터: questions.json의 seasons(seasonKey, name, start, 하루 하나씩의 days, opening·followup 문구, 다른 시즌의 이어지는 질문을 쓸 때 followupFrom). 계산은 순수 모듈 src/content/seasonQuestions.js. 문서 ID는 system_season_{seasonKey}_{키}(예: system_season_2026-winter_01, 감사의 계절 system_season_2026-thanks_t1, 마무리 _m1, 이어지는 질문 _f1).
  • 앱 안 사본: 시드 전이나 질문을 읽지 못해도 앱에 든 사본으로 나옵니다. 시드된 뒤에는 Firestore 문서(같은 ID)를 씁니다.
  • 운영자가 숨긴 질문: 그 시즌의 다른 질문은 풀에 있는데 그날 질문만 없으면 숨긴 것으로 보고, 그날은 기본 순환 질문을 보입니다(슬픈 일이 있는 날, reviewQuestion hide). 시즌 질문을 모두 숨기면 시드 전과 구별할 수 없어 앱 안 사본이 나옵니다(알려진 한계). → ADR-35
  • 다른 질문: 지금처럼 풀 전체입니다. 시드된 시즌 질문도 들어 있어 2/1에 숨길 때까지 나옵니다. 기본 순환(시즌 밖의 그날 질문)에는 시즌 질문을 넣지 않아, 시드해도 순서가 밀리지 않습니다.
  • 이어지는 질문: 감사의 계절·한 해 돌아보기 질문으로 시작하면 한 해 돌아보기의 이어지는 질문 3개 중 하나(감사의 계절은 followupFrom: "2026-winter")("그 순간을 떠올리면 지금 어떤 마음이 드나요?" 등). 신년 질문과 그 밖에는 기본 이어지는 질문. 두 번째 질문의 "다른 질문"은 풀 전체.
  • 나만 보기 그대로: 시즌 질문으로 써도 기본은 나만 보기, Circle은 미리 고르지 않습니다(ADR-12). 시즌 문구에 "나눠 보세요"를 넣지 않습니다.
  • 위젯: 앱이 7일 치 질문을 같은 함수로 계산해 요약본에 넣으므로, 앱을 며칠 열지 않아도 시즌 첫날부터 위젯에 시즌 질문이 나옵니다. Swift·Java 위젯은 날짜별 질문을 보여 주기만 해 바꾸지 않았습니다.
  • 예전 앱(1.0.1 (4) 이하): 시즌 계산이 없어 그날의 질문은 기본 순환입니다. 시드된 시즌 질문은 풀에 들어가 "다른 질문"과 날짜 순환에서 만납니다(순환 순서는 바뀜).
  • 미리 보기: 개발 빌드의 테스트 날짜로 11/15·12/1·12/28·1/1·2/1을 봅니다.

서버 시즌 (관리자에서 만들기·게시) ​

앱 업데이트 없이 시즌을 더하거나 고칩니다(앱 1.0.1 (7)부터). 운영자가 관리자 › 시즌에서 서버 시즌 문서를 만들고 게시하면, 앱이 다음에 열릴 때 그 시즌으로 그날의 질문·이어지는 질문·위젯·매일 알림 문구를 계산합니다. → ADR-41, 운영 절차

  • 읽기: src/lib/seasonApi.js의 loadSeasons()가 seasons를 status in ['published', 'ended']로 세션에 한 번 읽습니다(최대 50개). 질문 풀을 읽을 때(loadQuestionPools) 함께 기다리되 같은 4초 제한 안에서이고, 시작을 막지 않습니다(ADR-13). 실패·오프라인 캐시 결과는 기억하지 않아 다음에 다시 읽습니다.

  • 합치기: seasonQuestions.js의 applyServerSeasons(docs) → mergeSeasons(BUNDLED_SEASONS, docs). 게시된 문서는 같은 키의 앱 안 시즌을 대신하거나 새로 더하고, 끝난 문서는 그 키를 뺍니다. 날짜·키가 맞지 않는 문서(isRunnableSeason)와 초안은 무시합니다(앱 안 시즌 그대로). SEASONS·SEASON_QUESTIONS는 바뀌는 값(export let)이라 questionForDay 등 기존 함수가 그대로 씁니다.

  • 문구: 게시하면 서버가 시즌 질문 문서(system_season_*)도 씁니다. 그래서 그날 질문은 지금처럼 풀의 사본이 있으면 그것을, 없으면 시즌 문서의 문구를 보입니다. 질문 탭에서 그날 질문만 숨기면 그날은 기본 순환(지금과 같음).

  • 예전 앱: 1.0.1 (5)는 서버 시즌을 모릅니다. 새 키의 시즌 질문은 "다른 질문"에만, 앱 안 시즌을 서버에서 고친 경우는 문구(같은 문서 ID)만 반영되고 날짜·순서는 앱 안 그대로입니다.

  • 넣기·숨기기: 배포: 시즌 질문
