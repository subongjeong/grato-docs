신고·차단과 자동 숨김 ​

다른 사람에게 보이는 사용자 콘텐츠(UGC)를 안전하게 유지하는 기능입니다. 스토어 정책(Apple 1.2, Google Play UGC)은 부적절한 콘텐츠 신고, 사용자 차단, 필터, 운영자의 빠른 대응을 요구합니다. → 결정 기록 #14, 출시 준비 체크리스트

수단누가하는 일
신고로그인 사용자 (비로그인은 이메일)글·댓글·사용자·Circle을 운영자 대기열에 올림
차단로그인 사용자그 사람의 글·댓글과 그 사람 때문에 오는 알림을 내 화면에서 없앰
자동 숨김서버욕설·혐오 표현이 든 공유 글·댓글을 바로 숨기고 대기열에 올림
운영자 처리운영자 (users.isAdmin)숨기기·숨김 해제·삭제·이용 정지·문제 없음

신고 화면 (ReportSheet) ​

  • 사유(필수, 하나): 스팸·광고, 욕설·괴롭힘, 음란·성적인 내용, 혐오·차별 표현, 자해·자살 관련 내용, 개인정보 노출, 기타
  • 자세한 내용(선택, 500자까지)
  • 보낸 뒤 작성자를 차단할지 바로 묻습니다.
  • 신고는 reports에 addDoc(자동 ID)으로 만들고, 보낸 사람도 다시 읽을 수 없습니다. 신고한 사람이 누구인지는 상대에게 알리지 않습니다.

서버 처리 (onReportCreated) ​

  • 도배 방지: 규칙은 개수를 셀 수 없어, 한 사용자가 24시간에 보낸 21번째 신고부터 spam으로 표시합니다(차단으로 생긴 신고 포함). 스팸 신고도 운영자 화면의 "스팸 의심" 탭에서 볼 수 있습니다.
  • 대상 정보 복사: 작성자(targetOwnerId)와 내용 발췌(targetPreview, 200자)를 신고에 남겨, 작성자가 글을 지운 뒤에도 운영자가 판단하고 이용 정지할 수 있게 합니다. "나만 보기" 글은 발췌를 남기지 않습니다.
  • 푸시: 약관이 "24시간 안에 검토"를 약속하므로 운영자 기기로 바로 알립니다. 같은 대상에 이미 열린 신고가 있으면 다시 보내지 않고 같은 카드에 모입니다. 잠금 화면에 보이므로 내용과 이름은 넣지 않고 종류와 사유만 씁니다(예: "감사 글 · 욕설·괴롭힘. 24시간 안에 확인해주세요"). 클릭하면 /admin?tab=reports.

차단 ​

users/{uid}/blocks/{차단한 uid} = { createdAt }. 본인만 읽고 씁니다.

효과방식
그 사람의 글·댓글이 내 화면에서 빠짐클라이언트가 그릴 때 거름(canSeeItem). 다시 불러오지 않아도 차단·해제가 바로 반영됨
그 사람 때문에 오는 알림이 오지 않음Circle 새 글 알림은 작성자를 차단한 멤버를 빼고, 리액션 알림은 글 작성자가 차단한 사람의 리액션이면 보내지 않음
운영자가 알게 됨onBlockCreated가 낮은 우선순위 신고(source: "block", 푸시 없음)를 남김. 한 쌍에 한 번만
상대는 모름상대에게 알리지 않고, 상대 화면은 바뀌지 않음
  • 차단한 화면에서는 그 자리에 "차단한 사용자의 글이에요" 안내를 남겨, 열려 있던 메뉴나 신고 화면이 갑자기 사라지지 않게 합니다.
  • 차단 목록과 해제: MyPage › 설정 › 차단한 사용자 (/settings/blocked). Circle 설정의 멤버 목록에도 "차단됨"이 표시됩니다.
  • 차단은 내가 보는 것을 정리하는 기능입니다. Circle 멤버십은 바뀌지 않으므로, 같은 Circle에 있는 상대는 내가 공유한 글을 계속 볼 수 있습니다. 완전히 떨어지려면 Circle 관리자가 내보내기를 합니다.
  • 차단 목록은 첫 화면을 그린 뒤 필요한 컴포넌트가 처음 물을 때 한 번 구독합니다(시작을 막지 않음, ADR-13).

자동 숨김 ​

다른 사람이 볼 수 있는 글·댓글의 텍스트가 내용 필터의 욕설·혐오 표현에 걸리면 서버가 바로 숨기고 운영자 대기열에 올립니다.

언제트리거
Circle에 공유한 글을 만들 때onGratitudeCreated (통계·배지·알림보다 먼저)
글을 링크 공개로 바꿀 때onReactionUpdated (isPublic false → true)
Circle 글에 댓글을 달 때onCommentCreated
  • 연락처와 링크는 숨기지 않습니다. 친구에게 쓰는 글에 링크가 들어가는 것은 자연스럽기 때문입니다(질문 제안 필터와 다른 점). 그런 경우는 신고로 다룹니다.
  • 숨기면 글·댓글에 moderation = { status: "hidden", source: "auto", reason: "profanity" }를 쓰고, 같은 트랜잭션에서 시스템 신고(reporterId: "system")를 만듭니다. 같은 대상에는 한 번만 만듭니다.
  • 숨긴 Circle 글은 Circle에서 빠집니다. groupId를 비우고 원래 Circle은 moderation.groupId에 둬서 Circle 피드 쿼리에 나오지 않게 하고, 숨김을 해제하면 되돌립니다. 작성자의 "내 기록"에는 그대로 있습니다.
  • 숨긴 글은 Circle 새 글 알림을 보내지 않고, 공유 페이지는 "비공개"로 보여 줍니다(검토 중이라는 사실도 드러내지 않음). 숨긴 글은 다시 링크 공개로 바꿀 수 없습니다.
  • 운영자가 이미 결정한 콘텐츠(moderation 기록이 있음)는 필터가 다시 건드리지 않습니다. 운영자가 되살린 글이 다시 숨겨지지 않습니다.

이름 ​

공개 이름과 Circle 이름·설명은 클라이언트가 쓰므로 필터를 쓴 뒤에 검사합니다(onPublicNameWritten, onCircleNameWritten). 이름은 바꾸지 않고 시스템 신고만 남깁니다. 같은 이름에는 한 번, 다시 바꾼 이름에는 다시 남깁니다. 운영자는 "문제 없음"으로 닫거나 계정을 이용 정지합니다. Circle을 만들 때는 createCircle이 이런 이름을 처음부터 거절합니다("Circle 이름이나 설명에 쓸 수 없는 표현이 있어요").

운영자 처리 ​

관리자 페이지의 첫 탭이 신고입니다(/admin?tab=reports, ReportManager). 이 화면 코드는 관리자 페이지에서만 받습니다.

  • "처리 대기"와 "스팸 의심" 탭, 탭마다 개수. 최신순 100개.
  • 카드마다 신고 종류·사유·자세한 내용·시각, 그리고 대상 미리보기(지금 내용). 대상이 지워졌으면 신고 당시 발췌를 보여 줍니다. "나만 보기" 글은 운영자도 읽을 수 없어 "볼 수 없음"으로 표시됩니다.
  • 처리는 moderate callable 하나로 합니다. → Cloud Functions
작업화면 이름가능한 대상결과
hide숨기기글, 댓글, 질문글·댓글: moderation.status = "hidden"(source: "admin"). 질문: 선정됨 → 숨김
unhide숨김 해제글, 댓글moderation.status = "visible", 글은 Circle로 돌아감
delete삭제글, 댓글, 질문, Circle문서 삭제. 글은 삭제 트리거가 댓글·통계를 정리. Circle은 deleteCircle과 같은 정리(글은 보존)
disableUser이용 정지모든 대상의 작성자 (Circle은 관리자)로그인 차단·세션 철회·남은 토큰 잠금. 운영자 계정과 자기 자신은 불가
dismiss문제 없음모두대상은 그대로
  • 처리하면 같은 대상의 열린 신고가 모두 닫힙니다(resolved, "문제 없음"은 dismissed). 닫힌 신고는 1년 뒤 TTL로 지워집니다(처리방침의 보관 기간).
  • 작업마다 adminAuditLogs에 moderate_<작업>을 같은 커밋으로 남깁니다. 처리한 운영자는 신고 문서가 아니라 여기에만 남습니다.
  • 질문을 다시 보이게 하려면 관리자 페이지 "질문" 탭에서 다시 선정합니다.
  • 이용 정지를 푸는 기능은 앱에 없습니다. 이의 신청이 받아들여지면 콘솔에서 사용자를 다시 사용 설정합니다(약관 제12조의 이의 신청 절차).
