감사 글과 공유 ​

작성 ​

/write에서 두 가지 모드 중 하나를 고릅니다. 어느 모드든 마지막에 공개 범위를 고르고 저장합니다. 모드 선택 화면에는 "기본으로 나만 보기로 저장돼요. 저장할 때 Circle에 공유할 수도 있어요"가 함께 보입니다.

모드흐름
질문으로 쓰기첫 질문 → 답변 → 이어지는 질문 → 답변(건너뛰기 가능) → 답변으로 만든 초안 → 제목 입력·수정 → 공개 범위 → 저장
직접 작성제목과 내용을 직접 입력 → 공개 범위 → 저장

두 모드 모두 화면에서 제목과 내용을 요구합니다. 질문으로 쓰기는 운영자가 선정한 질문으로 동작하고, 답변과 초안은 기기 안에서 만듭니다. → 질문으로 쓰기

공개 범위: 기본은 나만 보기 ​

감사 글은 기본이 개인 기록입니다. Circle에 나누는 것은 글을 쓸 때마다 직접 고르는 선택입니다. → 결정 기록 #12

선택 ("누가 볼 수 있나요?")저장볼 수 있는 사람안내 문구저장 버튼
나만 보기 (기본, 항상 처음 선택됨)groupId: null작성자나만 볼 수 있어요저장하기
Circle에 공유 + Circle 선택groupId: <Circle ID>작성자, 그 Circle의 현재 멤버선택한 Circle 멤버만 볼 수 있어요Circle에 공유하기
  • 두 모드가 같은 컴포넌트 src/components/write/VisibilityPicker.jsx를 씁니다.
  • Circle은 미리 선택되지 않습니다. "Circle에 공유"를 고르면 내 Circle 목록이 칩으로 나오고, Circle을 고르기 전까지는 "공유할 Circle을 선택해주세요"가 보이며 저장할 수 없습니다.
  • Circle이 없으면 "Circle에 공유"는 꺼져 있고, 안내는 "나만 볼 수 있어요. Circle에 참여하면 함께 나눌 수도 있어요"입니다.
  • /write로 바로 들어와도 Circle 목록을 읽어 옵니다(useGroups({ skipIfLoaded: true })). 목록에 없는 Circle(탈퇴·삭제)로는 저장하지 않습니다.
  • 저장 후 홈은 글이 간 곳(내 기록 또는 그 Circle 탭)을 엽니다.
  • "Circle에 공유"를 고르면 "건강·종교 같은 민감한 내용이 있다면 공유 전에 한 번 더 확인해 주세요. 공유한 글은 언제든 삭제할 수 있어요."를 함께 보여 줍니다(개인정보 보호법 제23조제3항의 사전 안내).
  • "나만 보기"는 Circle 공유에 관한 선택입니다. 외부 공유 링크는 이와 별개로 작성자가 따로 공개를 골라야 열립니다. → 외부 공유
  • Circle은 공개 목록이나 검색이 없고 초대 코드로만 참여합니다. → Circle

홈: 내 기록 ​

홈 피드의 첫 탭은 항상 "내 기록"(자물쇠 아이콘)이고 기본으로 선택됩니다. Circle이 없어도 있습니다. 본인 글(개인 글과 Circle에 공유한 글)을 최신순으로 보여 주고, Circle 탭이 그 뒤에 이어집니다.

  • 첫 20개는 실시간(userId == 나, createdAt 내림차순, limit(20)), 그 뒤는 "더 보기"로 20개씩 읽습니다. Circle 탭도 같은 방식입니다(src/lib/feed.js). → 클라이언트 상태
  • 카드에는 작성자 대신 시간과 공개 범위가 작게 표시됩니다: "나만 보기"(자물쇠), 링크로 공개한 개인 글이면 "링크 공개", Circle에 공유한 글이면 Circle 이름(떠났거나 삭제된 Circle이면 "Circle"). MyPage 글 목록도 같은 표시를 씁니다.
  • 글이 없으면 "아직 남긴 기록이 없어요"와 "Grato 쓰기" 버튼을 보여 줍니다.
  • 실시간 구독이 실패하면(네트워크, 권한, 준비 중인 인덱스) "기록이 없어요"가 아니라 "기록을 불러오지 못했어요"와 "다시 시도"를 보여 줍니다.
  • Circle이 없으면 탭 아래에 Circle 만들기·참여를 권하는 카드("함께 나누고 싶은 사람이 있나요?")를 내 기록과 함께 보여 줍니다.

저장 ​

createGratitude(userId, groupId, {title, content})가 한 번의 setDoc으로 글을 만듭니다.

js
{
  userId, groupId,            // groupId는 Circle ID 또는 null
  title, content,             // 제목 0~100자, 내용 1~3000자
  authorName, authorTag, authorPublicName, authorPhotoURL, // 공개 프로필 사본
  reactions: { '❤️': [], '🙏': [], '✨': [], '🔥': [] },
  isPublic: false,
  createdAt: serverTimestamp(),
}
  • 작성자 필드는 저장 직전에 publicProfiles/{uid}를 읽어 채웁니다. 규칙이 원본과 같은지 확인합니다.
  • 문서 ID는 클라이언트 자동 ID입니다(doc(collection(...))).
  • 더 이상 멤버가 아닌 Circle에 저장하려 하면 규칙이 거부하고, 화면은 "이 Circle에는 더 이상 글을 남길 수 없어요"를 보여 줍니다.
  • 저장 후 통계·배지·알림은 onGratitudeCreated 트리거가 처리합니다. 트리거가 반영되기 전 잠깐 동안은 authStore.lastPostDateKey로 "오늘 기록함"을 미리 표시합니다.

수정과 삭제 ​

글 내용은 저장 후 고칠 수 없습니다. 작성자는 글을 지울 수 있습니다.

  • 글 카드와 글 상세의 "⋯" 메뉴 → "이 Grato 삭제하기" → 확인 창("삭제하면 되돌릴 수 없어요. 달린 댓글과 리액션도 함께 사라지고, 공유 링크로도 더 이상 볼 수 없어요.")
  • 클라이언트는 문서 하나만 지우고(deleteGratitude), 불러온 피드에서 바로 뺍니다(removeFromFeeds). 오늘 쓴 글이면 "오늘 기록함" 미리 표시도 지웁니다.
  • 나머지는 서버 트리거 onGratitudeDeleted가 합니다: 댓글 삭제, 통계(연속일·이번 달 수) 재계산, 그 달에 글이 남지 않으면 공유한 캘린더 월 비공개. 받은 배지는 유지합니다. → Cloud Functions, 글을 지웠을 때
  • 공유 링크는 바로 "비공개"가 됩니다(문서가 없음).
  • 운영자도 신고된 글을 지울 수 있고, 계정을 삭제하면 그 사람의 글이 모두 지워집니다. 같은 트리거가 정리합니다.

다른 사람에게 보이지 않는 글 ​

  • 차단: 내가 차단한 사람의 글·댓글은 내 화면에서 빠집니다.
  • 숨김: 신고나 자동 검사로 숨긴 글·댓글은 작성자에게만 "검토 중이에요"로 보입니다. 숨긴 Circle 글은 Circle 피드에서 빠지고 작성자의 내 기록에만 남습니다.

리액션 ​

이모지 4종(❤️ 🙏 ✨ 🔥)을 Slack처럼 칩으로 보여 줍니다. 각 이모지는 누른 사람의 uid 배열입니다.

js
updateDoc(ref, { [`reactions.${emoji}`]: hasReacted ? arrayRemove(uid) : arrayUnion(uid) })
  • 글을 읽을 수 있는 사람(작성자, 현재 Circle 멤버)만 누를 수 있습니다.
  • 규칙은 자기 uid의 추가·제거만 허용하고, 리액션과 다른 필드를 함께 바꾸는 것을 막습니다.
  • 다른 사람이 새로 누르면 작성자에게 알림이 갑니다(본인 리액션 제외). → 알림

외부 공유 (opt-in) ​

공유 링크는 작성자가 공개하기로 한 것만 보여 줍니다. 링크를 아는 것만으로는 내용을 볼 수 없습니다. → 결정 기록 #6

대상공개 상태 저장 위치공개하는 곳공유 URL
감사 글gratitudes/{id}.isPublic, sharedAt글 카드·상세의 공유 버튼 (작성자)/share/gratitude/{id}
캘린더 월publicShares/{uid}.calendarMonthsMyPage 캘린더의 링크 공유/share/calendar/{uid}/{YYYY-MM}
배지publicShares/{uid}.badgeIds배지 상세 시트의 공유/share/badge/{badgeId}/{uid}

공개 흐름 ​

  1. 공개되지 않은 것을 공유하려 하면 확인 창이 뜹니다. 예: "이 감사를 링크가 있는 누구나 볼 수 있게 공개할까요?" 감사 글은 민감한 내용을 한 번 더 확인하라는 안내가 함께 나옵니다.
  2. 확인하면 공개 저장을 기다리지 않고 바로 공유 시트(Web Share API, 없으면 클립보드 복사)를 엽니다. Safari는 네트워크 왕복 뒤에는 사용자 동작으로 인정하지 않아 공유 시트가 막히기 때문입니다.
  3. 공개 저장이 실패하면 상태를 되돌리고 "공개 설정에 실패했어요"를 알립니다.
  4. 배지는 공유 시트를 닫으면(취소) 방금 한 공개를 되돌립니다.

공개는 언제든 취소할 수 있습니다(글 상세의 "공개 취소", 캘린더의 비공개 전환). 공유 페이지는 캐시하지 않아 바로 반영됩니다. 숨김 처리된 글은 공개로 바꿀 수 없고, 이미 공개된 글이 숨겨지면 공유 페이지가 "비공개"로 보입니다. 공유 페이지 아래에는 로그인 없이 쓸 수 있는 "신고하기"(고객지원 이메일)가 있습니다.

공유 페이지가 보여 주는 것 ​

공유 URL은 Hosting rewrite로 shareRenderer가 렌더링합니다(Admin SDK로 읽음). 로그인하지 않은 방문자도 볼 수 있습니다.

페이지공개된 경우공개되지 않은 경우
감사 글제목, 내용, 작성자 공개 이름, 날짜(KST), JSON-LD Article"비공개 감사" 안내만, noindex
캘린더 월표시 이름, 그 달(KST)에 기록한 날, 개수, 현재 연속일"비공개 캘린더" 안내만 (이름도 숨김), noindex
배지배지 정보 + 사용자 이름 + 획득/도전 중 여부배지 정의(이름·아이콘·설명)만, 사용자 정보 없음, noindex
초대 (/invite/{code})Circle 이름, 설명, 인원코드가 없으면 "유효하지 않은 초대", noindex
  • 페이지마다 <title>, description, Open Graph, Twitter 카드를 채워 메신저·SNS 미리보기가 나오게 합니다.
  • 서버는 데이터를 window.__SHARE_DATA__로 함께 내려 주고, React 페이지(ShareGratitudePage 등)가 이것으로 화면을 그립니다.
  • 본인이 자기 캘린더 공유 페이지를 열면, 아직 공개하지 않은 달도 Firestore에서 직접 읽어 미리보기로 보여 줍니다(규칙상 본인 글만 읽을 수 있음).

공유 문구 ​

src/lib/share.js가 공유용 텍스트를 만듭니다. 예: "🙏 오늘의 감사 … Grato에서 감사한 순간을 함께 나눠요. {URL}". navigator.share가 있으면 공유 시트, 없으면 클립보드에 복사합니다.

캘린더 PNG 내보내기 ​

MyPage의 캘린더 카드는 PNG 이미지로 저장·공유할 수 있습니다. 이미지는 src/lib/calendarImage.js가 카드와 같은 배치로 캔버스에 직접 그립니다(가로 1080px). 화면을 캡처하던 html2canvas는 날짜 숫자가 동그라미 아래로 쏠리고 이미지 크기가 화면 폭에 따라 달라져 2026-10에 바꿨습니다. 이미지는 기기에서 만들어지므로 공개 설정과 관계없습니다.
