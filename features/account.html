계정: 로그인, 동의, 삭제 ​

로그인 수단(Apple 포함), 가입할 때의 약관 동의와 만 14세 이상 확인, 앱 안의 계정 삭제를 다룹니다. 세 가지 모두 스토어 출시에 필요한 2단계 기능입니다. → 결정 기록 #15, 출시 준비 체크리스트

로그인 수단 ​

수단방식비고
이메일·비밀번호createUserWithEmailAndPassword / signInWithEmailAndPassword가입 폼에서 약관에 동의
GooglesignInWithPopup(googleProvider)로그인 도메인은 커스텀 도메인(VITE_FIREBASE_AUTH_DOMAIN)
ApplesignInWithPopup(appleProvider), OAuthProvider('apple.com')범위 email, name, 화면 언어 ko_KR
Google·Apple (iOS·Android 앱)네이티브 로그인 화면 → signInWithCredential웹과 같은 uid. 창을 닫으면 오류 없음 → 앱 로그인
  • 로그인 화면에서 "Google로 계속하기"와 "Apple로 계속하기"를 같은 크기로 나란히 보여 줍니다(Apple 4.8). 로그인 탭과 가입 탭 모두에 있습니다.
  • 카카오톡 같은 앱 내 브라우저에서는 두 버튼을 끄고 "앱 내 브라우저에서는 Google·Apple 로그인을 사용할 수 없어요"를 보여 줍니다(OAuth 팝업이 막힘). 이메일 로그인은 됩니다.
  • 휴대폰·Safari는 팝업 준비 파일을 미리 받아 둬야 버튼을 누른 즉시 팝업이 열립니다. 데스크톱은 버튼에 마우스를 올릴 때 받습니다. → 성능

Apple 로그인의 특징 ​

  • 이름: Apple은 처음 동의할 때만 이름을 주고, Firebase 웹 로그인은 이를 넘겨주지 않습니다. 그래서 Apple 사용자는 이름 "익명"으로 시작하고, 홈에 "이름을 알려주세요" 카드(ProfileNameCard, 닫을 수 있음)가 떠서 MyPage 이름 편집으로 안내합니다.
  • 이메일 가리기: 사용자가 "이메일 가리기"를 고르면 …@privaterelay.appleid.com 주소가 옵니다. 그대로 받아들이고, 이 주소로 메일을 보내지는 않습니다.
  • 같은 이메일, 다른 수단: Firebase의 "이메일당 계정 하나" 설정에서 이미 다른 수단으로 가입한 이메일이면 auth/account-exists-with-different-credential 오류가 나고, "처음 가입할 때 쓴 방법(Google, Apple 또는 이메일)으로 로그인해주세요"를 보여 줍니다. 계정 연결 기능은 없습니다.
  • 콘솔 설정(Apple Developer의 Services ID, 키)은 배포: Apple 로그인 설정에 있습니다.
  • iOS·Android 앱에서는 팝업 대신 휴대폰의 로그인 화면을 쓰고, 받은 토큰으로 웹과 같은 Firebase JS SDK에 로그인합니다. iPhone의 Apple 로그인은 처음 동의할 때 이름을 받아 바로 씁니다. 계정 삭제의 재인증과 Apple 연결 해제(iOS는 인증 코드)도 같은 방식입니다. → 앱 로그인, 결정 기록 #17

약관 동의와 연령 확인 ​

Grato는 만 14세 이상만 이용할 수 있습니다(법정대리인 동의 절차 없음). 로그인한 모든 사용자는 현재 약관 버전에 동의한 기록이 있어야 앱을 씁니다.

js
users/{uid}.consent = { termsVersion: '2026-10', ageConfirmed: true, at: serverTimestamp() }
  • 약관 버전은 src/content/legal.js의 TERMS_VERSION입니다. 다시 동의받아야 할 만큼 약관이 바뀌면 이 값을 올립니다. 그러면 모든 사용자가 다음에 열 때 "이용약관이 바뀌었어요" 화면을 봅니다. 처리방침 버전(PRIVACY_VERSION)은 다시 동의받지 않습니다.
  • 규칙은 정확히 이 형태만 받고(at은 서버 시간), 감사 글·댓글을 만들 때 이 기록이 있는지 확인합니다. 클라이언트 화면을 건너뛰어도 글을 쓸 수 없습니다. → 보안 규칙

어디서 동의하나요 ​

경로동의 시점
이메일 가입가입 폼의 체크리스트: [필수] 만 14세 이상이에요, [필수] 이용약관에 동의해요(바로 아래 "불쾌하거나 해로운 콘텐츠와 괴롭힘은 무관용 원칙으로 금지, 확인되면 삭제·이용 정지" 안내), 개인정보 처리방침 확인(링크), "모두 동의해요". 버튼은 "동의하고 가입하기". Google·Apple로 처음 시작한 사용자는 같은 체크리스트를 동의 화면에서 봅니다. 로그인 화면 아래에도 같은 원칙을 한 줄로 보여 줍니다(App Store 1.2: 가입·로그인 전에 무관용 원칙이 보여야 함)
Google·Apple, 가입 탭에서 미리 체크로그인 직후 바로 기록 (동의 화면 없음)
Google·Apple, 그 밖의 경우로그인 직후 /consent 동의 화면
기존 사용자 (동의 기록 없음 또는 예전 버전)다음에 앱을 열 때 /consent

동의 화면 (/consent) ​

App.jsx의 ConsentGate가 로그인 페이지들을 감싸, 동의가 필요하면 /consent로 보내고 동의하면 원래 가려던 곳(초대 링크 포함)으로 돌려보냅니다.

  • 시작을 막지 않습니다(ADR-13). 프로필을 아직 모르면 페이지를 그대로 그리고, 프로필이 오면 판단합니다. 방금 가입한 로그인(첫 로그인, 생성 10분 이내, 이 화면에서 로그인함)은 프로필을 기다리지 않고 바로 묻습니다. 가입 직후 로그아웃했다가 다시 로그인하거나 앱을 다시 열면 방금 가입한 것으로 보지 않고 프로필로 판단합니다(동의한 사용자에게 동의 화면이 잠깐 보이지 않게). 판단은 src/lib/consent.js(단위 테스트)에 있습니다.
  • 문구는 세 가지입니다: 새 사용자 "Grato를 시작하기 전에", 동의 기록이 없는 기존 사용자 "새 이용약관을 확인해주세요", 버전이 바뀐 사용자 "이용약관이 바뀌었어요".
  • 고를 수 있는 것: 동의하고 시작하기, 만 14세 미만이에요, 동의하지 않고 로그아웃, (기존 사용자) 계정 삭제.
  • 동의 화면과 계정 삭제 화면은 동의 없이 들어갈 수 있습니다. 새 약관을 거부한 사람도 탈퇴할 수 있어야 하기 때문입니다.
  • 동의 화면에서는 아래 탭 막대를 숨깁니다.
  • 새 계정은 동의한 뒤 언제 감사를 떠올릴까요? 한 화면을 거쳐 원래 가려던 곳으로 갑니다.

만 14세 미만이라고 답하면 ​

만 14세 미만의 정보는 보관하지 않으므로(처리방침 "11. 만 14세 미만 아동") 계정을 바로 지웁니다.

  • 방금 만든 계정: "방금 만든 계정은 남기지 않고 로그아웃할게요" → 계정 삭제 후 로그아웃.
  • 기록이 있는 기존 계정: "계정과 기록을 모두 삭제하고 로그아웃할게요" → 계정 삭제와 같은 서버 처리. 다시 로그인이 필요하면 계정 삭제 화면으로 넘어갑니다.
  • 로그인 화면에 "만 14세 이상부터 이용할 수 있어요"를 한 번 보여 줍니다.

가입 직후: 언제 감사를 떠올릴까요? ​

새 계정이 동의를 마치면(이메일 가입은 가입 폼에서 동의한 뒤) 한 화면에서 매일 감사를 떠올릴 때를 고릅니다. "언제·어디서 할지"를 미리 정해 두는 실행 의도(if–then 계획)는 습관을 시작하는 데 근거가 단단한 기법입니다. → ADR-34

상황동작
새 계정, 동의를 마침/consent → /welcome/plan → 원래 가려던 곳(보통 홈)
새 계정, 초대 링크로 옴화면을 건너뛰고 초대(/invite/…)로 바로. 홈에 같은 내용의 카드를 한 번
약관 재동의, 기존 계정의 새 기기 로그인띄우지 않음
계획이 없는 기존 사용자홈에 카드를 한 번(닫거나 고르면 이 기기에서 다시 안 보임)
만 14세 미만지금처럼 계정 삭제. 이 화면은 나오지 않음
  • 선택지 6개(하나만, 미리 고르지 않음): ☕ 아침 차 한 잔 할 때 08:00 · 🚌 출근·등교길에 08:30 · 🍚 점심 먹고 나서 12:30 · 🌆 퇴근·하교길에 18:30 · 🌙 잠들기 전에 22:00 · 🕰️ 내가 정한 때 21:00. 시각은 "바꾸기"로 15분 단위로 고칩니다(설정의 감사 알림 시간과 같은 부품). 자유 글은 받지 않습니다.
  • 고르면 계획 문장이 보입니다: "잠들기 전이 되면, 고마웠던 일을 한 줄 적어요."
  • 버튼: 이 시간에 알려 주세요(누를 때만 알림 권한을 물음), 알림 없이 정해 둘게요(계획과 시각만), 오른쪽 위 건너뛰기(아무것도 저장하지 않음). 권한 창을 스스로 띄우지 않습니다.
  • 권한을 거부하면 "알림은 꺼져 있어요. 정한 때는 저장했어요. 설정에서 언제든 켤 수 있어요." 알림을 받을 수 없는 브라우저(iPhone 웹 등)에서는 주 버튼이 정해 둘게요가 되고 "이 브라우저에서는 알림이 오지 않아요. 알림은 Grato 앱에서 받을 수 있어요."(Android·PC는 "다른 브라우저에서는 받을 수 있어요.") → iPhone·iPad 웹
  • 시작을 막지 않습니다(ADR-13). 화면은 지연 로딩하는 작은 페이지이고(동의 화면·로그인 화면이 미리 받아 둠) Firestore를 기다리지 않습니다. 저장은 뒤에서 하고, 실패해도 다음 화면으로 갑니다.
  • 저장: users/{uid}.writingPlan과 매일 알림 시각(notificationSettings.dailyReminderHour/Minute)을 한 번에. 알림을 고르면 dailyReminder: true. 앱은 저장 뒤 휴대폰 알림을 바로 다시 예약합니다(ADR-16). → 데이터 모델
  • 언제든 마이페이지 > 설정의 쓰기로 한 때("잠들기 전 · 22:00 [바꾸기]")에서 바꿉니다. 바꿀 때는 지금 계획이 골라진 채로 열립니다.
  • 판단은 src/lib/writingPlan.js(순수, 단위 테스트). 홈 카드를 닫은 기록은 기기별(localStorage grato:writingPlanCard:{uid})이라 다른 기기에서는 한 번 더 보일 수 있습니다.
  • 이용 기록: writing_plan_shown {source: onboarding|home_card}, writing_plan_set {cue, hour, minute, notify, permission, source}, writing_plan_skipped {source}, writing_plan_changed(설정에서). 고른 때와 시각 말고 개인 내용은 없습니다.

마이페이지 구성 ​

한 화면으로 이어집니다(탭 없음): 프로필 → 숫자 칸(기록한 날·전체 Grato·최대 연속일·Circle, 연속일 숨기기를 켜면 최대 연속일 없이 3칸) → 저장한 감사 N개 ›(/saved, 저장) → 나의 감사 기록(그 달 캘린더, 링크 공유·이미지 저장) → 배지 → 내가 제안한 질문(#questions). 설정은 오른쪽 위 톱니 버튼으로 여는 별도 페이지(/settings)입니다: 알림, 연속일 숨기기, 의견 보내기, 고객 지원, 차단한 사용자, 로그아웃, 계정 삭제, 약관 링크. 설정 페이지에 있는 동안 아래 탭은 "마이"가 켜져 있습니다. 내 글 목록은 홈의 "내 기록"과 같아서, 이번 달 수·지금 연속일은 캘린더 카드에 있어서 위 칸에는 전체 기간 값(기록한 날·최대 연속일)을 둡니다(2026-10, 기록한 날은 GRATO-21).

이름·사진을 바꾸면 ​

프로필의 이름이나 사진을 바꾸면(사진 삭제 포함) 지금까지 쓴 글과 댓글에도 새 이름·사진이 보입니다. 서버가 그 사람의 글·댓글에 복사된 작성자 표시를 바꿉니다(몇 초 걸림). 모두의 감사방에 쓴 글은 그대로 별명입니다. 이미 받은 알림과 선정된 질문의 제안자 이름은 바뀌지 않습니다. → 작성자 표시 맞추기

프로필 사진 ​

MyPage › 프로필 수정에서 사진을 바꾸거나, 사진 왼쪽 위의 X 버튼(프로필 사진 삭제)으로 지울 수 있습니다. 지우면 이름 첫 글자가 대신 보입니다.

  • 올린 사진은 512px JPEG로 줄여 profilePhotos/{uid}/{시각}.jpg에 올립니다(5MB 미만, 본인만).
  • 삭제하면 users·publicProfiles의 photoURL을 비웁니다. 저장이 확인되면 Storage의 그 파일도 지웁니다(본인이 올린 사진일 때만, 실패해도 계정 삭제 때 함께 지워짐). 이미 쓴 글·댓글의 사진도 서버가 함께 비웁니다(이름·사진을 바꾸면).
  • Google 계정 사진은 Storage 파일이 아니라 지울 파일이 없습니다. 프로필에서만 빠집니다.
  • 로그인 계정(Auth)의 사진은 SDK로 비울 수 없습니다(updateProfile은 photoUrl: null을 보낼 뿐 deleteAttribute를 쓰지 않아 비워지지 않음. 에뮬레이터는 400으로 거부). 그래서 로그인 동기화는 프로필(users.photoURL)에 값이 있으면(지운 null 포함) 그것을 따르고, Auth 사진은 프로필 문서에 사진 필드가 없을 때만 씁니다. 다른 기기에서 로그인해도 지운 사진이 돌아오지 않습니다.

동의 화면의 "계정 삭제"새 약관에 동의하지 않는 기존 사용자
/account-deletion (공개)로그인 없이 볼 수 있는 삭제 안내. Google Play에 등록하는 "계정 삭제 URL"이며, 앱을 지운 사람을 위한 이메일 요청 방법도 있음

삭제 화면 ​

  • "삭제하면 되돌릴 수 없어요" 경고, 바로 삭제되는 정보, Circle은 이렇게 정리돼요, 누구인지 알 수 없게 남는 정보를 먼저 보여 줍니다.
  • 확인 문구 "계정 삭제"를 직접 입력해야 버튼이 켜집니다. 비밀번호 사용자는 비밀번호도 입력합니다.
  • Google·Apple 사용자는 본인 확인 팝업이 한 번 더 열립니다. 앱 내 브라우저에서는 팝업이 막히므로 Chrome·Safari에서 열라고 안내합니다.
  • 앱에서 확인할 수 없는 계정은 고객지원 이메일로 요청하도록 안내합니다.

흐름 ​

  • 최근 로그인 필요: 서버는 ID 토큰의 로그인 시각(auth_time)이 10분 이내가 아니면 "보안을 위해 다시 로그인한 뒤 삭제해주세요"로 거절합니다. 클라이언트는 그래서 항상 재인증부터 합니다.
  • Apple 연결 해제: Apple 사용자는 재인증에서 받은 토큰으로 Apple 쪽 연결을 끊습니다(5.1.1(v)). 오프라인이면 멈추고 다시 시도하게 하고, 그 밖의 이유로 실패하면 삭제는 그대로 진행한 뒤 로그인 화면에서 iPhone 설정에서 직접 지우는 방법을 안내합니다. 성공 여부는 삭제 기록(appleRevoked)에 남습니다.
  • 오래 걸려도 끝까지: 큰 계정은 오래 걸릴 수 있어 클라이언트는 540초까지 기다립니다. 호출이 실패하거나 시간이 지나도 Auth 사용자가 이미 지워졌다면 성공으로 처리합니다.
  • 다시 시도 가능: 모든 단계가 멱등적이고 Auth 사용자를 마지막에 지우므로, 중간에 실패하면 아직 로그인된 사용자가 그대로 다시 시도하면 됩니다.

무엇을 지우고 무엇을 남기나요 ​

원칙은 "내 것은 지우고, 다른 사람에게 이미 의미가 생긴 것은 나와의 연결만 끊는다" 입니다. → 결정 기록 #15

처리대상
삭제계정(Auth), users(차단 목록 포함), 공개 프로필, 이름 선점, 내 감사 글과 거기 달린 댓글(누가 썼든), 다른 글에 남긴 내 댓글, 리액션 속 내 uid(다른 사람 글의 공감과 보상 공감, 댓글의 공감), 통계·배지, 공유 opt-in(publicShares), 푸시 토큰, 보낸 의견, 검토 중·반려된 질문 제안, 모든 제안의 원문(questionOriginals), 내 질문으로 쓰인 감사 숫자(questionStats), 내가 한 질문 추천, 질문 하루 한도, 통계 마커, 프로필 사진(Storage)
Circle참여한 Circle에서 모두 나감. 내가 관리자이고 다른 멤버가 있으면 가장 오래 함께한 멤버가 관리자가 됨. 혼자 있는 Circle은 삭제(초대 코드·사진 포함). 내보낸 멤버 목록과 초대 코드 발급자에서도 빠짐
익명화해서 남김선정된(또는 선정 후 숨긴) 제안 질문: 작성자 정보만 지움. 이용 통계 이벤트: uid만 지움. 내가 보낸 신고: 신고자만 지움. 나에 대한 신고: 대상 계정·발췌를 지움(1년 뒤 TTL 삭제). 운영자 조치 기록: 대상 uid를 지움
기간이 지나면 지워짐알림 발송 기록(30일), 서버 로그(30일), 토큰 잠금 표시(약 2시간), 장애 복구용 백업
남는 것다른 사람의 차단 목록에 남은 uid (그 사람만 보고, 연결된 정보 없음)

삭제가 끝나면 adminAuditLogs에 account_deleted를 개수만 남깁니다(uid 없음).

늦게 도착한 작업이 데이터를 되살리지 않도록 ​

삭제 중이거나 직후에도 이미 발급된 ID 토큰은 최대 1시간 유효하고, 트리거는 늦게 실행될 수 있습니다.

  • 삭제를 시작하자마자 서버 전용 disabledUsers/{uid}(약 2시간, TTL)를 씁니다. 규칙과 callable은 이 기간 동안 그 계정의 새 쓰기를 거부합니다.
  • 통계·배지 트리거는 사용자 문서나 글이 없으면 아무것도 다시 만들지 않습니다. 차단·이름 신고 트리거도 삭제 중인 계정에는 신고를 만들지 않습니다.

이용 정지(moderate의 disableUser)도 같은 잠금을 씁니다. → 보안 규칙

경로내용

/account-deletion계정 삭제 안내 (위)
  • 본문은 src/content/legalPages.js, 공통 값(약관·처리방침 버전, 운영자 정보, 시행일, 고객지원 이메일)은 src/content/legal.js 한 곳에 있습니다. 네 페이지 모두 같은 LegalDocument 컴포넌트로 그리고, 빌드 때 정적 HTML로 미리 렌더링합니다.
  • 약관과 처리방침은 시행일이 따로입니다: TERMS_EFFECTIVE_DATE(약관 페이지·부칙), PRIVACY_EFFECTIVE_DATE와 PRIVACY_VERSION(처리방침 페이지·변경 이력). 처리방침만 바뀌면 약관 시행일과 TERMS_VERSION은 그대로라 다시 동의받지 않습니다.
  • 값(예: 처리방침 시행일 PRIVACY_EFFECTIVE_DATE)이 아직 중괄호 자리 표시로 남아 있으면 페이지에 강조되어 보이고, Hosting 배포가 거부됩니다(scripts/checkLegalPlaceholders.js). → 배포
  • 로그인·온보딩·소개 페이지 아래에 약관·처리방침·고객지원 링크(LegalLinks)가 있고, MyPage › 설정에 "고객 지원"이 있습니다.
  • src/content/legal.test.js가 처리방침의 법정 항목, 약관의 무관용·24시간·연령 조항, 삭제 안내의 두 경로와 보관 기간이 빠지지 않았는지 확인합니다.
